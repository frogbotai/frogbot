Pieces package related actions as FrogBot tools. Register each piece once in the root `pieces` array, then select its tools for individual agents.

For fetch-based search, see [Web search via pieces](/pieces/web-search).

## Install a piece

Install the package for the integration you need. Every shipped piece is native and includes its runtime dependencies.

```bash
pnpm add @frogbotai/piece-google-sheets
```

## Register and select tools

```ts
import { createGoogleSheets } from '@frogbotai/piece-google-sheets'
import type { FrogBotConfig } from 'frogbot'

export const googleSheets = createGoogleSheets({
  auth: { accessToken: process.env.GOOGLE_SHEETS_ACCESS_TOKEN! }
})

export const pieceConfig = {
  pieces: [googleSheets],
  agents: [
    {
      slug: 'assistant',
      model: 'openai/gpt-4o-mini',
      instructions: 'Read QA evidence from spreadsheets without changing it.',
      tools: [googleSheets.findRows, googleSheets.getRows]
    }
  ]
} satisfies Pick<FrogBotConfig, 'pieces' | 'agents'>
```

Merge `pieceConfig` into your root config alongside your database, collections, secret, and AI provider configuration. This example uses a developer access token. For user-owned credentials, reuse the factory instances from the [OAuth connection example](/connections/overview#configure-linking).

Pieces expose actions directly. Pass only the actions your agent needs in `tools`, or pass the piece to expose all of its actions. Each action can also be called on the server with `{ input, req }` to use the caller's credentials.

Tool slugs combine the instance slug and action name, such as `google-sheets_getRows`, so tools from different pieces do not collide. See [Google actions](/pieces/index#google-actions) for the action inventory and key input details.

## Keep tool sets focused

Configure only the tools an agent needs. About 20 to 40 tools per agent is a practical ceiling for reliable selection by the model. Prefer explicit action subsets when combining several pieces.

## Network access

The HTTP and GraphQL pieces can request arbitrary URLs without an allowlist. Only assign them to trusted agents and treat access to private network addresses and cloud metadata endpoints as an intentional SSRF risk.

## File output

Pieces that create files buffer the complete result in memory and write it to the default `files` collection. Set upload size limits appropriate for your deployment. See [Files](/upload/files) to adopt another collection.

## Credentials and linked accounts

Pass developer credentials as factory `auth`. To let users link accounts, configure root `connections` entries with `oauth: true`, `secret: true`, or both supported methods. Factory `oauth` holds your app credentials; it does not enable linking by itself. See [Connections](/connections/overview).

Use the identity-only `createGoogle` factory for [Google sign-in](/authentication/sign-in). Pass `google.oauth` to `createGoogleSheets`, `createGoogleDrive`, `createGoogleCalendar`, or `createGmail` to share the app credentials. Each product has its own scopes, connection entry, and callback. A Google login or identity connection does not authorize product actions.

## Gmail verification

Gmail uses restricted Google OAuth scopes. Production apps may require Google verification and a security assessment before users outside the test project can connect. Treat Gmail as an optional integration and complete Google's current approval requirements before enabling it.
