`@frogbotai/piece-openai` makes OpenAI a linked account. Each user pastes their OpenAI API key in **Settings → Linked accounts**, and their chats, agent runs and AI calls on OpenAI models run and bill on that key.

## Set up

```bash
pnpm add @frogbotai/piece-openai
```

```ts
import { createOpenAI } from '@frogbotai/piece-openai'
import { defineConfig } from 'frogbot'

export default defineConfig({
  connections: [{ piece: createOpenAI(), secret: true }],
})
```

That is the whole setup. Listing the piece in `connections` chooses OpenAI, so FrogBot adds the `openai` provider when [`ai.providers`](/ai/overview#configure-providers) has none. You don't need an `ai` block or an `OPENAI_API_KEY`, and the app boots without one.

`createOpenAI` takes only `slug` (default `'openai'`). It takes no `auth`: the app's own key goes in `ai.providers.openai.apiKey` or `OPENAI_API_KEY`. See [factory options](/pieces/overview#factory-options).

## Which key a call uses

For each call to an `openai/*` model:

1. The asking user's linked key.
2. Otherwise the app key: `ai.providers.openai.apiKey`, then `OPENAI_API_KEY`.
3. Otherwise the call fails before any request with "OpenAI isn't set up. Add your OpenAI key in Settings → Linked accounts."

Work without a user, such as jobs and schedules, has no linked key, so it uses the app key or fails the same way. A linked key that can't be used, because it was revoked or can't be read, fails with "Reconnect OpenAI in Settings → Linked accounts." and never falls back to the app key.

This holds for chat and agent turns on every step, for [AI operations](/ai/overview#call-operations) given `req`, and for the [HTTP gateway route](/ai/overview#call-over-http). One user's key is never sent on another user's call.

## Link a key

When a user saves a key, FrogBot checks it with one `GET https://api.openai.com/v1/models` call first:

| Result | What the user sees | Saved |
| --- | --- | --- |
| The key lists models | The linked account | Yes |
| OpenAI answers 401 or 403 | "OpenAI didn't accept this key." | No |
| The check fails or takes over 10 seconds | "Couldn't reach OpenAI to check this key. Try again." | No |
| The key doesn't start with `sk-` | "These credentials were not accepted." | No |

Each user has one linked OpenAI key. Disconnecting deletes the stored key. OpenAI has no API to revoke a pasted key, so tell users to revoke it at [platform.openai.com/api-keys](https://platform.openai.com/api-keys) when they stop using it.

## Model picker

For a user with a linked key, the chat model picker offers the agent's OpenAI models that the key can use: the models from `GET /v1/models` that are also in the agent's options and allowed by [`ai.access`](/ai/overview#control-access). Models from other providers are unchanged. FrogBot keeps the list for 15 minutes per linked key; linking a new key fetches it again. When the list can't be fetched, the picker shows the full list. If the agent's default model isn't in the list, the first listed model is the default.

## Errors on a user's key

| OpenAI answers | Message |
| --- | --- |
| 401 or 403 | "OpenAI rejected your API key. Update it in Settings → Linked accounts." |
| 429 `insufficient_quota` | "Your OpenAI account is out of credit. Check billing at platform.openai.com." |

FrogBot doesn't retry `insufficient_quota`; other 429s are retried. Errors on the app key keep their usual messages.
