Use the Brave Search or Exa piece with a developer-provided key when an agent needs current web results.

## Choose a provider

| Provider | Default action | Best fit |
| --- | --- | --- |
| Brave Search | `searchWeb` | General web search against an independent index |
| Exa | `search` | Semantic search, page content, similarity, and grounded answers |

Brave Search provides `searchWeb` and `customApiCall`. Exa provides `search`, `getContents`, `findSimilarPages`, and `generateAnswer`.

## Install the packages

Install the FrogBot piece you need. Each package includes its runtime dependencies.

```bash
pnpm add @frogbotai/piece-brave-search
```

```bash
pnpm add @frogbotai/piece-exa
```

## Use a developer key

Pass the provider key when creating the piece, register the piece, and assign its default tool to the agent.

```ts
import { createBraveSearch } from '@frogbotai/piece-brave-search'
import { buildConfig } from 'frogbot'

const braveSearch = createBraveSearch({
  auth: { apiKey: process.env.BRAVE_API_KEY! }
})

export default buildConfig({
  pieces: [braveSearch],
  agents: [
    {
      slug: 'researcher',
      model: 'fast',
      instructions: 'Search before answering questions about current events.',
      tools: [braveSearch.searchWeb]
    }
  ]
})
```

For Exa, replace the import and factory with `createExa`, and read `EXA_API_KEY`.

## Select opt-in Exa actions

Select only the Exa actions the agent needs.

```ts
tools: [exa.search, exa.getContents, exa.findSimilarPages]
```

Pass the whole piece, such as `tools: [exa]`, only when the agent should receive all four actions.
