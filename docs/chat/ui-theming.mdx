FrogBot UI uses the admin panel's color tokens, in the admin and on your own pages. Set them with CSS variables on `:root`. A page-level value reaches every FrogBot component on the page, including menus and dialogs, which render outside your layout.

```css
:root {
  --color-bg-brand: oklch(0.58 0.18 250);
  --color-bg-brand-hover: oklch(0.5 0.18 250);
}
```

With Tailwind CSS v4, set the same tokens in `@theme static`:

```css
@import "tailwindcss";

@theme static {
  --color-bg-brand: oklch(0.58 0.18 250);
}
```

Tailwind drops `@theme` values that no utility uses, so these tokens need `static`.

## Color tokens

The tokens come in two levels:

- **Ramps** are the raw palette, such as `--ramp-grey-100` to `--ramp-grey-900`, `--ramp-blue-500` or `--ramp-green-600`. Override a ramp to retint everything built on it.
- **Semantic tokens** say what a color is for. Components only read these:

| Token | Used for |
| --- | --- |
| `--color-bg` | Page, navigation, chat and dialog backgrounds |
| `--color-bg-secondary`, `--color-bg-tertiary` | Raised panels, secondary buttons, tracks |
| `--color-bg-hover`, `--color-bg-pressed`, `--color-bg-transparent-hover` | Hover and pressed states |
| `--color-bg-elevated` | Menus, dropdowns and popovers |
| `--color-bg-inverse`, `--color-text-oninverse` | Default buttons and other solid neutral fills, and their text |
| `--color-bg-brand`, `--color-text-onbrand`, `--color-text-brand` | Brand accents such as primary buttons, checked checkboxes and the chat's send button |
| `--color-text`, `--color-text-secondary`, `--color-text-tertiary` | Text, from strongest to faintest |
| `--color-border`, `--color-border-strong` | Borders and dividers |
| `--field-color-*` | Inputs, textareas and select triggers |
| `--color-*-danger`, `--color-*-success`, `--color-*-warning` | Status colors |

`@frogbotai/ui/styles.css` defines every token with the admin panel's default values, so pages outside the admin look like the admin. In the admin, the admin's own values apply.

The brand tokens default to FrogBot green, in the admin and on your own pages:

| Token | Light | Dark |
| --- | --- | --- |
| `--color-bg-brand` | `#2f964f` | `#2f964f` |
| `--color-bg-brand-hover` | `#166d30` | `#166d30` |
| `--color-bg-brand-pressed`, `--color-bg-brand-secondary` | `#0e5523` | `#0e5523` |
| `--color-bg-brand-tertiary` | `#d1f0db` | `#083d19` |
| `--color-bg-brand-tertiary-hover` | `#a0ddb4` | `#0e5523` |
| `--color-border-brand` | `#a0ddb4` | `#166d30` |
| `--color-border-brand-strong` | `#166d30` | `#67c285` |
| `--color-icon-brand`, `--color-text-brand`, `--color-text-brand-secondary` | `#166d30` | `#67c285` |

Text and icons on a brand fill (`--color-text-onbrand`, `--color-icon-onbrand`) stay white. Focus rings and selected rows use the separate `--color-*-selected` tokens, which stay blue.

For example, to give every grey surface a navy tint, and make brand accents blue:

```css
:root {
  --ramp-grey-900: #070b16;
  --ramp-grey-800: #0b1120;
  --ramp-grey-700: #171d2c;
  --ramp-grey-600: #232938;
  --color-bg-brand: #0d99ff;
  --color-bg-brand-hover: #007be5;
  --color-bg-brand-pressed: #0768cf;
}
```

Set the other brand tokens too, light on `:root` and dark on `[data-theme='dark']`, or they keep FrogBot's green.

### Token names your app may already use

The tokens use common names such as `--color-bg`, `--color-text` and `--color-border`. If your app defines a token with the same name for its own use, it restyles FrogBot too. Rename your token or scope it to your own elements. On admin pages, overriding one restyles the admin as well as FrogBot.

## Fonts

FrogBot's text uses one token, `--font-body`. Set it on `:root` to change the font of every FrogBot component, in the admin panel and on your own pages:

```css
@font-face {
  font-family: Satoshi;
  src: url('/fonts/Satoshi-Variable.woff2') format('woff2');
  font-weight: 300 900;
}

:root {
  --font-body: Satoshi, sans-serif;
}
```

Outside the admin it defaults to `Inter, sans-serif`. Inter only loads if you import `@frogbotai/ui/fonts.css`; without it, the browser's sans-serif font shows. In the admin panel, Inter is already loaded and `--font-body` already set.

FrogBot sets the regular text size to 14px, in the admin panel (where it raises the admin's 12px default) and on your own pages. To change it, set the text tokens on `:root`:

```css
:root {
  --text-body-medium-font-size: 0.8125rem;
  --text-body-medium-line-height: 1.125rem;
}
```

Code in tool results and code blocks uses Roboto Mono, also from `fonts.css`. On pages outside the admin, set `--font-family-mono` on `:root` to use another code font.

## Glow

The composer's animated rainbow ring is a reusable block. Put `fb-glow` on a wrapper and `fb-glow__ring` on the element inside it; the ring shows in a 5px band around that element's child, with 20px corners. Add `fb-glow--active` for the brighter glow the composer shows while you type.

```tsx
<div className="fb-glow">
  <div className="fb-glow__ring">
    <div className="my-panel">…</div>
  </div>
</div>
```

`@frogbotai/ui/styles.css` includes it. `@frogbotai/ui/glow.css` is the block on its own, with its colors set on `.fb-glow`, so it also works where FrogBot's tokens don't reach, such as a page's shadow root. With reduced motion the ring stops turning.

## Light and dark modes

Light values are set on `:root` and dark values on `[data-theme='dark']`. A value you set on `:root` applies in light mode, and in dark mode too unless dark mode sets that token. To set a dark value, set it on `[data-theme='dark']`:

```css
:root {
  --color-bg-brand: oklch(0.58 0.18 250);
}

[data-theme='dark'] {
  --color-bg-brand: oklch(0.82 0.12 250);
}
```

A ramp you override on `:root` applies in both modes, because the dark tokens read the same ramps.

On your own pages, `<html data-theme="dark">` turns on dark mode for the whole page. `ThemeProvider` sets it for you.

### ThemeProvider

`ThemeProvider` sets the light, dark, or system mode. Without `mode`, it themes the whole page by setting `data-theme` on `<html>`. With `mode`, it themes only its children and the menus and dialogs opened inside it. It doesn't set colors.

```tsx
import { ThemeProvider, ThemeScript } from '@frogbotai/ui/theme'

export function AppTheme({ children }: { children: React.ReactNode }) {
  return (
    <>
      <ThemeScript />
      <ThemeProvider>{children}</ThemeProvider>
    </>
  )
}
```

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `children` | `ReactNode` | Required | Content that uses the provider's mode. |
| `mode` | `'light' \| 'dark' \| 'system'` | — | Themes only the provider's children and their overlays. Without it, the provider themes the page, starting in `system` and using the stored preference. |
| `onModeChange` | `(mode: ThemeMode) => void` | — | Called when `setMode` from `useTheme()` changes the mode. |
| `storage` | `ThemeStorage` | `localStorage` | Reads and saves the preference with `get(key)` and `set(key, mode)`. |
| `storageKey` | `string` | `'fb-ui-theme'` | Key the preference is stored under. |

`useTheme()` returns `mode`, `resolvedMode` (`light` or `dark`), and `setMode`.

Place `ThemeScript` before themed content during server rendering. It reads the stored preference, or the operating system's mode for `system`, and sets `data-theme` on `<html>` before hydration to avoid a mode flash. Pass the same `storageKey` to `ThemeScript` and `ThemeProvider` when using a custom key.

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `nonce` | `string` | — | Content Security Policy nonce for the inline script. |
| `storageKey` | `string` | `'fb-ui-theme'` | Key the preference is read from. |

### Sections

A section of a page can use its own mode: wrap it in `ThemeProvider` with `mode`, and its menus and dialogs follow. Colors set on a section, such as `.billing { --color-bg-secondary: … }`, apply to the section's own content but not to its menus and dialogs, which render at the end of the page. Set colors page-wide instead. A section sets its mode's tokens again, so a semantic token you change on `:root` alone doesn't reach a light section; set it on `:root, [data-theme='light']` (and dark values on `[data-theme='dark']`). Ramps and the brand fills (`--color-bg-brand`, `-hover`, `-pressed`, `-secondary`) set on `:root` reach every section.

## Override FrogBot styles

All FrogBot styles are in a CSS cascade layer named `frogbot`. You can override them three ways:

- Write CSS that isn't in a layer. It beats FrogBot whatever its selector.
- Add a Tailwind CSS utility to the component, with one of the [Tailwind setups](/chat/ui-installation#use-with-tailwind-css).
- Put your rules in a layer declared after `frogbot`.

```tsx
<Button className="checkout-action">Pay</Button>
```

```css
.checkout-action {
  border-radius: 4px;
}
```

Global element rules apply to FrogBot components too. A CSS reset, normalize.css, Tailwind CSS v3 Preflight, or a rule such as `button { background: none }` removes FrogBot's button backgrounds, and `a { text-decoration: underline }` underlines link buttons. Scope these rules to your own content if you don't want that.

## Admin panel styles

In the FrogBot admin panel, FrogBot UI components and theme tokens work in every custom component, including views, fields, document controls, drawers, menus, and dialogs, with no wrapper. They follow the admin's light and dark setting and update as soon as a user switches theme.

Use `ThemeProvider` on your application's own pages outside the admin panel. Inside the admin, add one only when a section needs its own mode; it overrides the admin theme for its children.

The admin orders its styles like this, from weakest to strongest:

1. `payload-default`: the admin's base styles.
2. `frogbot`: FrogBot components and screens.
3. `payload`: an empty layer for your admin overrides.
4. Layers your CSS declares, such as Tailwind's.
5. CSS that isn't in a layer.

No layer of yours can go between `payload-default` and `frogbot`.

To use Tailwind CSS in the admin, import only its theme and utilities, after `@frogbotai/next/css`. Don't import Preflight (`@import "tailwindcss"` includes it): it resets the admin's own controls and FrogBot's.

```css
@layer theme, base, components, utilities;
@import 'tailwindcss/theme.css' layer(theme);
@import 'tailwindcss/utilities.css' layer(utilities);
```

## Upgrade from the `theme` and `brand` props

`ThemeProvider` no longer accepts `theme` or `brand`, and `@frogbotai/ui/theme` no longer exports `ThemeTokens` or `BrandTheme`. `BrandConfig` no longer has `tokens`. Passing either prop is a TypeScript error. Move the values into CSS:

```tsx
// Before
<ThemeProvider theme={{ '--primary': 'oklch(0.58 0.18 250)' }}>{children}</ThemeProvider>
```

```tsx
// After
<ThemeProvider>{children}</ThemeProvider>
```

```css
/* Page-level, so it reaches menus and dialogs too */
:root {
  --color-bg-brand: oklch(0.58 0.18 250);
}
```

Set the [color tokens](#color-tokens) the components read instead.

To change colors at runtime, for example per tenant, set the CSS variables on `document.documentElement` yourself.

<Warning>
  Internal utility classes can change between releases and are not public API. Do not use them for white-label overrides.
</Warning>
