Place `<Chat>` under `ChatProvider`. The component loads thread history, streams messages, persists the active thread ID, and exposes slots for application-specific content.

```tsx
'use client'

import { Chat, ChatProvider, cookieFetch } from '@frogbotai/ui/chat'

const adapter = { fetch: cookieFetch() }

export function SupportChat() {
  return (
    <ChatProvider adapter={adapter}>
      <div style={{ height: '100dvh' }}>
        <Chat agent="support" />
      </div>
    </ChatProvider>
  )
}
```

Use `threadId` and `onThreadIdChange` for controlled routing. Use `defaultThreadId` when the component should manage selection internally. `headerSlot`, `composerStartSlot`, `composerEndSlot`, `panel`, and `renderThreadActions` add product-specific controls without replacing the shell.

## Composer selectors

`AgentSelector` reads the agents available to the current user from `ChatProvider`. Keep the selected agent in your application state and pass it to both the selector and `<Chat>`. Changing it starts a new conversation.

```tsx
'use client'

import { useState } from 'react'
import { AgentSelector, Chat, ChatProvider, cookieFetch } from '@frogbotai/ui/chat'

const adapter = { fetch: cookieFetch() }

export function AgentChat() {
  const [agent, setAgent] = useState('support')

  return (
    <ChatProvider adapter={adapter}>
      <Chat
        agent={agent}
        headerSlot={<AgentSelector selectedAgent={agent} onAgentChange={setAgent} />}
      />
    </ChatProvider>
  )
}
```

`ModelSelector` and `ToolSelector` accept caller-supplied lists and controlled selection state. Place `ModelSelector` in `headerSlot` and `ToolSelector` in `composerStartSlot` or `composerEndSlot`. They render nothing when their lists are empty.

<Warning>
  Model and tool selections are currently client-side only. They do not override the server model, change tool availability, or add fields to chat requests.
</Warning>

The selectors intentionally differ from Firmware where FrogBot has no matching concept: agents have no "Default" row, model billing locks are omitted, tools use multi-select availability instead of prompt injection, and Radix handles menu positioning.

## Voice input

The composer shows a microphone when the server manifest advertises a transcription model and the browser supports `MediaRecorder` and microphone access. Tap once to record and again to transcribe. The resulting text is appended to the current draft.

Recording uses the browser's supported audio container: Opus in WebM where available, MP4 on Safari, or the browser default. Audio is sent for batch transcription after recording stops; transcription is not streamed.

Permission, access, network, and empty-audio failures appear beside the microphone without clearing the draft. The recording button retains Firmware's pulse and ripple feedback. The separate live waveform is intentionally omitted because local batch recording does not require Firmware's streaming audio analyzer.
