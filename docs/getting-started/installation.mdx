You can scaffold a FrogBot app by pasting a prompt into your coding agent or by running `create-frogbot-app` in your terminal.

## Start with a coding agent

Open Claude Code, Cursor, Codex, or OpenCode in the folder where you want your project and paste this prompt. Your agent checks Node.js, runs `create-frogbot-app` with the bundled [FrogBot skill](/skills/coding-agents), configures `.env`, and boots the dev server:

<StarterPrompt />

Point your agent at the documentation index anytime it needs to look up a FrogBot page:

```text
https://docs.frogbot.ai/llms.txt
```

## Create an app from the CLI

<Steps>
  <Step title="Scaffold the project">
    Run `create-frogbot-app` interactively, or pass flags with `--yes` for a non-interactive setup:

    <Tabs>
      <Tab title="Interactive">
        ```bash
        npx create-frogbot-app@latest my-app
        ```

        Prompts you to choose a database (`sqlite`, `postgres`, or `mongodb`), an AI provider, your provider API key, and which coding agents should receive the [FrogBot skill](/skills/coding-agents).
      </Tab>
      <Tab title="Non-interactive (--yes)">
        ```bash
        npx create-frogbot-app@latest my-app --yes --ai openai --agents claude,cursor,codex,opencode
        ```

        `--yes` accepts defaults for any flag you omit (`sqlite` database, `blank` template, detected package manager, and `--ai none` unless `--ai` is passed).
      </Tab>
    </Tabs>

    The scaffolder installs dependencies first, then initializes a Git repository with an initial commit that includes the lockfile.
  </Step>
  <Step title="Check your .env file">
    `create-frogbot-app` writes `my-app/.env` with a generated `FROGBOT_SECRET`, your database `DATABASE_URL`, and your AI provider key if you entered one during setup.

    If you skipped the key prompt (or ran with `--yes` without `--api-key`), add your key to `my-app/.env` before starting the app:

    ```bash
    OPENAI_API_KEY=sk-...
    ```

    <Note>
      OpenAI, Anthropic, and Google apps require their key in `.env` before the server starts (unless you configure [`@frogbotai/piece-openai`](/pieces/openai) so users sign in with **Continue with ChatGPT** or link their own key in the UI). Bedrock and Zen apps start without a key, but require one before chatting.
    </Note>
  </Step>
  <Step title="Start the dev server">
    ```bash
    cd my-app
    npm run dev
    ```

    Open [http://localhost:3000](http://localhost:3000) to create your first admin user. From the dashboard, open **Chats** in the sidebar and select **Create New** to talk to your agent, or edit `src/frogbot.config.ts` to add collections, views, pieces, and tools.
  </Step>
</Steps>

## Command options

```bash
npx create-frogbot-app@latest [project-name] [options]
```

Any choice passed as a flag skips its interactive prompt. Passing `--yes` (or running without an interactive terminal) skips all prompts and uses the defaults below. Unknown options, missing values, or invalid choices exit with an error.

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `[project-name]`, `-n`, `--name` | name | Prompted | Project and folder name (required with `--yes`). Lowercase letters, numbers, `.`, `-`, or `_`. |
| `-t`, `--template` | `blank` \| `projects` \| `crm` | `blank` | Starter template. `projects` adds a project tracker with sample data, and `crm` a CRM with companies, deals, activities and tasks and sample data that only loads in development; see [Templates and sample data](/getting-started/templates). |
| `-d`, `--db` | `sqlite` \| `postgres` \| `mongodb` | `sqlite` | Database adapter and connection string. See [Database](/database/overview). |
| `--ai` | `zen` \| `openai` \| `anthropic` \| `google` \| `bedrock` \| `none` | `none` | AI provider configured in `src/frogbot.config.ts`. |
| `--api-key` | string | Prompted | Provider API key written to `.env` (ignored with `--ai none`). |
| `--agents` | `claude`, `codex`, `cursor`, `opencode`, `copilot`, `gemini` | Prompted | Coding agents that receive the [FrogBot skill](/skills/coding-agents). |
| `--no-agents` | flag | off | Skips installing coding-agent skills and overrides `--agents`. |
| `--use-npm`, `--use-pnpm`, `--use-yarn`, `--use-bun` | flag | Detected | Package manager for installing dependencies (`--use-pnpm` also writes `pnpm-workspace.yaml`). |
| `--no-install`, `--no-deps` | flag | off | Skips installing dependencies (and skips the initial Git commit). |
| `--no-git` | flag | off | Skips initializing a Git repository and initial commit. |
| `-y`, `--yes` | flag | off | Accepts defaults for all unspecified flags without prompts. |
| `-h`, `--help` | flag | off | Prints usage and exits. |

<Accordion title="Project naming, environment key detection, and quoting rules">
  - **Project name:** Pass the project name once (either positionally or with `--name`). Must start with a letter or number, and the target folder must not exist yet.
  - **Environment keys:** In interactive mode without `--api-key`, the scaffolder checks your environment for a matching variable (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY`, `AWS_BEARER_TOKEN_BEDROCK`, or `OPENCODE_API_KEY`) and offers to copy it into `.env`.
  - **Agent list quoting:** Spaces around agent names are ignored; quote the list if it includes spaces (for example `--agents "claude, codex"`). With `--yes`, no coding agents are selected unless `--agents` is passed.
</Accordion>

## Software requirements

- **Node.js** `24.21` or newer
- **TypeScript** `6.0.3` or newer
- **Package manager:** npm, pnpm, yarn, or bun
- **Database:** SQLite, PostgreSQL, or MongoDB — see [Database](/database/overview)
- **Object storage (optional):** S3, R2, GCS, Azure Blob, or Vercel Blob — see [Upload](/upload/storage-adapters)

## Monorepos

Keep a single copy of `frogbot` across a workspace so shared blocks, fields, and collections resolve identical TypeScript types:

```bash
pnpm why frogbot
```

- List `frogbot` under `peerDependencies` (and `devDependencies` for local build/test) in shared packages—never under `dependencies`.
- Keep the exact same `frogbot` version across every workspace package and run `pnpm dedupe` if multiple copies appear.
- Install optional peers such as `@ai-sdk/otel` in every package that depends on `frogbot`, or in none of them, so the package graph does not split `frogbot` into separate instances.
