FrogBot is built around a small set of declarative building blocks in one typed TypeScript file (`frogbot.config.ts`). Instead of generating thousands of lines of custom backend and UI glue code, you or your coding agent assemble these building blocks and FrogBot runs the application.

## 1. One config file drives the app

FrogBot loads `frogbot.config.ts` at startup. Your TypeScript configuration is the single source of truth—FrogBot does not rely on hidden dashboard state or scan Markdown folders into the database.

```ts
import { sqliteAdapter } from '@frogbotai/db-sqlite'
import { buildConfig } from 'frogbot'

export default buildConfig({
  secret: process.env.FROGBOT_SECRET!,
  db: sqliteAdapter({
    client: { url: 'file:./frogbot.db' },
  }),
  collections: [
    {
      slug: 'deals',
      fields: [
        { name: 'title', type: 'text', required: true },
        {
          name: 'stage',
          type: 'select',
          options: ['lead', 'qualified', 'proposal', 'won'],
          defaultValue: 'lead',
        },
        { name: 'value', type: 'number' },
      ],
    },
  ],
  ai: {
    providers: {
      openai: true,
    },
  },
  agents: [
    {
      slug: 'assistant',
      model: 'openai/gpt-4.1-mini',
      instructions: 'Help the team manage deals and answer pipeline questions.',
    },
  ],
})
```

Running `frogbot generate:types` produces `frogbot-types.ts` with end-to-end TypeScript types for every collection, field, agent, and piece in your config.

## 2. Collections generate your data layer, APIs, and Admin UI

[Collections](/configuration/collections) are source-controlled schema definitions. From each collection, FrogBot automatically provides:

- **Database storage & migrations** across [SQLite](/database/sqlite), [Postgres](/database/postgres), or [MongoDB](/database/mongodb)
- **Admin UI views** — instant [Table](/admin/overview), drag-and-drop [Kanban boards](/admin/collection-board), and [Calendars](/admin/collection-calendar)
- **Three APIs** — zero-overhead [Local API](/local-api/overview) (`frogbot.find`, `frogbot.create`), [REST endpoints](/rest-api/overview) (`/api/:slug`), and [GraphQL](/graphql/overview)
- **Document & field [access control](/access-control/overview)** and lifecycle [hooks](/hooks/overview)

When agents are configured, FrogBot automatically registers default `chats` and `messages` collections (or adopts collections marked with `chat: true` and `message: true`).

## 3. Agents run typed tool loops with user permissions

An [agent](/agents/overview) is a code-defined `AgentConfig` object backed by an AI SDK `ToolLoopAgent`. Tools use [Zod](https://zod.dev) input schemas and receive a request-aware context (`ctx.frogbot` and `ctx.req`).

```ts
import { z } from 'zod'
import type { AgentConfig, Tool } from 'frogbot'

const findDeal: Tool = {
  slug: 'find-deal',
  description: 'Look up a deal by ID using the caller permissions.',
  inputSchema: z.object({ dealId: z.string() }),
  execute: async ({ dealId }, ctx) => {
    return ctx.frogbot.findByID({
      collection: 'deals',
      id: dealId,
      req: ctx.req,
      overrideAccess: false,
    })
  },
}

export const dealDesk: AgentConfig = {
  slug: 'deal-desk',
  model: 'openai/gpt-4.1',
  instructions: 'Check deal stage and value before drafting a quote.',
  tools: [findDeal],
  access: ({ req }) => Boolean(req.user),
}
```

Every agent automatically gets `GET /api/agents` and `POST /api/agents/:slug` HTTP endpoints supporting both JSON and Server-Sent Events (SSE) streaming.

## 4. Chat persists full model trajectories

Authenticated agent calls create or continue owner-scoped [chats](/chat/overview). Messages retain the full `UIMessage.parts` structure—including tool calls and tool results—so follow-up turns see the complete reasoning trajectory rather than a flattened text transcript.

The server owns chat history: a client sends `chatId` and only the new user message, and FrogBot loads prior turns, validates them against the agent's tools, and saves the new turn.

## 5. Pieces, connections, and jobs automate workflows

- **[Pieces](/pieces/overview) & [Connections](/connections/overview)** wire up 40+ external services (Slack, Gmail, Linear, GitHub, Discord, Stripe, Notion, Xero) with managed OAuth, webhook triggers, and interactive [channel questions](/pieces/channel-questions) that pause until a human replies in chat.
- **[Jobs](/jobs-queue/overview)** run background tasks, cron schedules, and retries in your database without requiring a separate queue broker.
- **[Plugins](/plugins/overview)** transform your config to add capabilities like [RBAC roles](/plugins/roles), [audit logs](/plugins/audit-log), [MCP servers](/plugins/mcp), [API keys](/plugins/api-keys), and one-command cloud deployment to [Dojo](/plugins/dojo) (`npx frogbot share`).

## 6. Requests connect every layer

`FrogBotRequest` carries `req.user`, `req.frogbot`, active database transactions, and locale across every layer of your app:

- **HTTP endpoints** (`/api/...` and `/api/agents/:slug`) enforce collection and agent access rules automatically.
- **Local API calls** (`frogbot.find`, `frogbot.update`) run as trusted server code by default. Pass `req: ctx.req` and `overrideAccess: false` inside agent tools or custom endpoints whenever running on behalf of a signed-in user.
