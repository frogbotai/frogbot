The `frogbot` package installs a `frogbot` command. Run it from your app's root directory through your package manager, for example `pnpm frogbot dev` or `npx frogbot dev`.

```bash
pnpm frogbot generate:types
```

- **Environment files:** Before any command runs, `frogbot` loads `.env*` files from the current directory using Next.js rules (development files unless `NODE_ENV` is `production`).
- **Config discovery:** Commands that load your app look for `frogbot.config.{ts,js,mjs}` in the current directory, `src/`, a parent directory, or the path in `FROGBOT_CONFIG_PATH`.
- **Exit codes:** Command names are case-insensitive. A missing or unknown command prints available commands (and points to [Plugin commands](#plugin-commands)) and exits with code `2`. A command that fails prints the error and exits with code `1`.

## Commands

| Command | Arguments | Description |
| --- | --- | --- |
| `dev` | Next.js `dev` arguments | Generates the admin import map, then starts the Next.js development server. See [`dev` and `start`](#dev-and-start). |
| `start` | Next.js `start` arguments | Warns when the admin import map is stale, then starts the Next.js production server. See [`dev` and `start`](#dev-and-start). |
| `run` | `<file> [args...]` | Runs a TypeScript or JavaScript file with your app's environment and config alias. See [Outside Next.js](/local-api/outside-nextjs). |
| `generate:types` | — | Writes `frogbot-types.ts` from your config. See [Generating types](/typescript/generating-types). |
| `generate:importmap` | — | Writes the admin import map for the custom components your config references. See [Custom components](/custom-components/overview). |
| `generate:piece-types` | `<module>`, `--export`, `--output`, `--check` | Writes the TypeScript types for a piece's actions and triggers. See [Generate piece types](#generate-piece-types). |
| `pieces:port` | `<slug>` | Prepares a piece package in the FrogBot repository for porting. See [Port a piece](#port-a-piece). |
| `jobs:run` | `--cron`, `--limit`, `--queue`, `--all-queues`, `--handle-schedules` | Runs a long-lived jobs worker without Next.js. See [Workers](/jobs-queue/workers). |
| `channels:run` | — | Holds chat-channel gateway connections, such as Discord's, in their own process. See [Discord](/pieces/discord). |
| `migrate` | — | Applies pending database migrations. See [Migrations](/database/migrations). |
| `migrate:create` | `[name]`, `--name`, `--file`, `--skip-empty`, `--force-accept-warning` | Creates a migration from the current schema. See [Migrations](/database/migrations). |
| `migrate:status` | — | Lists applied and pending migrations. See [Migrations](/database/migrations). |
| `migrate:down` | — | Rolls back the last batch of migrations. See [Migrations](/database/migrations). |
| `migrate:refresh` | — | Rolls back every migration, then applies them all again. See [Migrations](/database/migrations). |
| `migrate:reset` | — | Rolls back every migration. See [Migrations](/database/migrations). |
| `migrate:fresh` | `--force-accept-warning` | Drops every table, then applies all migrations. See [Migrations](/database/migrations). |

## Plugin commands

Plugins and your config can register custom CLI commands under `cli.commands`. Each key is a lowercase command name, and each value is an async or sync handler that runs when you call `frogbot <name>`.

```ts
import { buildConfig } from 'frogbot'

export default buildConfig({
  // ...
  cli: {
    commands: {
      'users:count': async ({ getFrogBot }) => {
        const frogbot = await getFrogBot()
        const { totalDocs } = await frogbot.count({ collection: 'users' })

        console.log(totalDocs)
      },
    },
  },
})
```

When your app has a config file, `frogbot` loads it before running any command and passes the handler one context object:

| Field | Type | Description |
| --- | --- | --- |
| `args` | `string[]` | Arguments passed after the command name. |
| `command` | `string` | The name the command was invoked as. |
| `getConfig` | `() => Promise<FrogBotSanitizedConfig>` | Resolves to the sanitized config `frogbot` already loaded. |
| `getFrogBot` | `(options?) => Promise<FrogBot>` | Boots a FrogBot instance on first call, reuses it on later calls, and destroys it when the command finishes. Accepts `init` options (excluding `config`). |

<Accordion title="Execution lifecycle, overrides, and error handling">
  - **Completion & exit codes:** `frogbot` exits when your handler's promise resolves (using `process.exitCode` if set, otherwise `0`), so `await` all async work. Throwing an error prints the message and exits with code `1`.
  - **Overriding & merging:** A `cli.commands` entry with the same name as a built-in command replaces it. Plugins should spread existing commands (`cli: { ...config.cli, commands: { ...config.cli?.commands, 'my:command': handler } }`) so user commands are preserved.
  - **Validation:** Command names containing uppercase letters or non-function handlers fail config validation. If the config file fails to load, built-in commands still run while plugin commands print the load error and exit with code `1`.
  - **Unknown commands:** Running an unknown command prints `[frogbot] "<name>" isn't a command in this app.` (or `[frogbot] "<name>" isn't a built-in command, and there's no app here to add it.` when no config file is found) and exits with code `2`.
</Accordion>

### Commands from `dojo()`

Included automatically in apps created with `create-frogbot-app` via [`dojo()`](/plugins/dojo). Without an app (such as when pulling an app into an empty directory), run them as `npx @frogbotai/plugin-dojo <command>`:

| Command | Arguments | Description |
| --- | --- | --- |
| `share` | `--data`, `--no-data`, `--workspace`, `--name`, `--no-keys`, `--skip-key`, `--yes`, `--update-keys` | Uploads the app to Dojo, builds it, and prints its live URL. See [`share`](#share). |
| `pull` | `<app>` | Downloads an app shared with you on Dojo into a new folder. See [`pull`](#pull). |
| `logs` | `<app>`, `--follow` | Prints an app's recent logs from Dojo, or follows them live. See [`logs`](#logs). |
| `logout` | — | Signs the CLI out of Dojo. See [`logout`](#logout). |

### `share`

```bash
npx frogbot share --no-data
```

Uploads the app in the current folder to Dojo, streams `[build]` logs, and prints a share link followed by the live `https://<name>.frogbot.app` URL. Run it from the folder containing `frogbot.config.ts` (or its parent when the config is inside `src/`). In an app without `dojo()`, run `npx @frogbotai/plugin-dojo share`.

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `--data` | flag | — | On the first share, uploads local SQLite data and files without prompting. |
| `--no-data` | flag | — | On the first share, uploads code only without prompting. |
| `--workspace` | workspace slug | — | Dojo workspace to create the app in on first share (when you belong to multiple). |
| `--name` | name | `package.json` `name` | Subdomain slug for `https://<name>.frogbot.app` on first share (lowercased, alphanumeric + dashes). |
| `--no-keys` | flag | — | Uploads no `.env` keys. |
| `--skip-key` | key name (repeatable) | — | Excludes a specific key (case-sensitive), e.g. `--skip-key STRIPE_KEY`. Unknown key names exit with code `2`. |
| `--yes` | flag | — | On the first share, uploads all detected keys without the interactive checklist. |
| `--update-keys` | flag | — | On subsequent shares, overwrites live keys whose local values differ. |

<AccordionGroup>
  <Accordion title="Pre-flight checks & signing in">
    - **Lockfile check:** `share` stops before uploading if `package.json` is missing, if the app uses Bun, or if no `pnpm-lock.yaml`, `package-lock.json`, or `yarn.lock` is present.
    - **Browser login:** On first use, `share` prints a Dojo verification URL and code (and opens your browser in interactive terminals). Your token is saved in `~/.config/frogbotai/auth.json` (or `$XDG_CONFIG_HOME`) with owner-only permissions.
    - **Custom Dojo endpoint:** Set `FROGBOT_DOJO_URL` to target a different Dojo instance.
  </Accordion>
  <Accordion title="First share vs. subsequent updates">
    - **First share:** Creates a Dojo app named after `package.json`'s `name` (or `--name`), writes the app ID to `.frogbot/app.json`, and adds `/.frogbot` to `.gitignore`.
    - **Later shares:** Deploying again from the same folder ships a new version of the linked app. Delete `.frogbot/app.json` to deploy as a brand-new app.
    - **Name collisions & workspaces:** If the app name is taken on Dojo, `share` prompts you to rerun with `--name <another name>`. If you belong to multiple workspaces in a non-interactive shell, pass `--workspace`.
  </Accordion>
  <Accordion title="Bringing local database & upload files (--data)">
    - **First share only:** On the first share of a local `file:` SQLite app, `share` asks `Bring your data? 42 deals, 3 users, 12 files` (or requires `--data` / `--no-data` when non-interactive). Once a version of the app has started on Dojo, later shares deploy code only and never overwrite live data.
    - **Safe live copy:** `share` copies your SQLite database so it works while `frogbot dev` is running, stripping local-only state (queued jobs, locks, sessions, trigger subscriptions) while preserving users, password hashes, and `FROGBOT_SECRET` so existing connections keep working.
    - **Upload collections:** Files inside upload directories within your project root are uploaded with progress output and automatic 3x retries. `.env*`, `.git`, `node_modules`, and database files inside upload folders are excluded.
  </Accordion>
  <Accordion title="Environment keys (--no-keys, --skip-key, --update-keys)">
    - **Encryption & masking:** Keys from `.env*` files are masked in terminal output (`STRIPE_KEY ••••4242`) and sealed to Dojo's public key before leaving your machine. Platform variables (`DATABASE_URL`, `FROGBOT_SECRET`, `NODE_ENV`, `PORT`, `HOSTNAME`) are managed by Dojo automatically.
    - **First vs. later shares:** The first share lets you untick any keys interactively (or uploads all keys when non-interactive). Later shares add newly introduced keys automatically and keep existing live values unless you pass `--update-keys`.
    - **Editors:** Collaborators with editor access (such as from [`pull`](#pull)) deploy code only; key changes are restricted to workspace owners.
  </Accordion>
  <Accordion title="Uploaded files, 100 MB limit, and exit codes">
    - **Included files:** Uploads all tracked and untracked working files that are not ignored by `.gitignore` (up to **100 MB**).
    - **Always excluded:** `.git`, `.frogbot/`, `.env*`, `frogbot.db*`, `*.sqlite*`, `node_modules`, `.next`, `files/`, upload collection folders, and symlinks.
    - **Exit codes:** Build or upload failures print the last build lines and exit with code `1`. Invalid flag combinations (such as `--data` with `--no-data`) exit with code `2`.
  </Accordion>
</AccordionGroup>

### `pull`

```bash
npx @frogbotai/plugin-dojo pull deals
```

Downloads the live code of a Dojo app you own or edit into a new `./<app>` directory, links `.frogbot/app.json` so running `npx frogbot share` from that folder updates the same app, and writes a fresh local `.env` (`DATABASE_URL=file:./frogbot.db` and `FROGBOT_SECRET`). Live data and production secrets remain on Dojo.

```bash
cd deals
pnpm install
pnpm dev
```

- Refuses to overwrite an existing folder.
- Exits with code `1` if you lack editor/owner permissions or the app has no live version yet, and code `2` if no app slug is passed.

### `logs`

```bash
npx @frogbotai/plugin-dojo logs deals --follow
```

Prints recent logs (last 24 hours, oldest first) for a Dojo app you own or edit, masking any stored secret values of 8+ characters as `••••`. Pass `--follow` to stream new lines every 2 seconds until Ctrl+C.

### `logout`

```bash
npx @frogbotai/plugin-dojo logout
```

Revokes the CLI's key in Dojo and removes it from `auth.json`. If Dojo cannot be reached, the local file is kept so you can retry `logout`.

## `dev` and `start`

```bash
frogbot dev --port 4000
```

`frogbot dev` regenerates the admin import map, then runs `next dev`. `frogbot start` checks the import map, warns if `frogbot generate:importmap` is needed, and runs `next start`. Set `admin.importMap.autoGenerate` to `false` in `frogbot.config.ts` to skip the import map step.

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| Any Next.js argument | Next.js `dev` or `start` arguments | — | Forwarded to Next.js unchanged (for example `--port 4000` or `--webpack`). |

Requires `next.config.{ts,mjs,js,cjs}` and `next` in the current directory (`typescript` is also required at startup when using `next.config.ts`). Forwards `SIGINT`/`SIGTERM` and exits with Next.js's exit code.

## Generate piece types

```bash
frogbot generate:piece-types src/index.ts --export createResend --output src/piece-types.ts
```

Loads a piece factory and writes the TypeScript input/output types for its actions and triggers, formatted with Prettier.

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `<module>` | file path | Required | Module that exports the piece factory, resolved from the current directory. |
| `--export` | export name | Required | Name of the piece factory export, such as `createResend`. |
| `--output` | file path | Required | File to write (left untouched when content is unchanged). |
| `--check` | flag | off | Exits with `Piece types are stale` instead of writing when out of date (for CI). |

## Port a piece

```bash
frogbot pieces:port google-sheets
```

Contributor command run from the root of the FrogBot repository. Moves `packages/pieces/piece-<slug>` and `test/unit/piece-<slug>` to `.legacy` folders, then scaffolds a native piece package and test skeleton.

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `<slug>` | lowercase letters, numbers, and single dashes | Required | Piece slug, such as `google-sheets`. |
