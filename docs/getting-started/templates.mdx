`create-frogbot-app` asks which template to start from, or takes it from `--template`:

```bash
npx create-frogbot-app@latest my-app --template projects
```

| Template   | What you get                                                                                                                                                                                  |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `blank`    | Users, file uploads, and the `general` and `assistant` agents. The default.                                                                                                                                           |
| `projects` | A project tracker: projects, tasks numbered per project with keys such as `WEB-12` ([autonumber](/fields/autonumber#numbering-per-project)), a board grouped by status, and sample data. |

Every template works with SQLite, PostgreSQL and MongoDB, and with every AI provider. With `--ai none`, the template's agents, AI config and AI-only plugins are left out; its collections and sample data stay.

## Loading the sample data

While a template's app has none of its records, the dashboard shows an **Add sample data** panel at the top. Its button calls `POST /api/seed`, which adds the sample records for you, the signed-in user: in the `projects` template, every sample task is assigned to you. It makes no demo login and deletes nothing.

Seed works only on an empty app. Once the app has a record, such as one project, the panel hides and the endpoint answers `409` without changing anything. That makes it safe to keep in a deployed app, including one on Dojo, where each app has its own database. To seed again locally, delete the database.

## How a seed is built

The seed is plain code in your app, in three files you can change or delete:

| File                           | Does                                                                                                         |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| `src/seed/index.ts`            | `seed({ frogbot, req })` adds the sample records through the [Local API](/local-api/overview), and `hasRecords(frogbot)` says whether the app has any. |
| `src/seed/endpoint.ts`         | `seedEndpoint()`, the `POST /api/seed` [root endpoint](/rest-api/overview#custom-endpoints).                  |
| `src/components/SeedPanel.tsx` | The dashboard panel, registered in `admin.components.beforeDashboard`. A server component that renders the button only while `hasRecords` is false. |

The seed passes `overrideAccess: true` and the request to each call, so it can write fields people can't, such as [autonumber](/fields/autonumber#seeds-and-migrations) numbers. It doesn't import anything from `src/agents`, so it keeps working when the app has no AI.

The endpoint refuses a request with no signed-in user with `403`, and answers `409` once the app has records. If the seed throws, it logs the error and answers `500`; otherwise it answers `{ "success": true }`:

```ts
import type { Endpoint } from 'frogbot'

import { hasRecords, seed } from './index'

export function seedEndpoint(): Endpoint {
  return {
    path: '/seed',
    method: 'post',
    handler: async (req) => {
      if (!req.user) {
        return Response.json({ error: 'Sign in to seed the database.' }, { status: 403 })
      }

      if (await hasRecords(req.frogbot)) {
        return Response.json(
          { error: 'This app already has data, so there is nothing to seed.' },
          { status: 409 },
        )
      }

      try {
        await seed({ frogbot: req.frogbot, req })
      } catch (err) {
        req.frogbot.logger.error({ err }, 'Seeding the database failed')

        return Response.json({ error: 'Seeding the database failed.' }, { status: 500 })
      }

      return Response.json({ success: true })
    },
  }
}
```

Register both in the config:

```ts
import { buildConfig } from 'frogbot'

import { seedEndpoint } from './seed/endpoint'

export default buildConfig({
  // ...
  endpoints: [seedEndpoint()],
  admin: {
    components: {
      beforeDashboard: ['/components/SeedPanel#SeedPanel'],
    },
  },
})
```
