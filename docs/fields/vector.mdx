A vector field stores a fixed-length array of numbers. You can create, read, replace, and delete its value through ordinary collection operations without configuring a search index or an AI provider. FrogBot does not generate the vector unless you add [`embedFrom`](#embed-on-save) to the field.

## Configure a vector field

Install `@frogbotai/db-sqlite`, set `FROGBOT_SECRET`, and add this `frogbot.config.ts`:

```ts
import { sqliteAdapter } from '@frogbotai/db-sqlite';
import { buildConfig } from 'frogbot';

export default buildConfig({
  secret: process.env.FROGBOT_SECRET!,
  db: sqliteAdapter({ client: { url: 'file:./frogbot.db' } }),
  collections: [
    {
      slug: 'articles',
      fields: [
        { name: 'title', type: 'text', required: true },
        { name: 'embedding', type: 'vector', dimensions: 3 },
      ],
    },
  ],
});
```

This configuration has **no `search` index** and can initialize with the SQLite adapter. The three-dimensional value keeps the example short; choose dimensions that match the vectors your application supplies.

## Config options

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `name` | `string` | Required | Property name used in stored records and APIs. See [field names](/fields/overview#field-names). |
| `type` | `'vector'` | Required | Selects the Vector field. |
| `dimensions` | `number` | Required | Number of values in every vector. Must be a positive integer. |
| `label` | `string \| Record<string, string> \| (({ i18n, t }) => string) \| false` | Generated from `name` | Label shown in the admin panel. Use an object keyed by language code for translations, or `false` to hide the label. |
| `required` | `boolean` | `false` | Rejects a missing or `null` vector on normal writes. |
| `unique` | `boolean` | `false` | Creates a unique database index for the field path. See [indexes](/database/indexes). |
| `index` | `boolean` | `false` | Creates a database index for faster queries. `unique` already creates one. |
| `localized` | `boolean` | `false` | Stores one value per configured locale. Ignored without [localization](/configuration/localization) or inside a localized parent. |
| `defaultValue` | `number[]` or `({ locale, req, user }) => value` | — | Value used when the field has no value. See [default values](/fields/overview#default-values). |
| `validate` | `Validate<number[]>` | — | Extra validation that runs after FrogBot checks the length and that every value is a finite number. See [validation](/fields/overview#validation). |
| `hooks` | `{ beforeValidate, beforeChange, afterChange, afterRead, beforeDuplicate }` | — | Arrays of `FieldHook` functions for each phase. See [field hooks](/hooks/fields). |
| `access` | `{ create, read, update }` | Allowed | `FieldAccess` functions for each operation. See [field access control](/access-control/fields). |
| `hidden` | `boolean` | `false` | Removes the field from API responses and the admin panel while keeping stored data. |
| `saveToJWT` | `boolean \| string` | `false` | In an auth-enabled collection, copies the value into the user's token. A string sets the token key. See [token data](/authentication/token-data). |
| `virtual` | `boolean \| string` | `false` | `true` skips database storage; a string reads a value through a relationship path. Virtual fields are read-only in the admin panel unless `admin.readOnly` is `false`. See [virtual fields](/fields/overview#virtual-field-configuration). |
| `disableDuplicate` | `boolean` | `false` | Leaves the value out when a document is duplicated, so the copy uses `defaultValue`. |
| `admin` | `object` | — | Admin-panel options. See [Admin options](#admin-options). |
| `custom` | `Record<string, any>` | — | Server-only metadata for your own code and plugins. Use `admin.custom` for data the browser also needs. FrogBot adds the dimensions under `custom.frogbot.vector`. |
| `jsonSchema` | `Array<({ jsonSchema }) => JSONSchema4>` | — | Functions that modify the JSON Schema used by [type generation](/typescript/generating-types). FrogBot runs its own step last, so generated types are always `number[]`, plus `null` when the field is optional. |

## Admin options

Vector fields use the JSON editor and support the standard [field admin options](/fields/overview#admin-options), plus these options:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `editorOptions` | `EditorProps['options']` | — | Monaco editor options for the JSON editor, such as `minimap` or `tabSize`. |
| `maxHeight` | `number` | — | Maximum editor height in pixels. The editor grows with its content up to this height. |

## Write and read vectors

In trusted server-side code, use the [Local API](/local-api/overview). This example explicitly bypasses collection access; for request-scoped operations, pass the request and use `overrideAccess: false` instead.

```ts
import { getFrogBot } from 'frogbot';

import config from './frogbot.config';

const frogbot = await getFrogBot({ config });

const created = await frogbot.create({
  collection: 'articles',
  data: { title: 'Account recovery', embedding: [0.5, -1, 0] },
  overrideAccess: true,
});

const updated = await frogbot.update({
  collection: 'articles',
  id: created.id,
  data: { embedding: [1, 2, 3] },
  overrideAccess: true,
});

const article = await frogbot.findByID({
  collection: 'articles',
  id: updated.id,
  overrideAccess: true,
});

await frogbot.delete({
  collection: 'articles',
  id: article.id,
  overrideAccess: true,
});

await frogbot.destroy();
```

- **`dimensions`** must be a positive integer.
- **A supplied value** must be an array of exactly that many finite numbers. Strings, `NaN`, and `Infinity` are rejected.
- **Optional fields** may be omitted or set to `null`. Set `required: true` to require a value on normal writes.
- **Generated collection types** represent vector values as `number[]`, optional or nullable according to the field configuration.
- **The admin panel** uses the JSON editor for the field. `admin.hidden` and `admin.readOnly` change presentation, not API permissions.

<Warning>
  Set vectors in a [collection hook](/hooks/collections) or in the vector field's own
  [hooks](/hooks/fields). FrogBot validates the vector after those hooks run. Hooks on other fields
  run at the same time as the vector's validation, so a vector they set after an `await` can be
  saved without validation, including in drafts.
</Warning>

Matching dimensions do not guarantee two embeddings use the same model or embedding space. Without [`embedFrom`](#embed-on-save), updating a record does not regenerate its embedding. See [Search](/search/overview) for the index and query API's current availability.

## Embed on save

`embedFrom` returns a `beforeChange` hook that fills the vector from the record's own text with [`frogbot.embed`](/ai/overview#embedding-options). Add it to the vector field and name the model; nothing is picked by default. This needs an [`ai` config](/ai/overview#configure-providers) with that embedding model.

```ts
import { embedFrom } from 'frogbot/search';

{
  name: 'embedding',
  type: 'vector',
  dimensions: 1536,
  hooks: {
    beforeChange: [embedFrom({ fields: ['title', 'body'], model: 'openai/text-embedding-3-small' })],
  },
}
```

| Option | Type | Description |
| --- | --- | --- |
| `model` | `ModelId` | Required. A configured embedding model or a router to one. |
| `fields` | `string[]` | Sibling `text`, `textarea`, `email` or `code` fields, not `hasMany`. Their trimmed values are joined in order with a blank line; empty ones are left out. |
| `text` | `(doc) => string \| null \| undefined` | Builds the text yourself instead. `doc` is the saved record merged with the incoming data, at the vector field's level. |

Set exactly one of `fields` or `text`. FrogBot checks the options at startup: the hook must be in the `beforeChange` hooks of a vector field, every `fields` entry must be a sibling text-like field holding one string, and the model must be a configured embedding model. A bad model only warns while generating types.

On each save, the hook builds the text from the saved record merged with the incoming data, so a partial update sees the whole record:

- Empty text stores `null`, with no model call.
- A create, a change in the text, or a missing stored vector calls the model and stores the result.
- Otherwise the stored vector is kept, with no model call, so saves that don't touch the text cost nothing.
- A vector you send yourself, different from the stored one, is kept as sent. Sending back the unchanged stored vector, as the admin panel does, doesn't count.

The field's dimension check runs on the result, so a model that returns the wrong size fails the save with a validation error.

**Drafts.** Draft saves, autosave included, make no model call. Publishing compares the text against the published record and embeds when it changed. Publishing a record again after unpublishing it always embeds.

**Access.** The call uses the save's own `overrideAccess`. A save that checks access, such as a REST request, also checks [`ai.access.embed`](/ai/overview#control-access), which by default needs a signed-in user. A Local API save that skips access skips it too. Usage is logged like any other `frogbot.embed` call.

**Failures.** If the call fails, or AI access is denied, the save fails with that error and nothing is written. To save without the vector instead, wrap the hook in your own `try`/`catch` and return `null`; the next save then retries because the vector is missing.

**Localization.** A `localized` vector field gets one vector per locale, built from that locale's text. If any `fields` source is localized, the vector field must be localized too. A write with `locale: 'all'` fails; save one locale at a time.

The model call runs while the save's transaction is open, so a slow provider makes saves slow. `embedFrom` does not:

- embed existing records: each one is embedded on its next save that has text;
- notice a model change: records keep vectors from the old model until their text changes;
- split long text into chunks, or store more than one vector per record.

## Storage

Vectors are stored as JSON arrays by default. A database adapter can instead map each vector field, with its path and dimensions, to a native vector column through the adapter's `mapVectorField` option. None of the built-in adapters provides native vector storage yet, so every adapter uses the JSON default today.
