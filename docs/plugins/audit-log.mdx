---
title: Audit log
description: Record immutable collection create, update, and delete activity in FrogBot.
---

The audit log plugin records who changed each document, what changed, and when. Audit entries are available in the `audit-logs` collection and cannot be created, updated, or deleted through the API.

## Installation

```bash
pnpm add @frogbotai/plugin-audit-log
```

## Configuration

```ts
import { auditLogPlugin } from '@frogbotai/plugin-audit-log'
import { buildConfig } from 'frogbot'

export default buildConfig({
  collections: [
    {
      slug: 'posts',
      fields: [{ name: 'title', type: 'text' }],
    },
  ],
  plugins: [auditLogPlugin()],
})
```

By default, the plugin audits create, update, and delete operations for every configured collection. The plugin runs with `order: 90`, after plugins that add collections, so those collections are audited too wherever you list it.

Each entry records the collection, operation, document ID, user, API key ID when available, timestamp, and a shallow changed-fields diff. Fields with `hidden: true` never appear in `changes` or `snapshot`, at any depth, even when the write reads them with `showHiddenFields`. Relationship, upload and join values are saved as IDs, so a related document's fields never appear either.

The entry is saved inside the change's transaction, so a rolled-back change leaves no entry. A failed audit write is logged. When the change runs in a transaction (Postgres, a MongoDB replica set, or SQLite with `transactionOptions`), the failed write has already rolled the transaction back, so the change fails too and nothing is saved. Without a transaction the change is already saved and stays saved.

## Collection selection

Use an allowlist:

```ts
auditLogPlugin({ collections: ['posts', 'media'] })
```

Or exclude selected collections:

```ts
auditLogPlugin({ collections: { exclude: ['sessions'] } })
```

Use `operations` to limit recorded operations:

```ts
auditLogPlugin({ operations: ['update', 'delete'] })
```

## The audit collection

Reading audit entries requires an authenticated user by default. Change the audit collection with `overrides`, which takes any collection config key. `access` and `admin` merge over the defaults, and `fields` receives the default fields and returns the full list:

```ts
auditLogPlugin({
  overrides: {
    slug: 'activity',
    access: {
      read: ({ req }) => req.user?.role === 'admin',
    },
    admin: { group: 'Settings' },
  },
})
```

Internal audit writes always override access. API create, update, and delete access stays disabled unless you override it. `overrides.fields` must keep every default field, because the plugin writes them, and the plugin throws at startup if one is missing or named twice.

## Activity field

`activityField()` returns a `ui` field that lists the open record's audit entries, newest first: who created it, which fields each edit changed, and when. Place it anywhere in a collection's `fields`, usually in a tab at the end, and it shows on the edit page and in the [record panel](/admin/record-panel#activity-and-comments):

```ts
import { activityField, auditLogPlugin } from '@frogbotai/plugin-audit-log'

export default buildConfig({
  collections: [
    {
      slug: 'tasks',
      fields: [
        { name: 'title', type: 'text' },
        {
          type: 'tabs',
          admin: { className: 'fb-pill-tabs' },
          tabs: [{ label: 'Activity', fields: [activityField()] }],
        },
      ],
    },
  ],
  plugins: [auditLogPlugin()],
})
```

It reads the record and its entries with the signed-in user's access: a record the user can't read shows nothing, and an edit names only the fields the user can read. It shows the latest 20 entries, skips entries older than the record (a database can reuse a deleted record's id), and renders nothing on a create form. Pass field options to change it, for example `activityField({ name: 'history', label: 'History' })`.

## Custom entries

`entry` receives the entry the plugin would save, the audited collection's slug, the operation, the document and previous document (with hidden fields removed and related documents reduced to IDs), and `req`. Return the entry to save, with any extra values, or `false` to save nothing. Add a field for each extra value with `overrides.fields`.

This activity log stores a tenant ID on every entry, so readers see only their tenant's rows, and skips updates that only bump `lastUsedAt`:

```ts
auditLogPlugin({
  overrides: {
    fields: ({ defaultFields }) => [
      ...defaultFields,
      { name: 'tenant', type: 'text', index: true },
    ],
    access: {
      read: ({ req }) => (req.user ? { tenant: { equals: req.user.tenant } } : false),
    },
  },
  entry: ({ entry, req }) => {
    const changed = Object.keys(entry.changes)

    if (entry.operation === 'update' && changed.every((key) => key === 'lastUsedAt')) return false

    return { ...entry, tenant: req.user?.tenant }
  },
})
```

An `entry` that throws is logged, and the change is saved without an entry. An entry the audit collection rejects, such as one missing a required field, is a failed audit write, so in a transaction it fails the change.

## Optional metadata

Enable request IP and user-agent capture:

```ts
auditLogPlugin({ ipAddress: true })
```

Forwarded IP headers are ignored by default because clients can spoof them. If every request reaches FrogBot through a trusted proxy that replaces `x-forwarded-for` or `x-real-ip`, explicitly enable proxy trust:

```ts
auditLogPlugin({ ipAddress: true, trustProxy: true })
```

`trustProxy` trusts the first `x-forwarded-for` value and falls back to `x-real-ip`. Do not enable it when clients can connect directly or when your proxy appends untrusted values instead of replacing the header. User-agent capture does not require proxy trust.

Store full document snapshots for deletes or every operation:

```ts
auditLogPlugin({ snapshot: 'delete' })
```

The default snapshot mode is `never`.

<Warning>
  Snapshots can store secrets, personal data, uploaded-content metadata, and other sensitive document fields. Enable them only after applying appropriate audit-log read access, retention, and data-handling controls.
</Warning>

## Retention

Audit entries are retained indefinitely by default. Enable scheduled pruning with a retention window:

```ts
auditLogPlugin({
  retention: {
    days: 365,
    cron: '0 2 * * *',
  },
})
```

The task `frogbot-prune-<slug>`, named after the audit collection's slug, runs at midnight daily unless you set `cron`, and it is scheduled on the `default` queue, so a jobs runner that covers `default` prunes without extra setup. Each run deletes entries whose `timestamp` is older than `days`, 100 at a time, and fails the job if any entry can't be deleted.

## Options

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `collections` | `string[] \| { include?: string[]; exclude?: string[] }` | All collections | Selects audited collections. |
| `operations` | `('create' \| 'update' \| 'delete')[]` | All operations | Selects audited operations. |
| `overrides` | `Partial<CollectionConfig>` with `fields?: ({ defaultFields }) => Field[]` | None | Changes the audit collection: `slug` (default `'audit-logs'`), `access` (read defaults to authenticated users), `admin`, `fields` and any other collection key. |
| `entry` | `({ entry, collection, operation, doc, previousDoc, req }) => entry \| false` | None | Returns the entry to save, or `false` to skip it. May be async. |
| `ipAddress` | `boolean` | `false` | Records user agent and trusted forwarded IP metadata. |
| `trustProxy` | `boolean` | `false` | Trusts forwarded IP headers when IP capture is enabled. |
| `snapshot` | `'never' \| 'delete' \| 'always'` | `'never'` | Controls full document snapshots. |
| `retention` | `false \| { days: number; cron?: string }` | `false` | Schedules deletion of entries older than `days` on the `default` queue. `days` must be a positive integer. |
