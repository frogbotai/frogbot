The MCP plugin exposes your app's collections to external MCP clients such as Claude Desktop and Cursor. It signs requests in with FrogBot's hashed, revocable API keys, so your app has one key system.

## Install

```bash
pnpm add @frogbotai/plugin-mcp @frogbotai/plugin-api-keys
```

## Configure

Add `mcpPlugin()` after `apiKeysPlugin()` in the plugin array.

```ts
import { apiKeysPlugin } from '@frogbotai/plugin-api-keys'
import { mcpPlugin } from '@frogbotai/plugin-mcp'
import { buildConfig } from 'frogbot'

export default buildConfig({
  collections: [
    { slug: 'users', auth: true, fields: [] },
    { slug: 'posts', fields: [{ name: 'title', type: 'text' }] },
  ],
  plugins: [apiKeysPlugin(), mcpPlugin()],
})
```

Configure your MCP client to send Streamable HTTP requests to `/api/mcp` with a key from the API Keys admin collection:

```http
Authorization: Bearer fb_...
```

Revoked, malformed, and unknown keys are rejected with `401`. The MCP endpoint only accepts users signed in by the API keys plugin.

## What clients can reach

Every app collection is exposed by default, through shared tools (`getConfigInfo`, `findDocuments`, `createDocuments`, `updateDocument`, `deleteDocuments`, `getCollectionSchema` and more). Each call runs as the key's owner, with your collections' [access control](/access-control/overview): a key reaches nothing over MCP its owner can't reach over REST. Development's `?overrideAccess=true` is ignored.

FrogBot's own collections (chats, messages, API keys, connections, logs and the like) are never exposed.

To narrow a collection, turn off its built-in tools or reword them:

```ts
mcpPlugin({
  collections: {
    posts: {
      description: 'Published blog articles.',
      tools: { delete: false },
    },
  },
})
```

## Custom tools

`defineTool`, `defineCollectionTool`, `defineGlobalTool` and `definePrompt` come from `@frogbotai/plugin-mcp`. They infer the handler's `input` from the schema:

```ts
import { defineTool, mcpPlugin } from '@frogbotai/plugin-mcp'
import { z } from 'zod'

mcpPlugin({
  tools: {
    rollDice: defineTool({
      description: 'Roll a die.',
      input: z.object({ sides: z.number().int().min(2) }),
    }).handler(({ input }) => ({
      content: [{ type: 'text', text: String(1 + Math.floor(Math.random() * input.sides)) }],
    })),
  },
})
```

## Options

FrogBot handles authorization itself, so there's no option to replace it.

| Option | Type | Description |
| --- | --- | --- |
| `collections` | `object` | Map keyed by collection slug: `description`, `tools` (turn built-in tools off with `false`, reword them, or add custom ones) and `overrideResponse`. |
| `globals` | `object` | The same, keyed by global slug. |
| `tools` | `object` | Custom tools not tied to a collection, keyed by name. |
| `prompts` | `object` | Custom prompts, keyed by name. |
| `resources` | `object` | Custom resources, keyed by name. |
| `disabled` | `boolean` | Skip registering the endpoint. |
| `hooks.afterToolCall` | `function[]` | Rewrite tool responses after handlers return. |
| `mcp.maxRequestBodySize` | `number` | Largest request body in bytes; larger requests get `413`. Default 4 MiB. |
| `mcp.serverOptions.serverInfo` | `{ name?: string; version?: string }` | Server name and version reported to clients. |
| `mcp.serverOptions.options` | `object` | Options passed to the underlying MCP server. |
| `mcp.verboseLogs` | `boolean` | Log the plugin's info and debug messages. Default `false`. |

Custom tools, prompts and resources take an optional `access({ req, permissions })` that hides them from keys it returns `false` for. Without one, any signed-in key can use them.

SSE is not supported.
