The API keys plugin adds an `api-keys` collection, API-key authentication, and admin controls for creating and revoking keys. Each user can own multiple named keys, and each key can be revoked independently.

## Install

```bash
pnpm add @frogbotai/plugin-api-keys
```

## Configure

Add the plugin to your FrogBot config. By default, it associates keys with the auth-enabled `users` collection.

```ts
import { apiKeysPlugin } from '@frogbotai/plugin-api-keys'
import { buildConfig } from 'frogbot'

export default buildConfig({
  collections: [
    {
      slug: 'users',
      auth: true,
      fields: [],
    },
  ],
  plugins: [apiKeysPlugin()],
})
```

`frogbot dev` generates the admin import map before starting, so the API Keys collection and its key-creation controls appear on the first load. Create a named key there and copy the token when it is displayed. The plaintext token cannot be retrieved again.

Build and start-only workflows must run `frogbot generate:importmap` after adding the plugin. The blank template does this automatically during `prebuild`; add the same step to custom CI workflows that invoke `next build` directly. If the server console suggests `payload generate:importmap`, run `frogbot generate:importmap` instead, or restart `frogbot dev`.

## Authenticate requests

Send the key as a Bearer token or through the `X-API-Key` header:

```http
Authorization: Bearer fbt_...
```

```http
X-API-Key: fbt_...
```

The request authenticates as the user who owns the key. Revoked, malformed, and unknown keys do not authenticate.

When AI is configured, usage rows include an optional `apiKey` relationship identifying the key that authenticated the request. Cookie-authenticated requests omit it, and the relationship follows a custom `collectionSlug`.

## Configuration options

```ts
apiKeysPlugin({
  authCollection: 'accounts',
  collectionSlug: 'credentials',
  tokenPrefix: 'acme',
  headerNames: ['x-service-key'],
  collection: {
    admin: { group: 'Security' },
    fields: [{ name: 'environment', type: 'text' }],
  },
})
```

| Option | Default | Description |
| --- | --- | --- |
| `authCollection` | `users` | Auth-enabled collection whose users own the keys. |
| `collectionSlug` | `api-keys` | Slug for the generated API-key collection. |
| `tokenPrefix` | `fbt` | Prefix placed before generated key values. |
| `headerNames` | `['x-api-key']` | Additional request headers accepted for authentication. |
| `collection` | — | Collection overrides, including fields, access, hooks, endpoints, and admin configuration. |
| `defaults` | — | Inherited monthly budget, RPM, TPM, model, and blocking defaults. |
| `alerts` | — | Threshold webhook URL, headers, and threshold fractions. |

Collection overrides merge with the generated configuration and changes made by other plugins. The admin controls use the default admin design system without plugin-specific CSS, so your global admin styles continue to apply.

## Budgets and limits

```ts
apiKeysPlugin({
  defaults: {
    monthlyBudgetUSD: 25,
    rpm: 60,
    tpm: 100_000,
    models: ['openai/gpt-4o-mini'],
    budgetBehavior: 'block',
  },
  alerts: {
    webhookURL: process.env.BUDGET_WEBHOOK_URL!,
    thresholds: [0.8, 1],
  },
})
```

Key and user policy fields support `inherit`, `custom`, and `unlimited`. Add `budgets:manage` to administrator grants. The fields use the roles plugin's field adapter, so owning a key does not permit changing its caps.

Budget and RPM checks run before the operation. Model policy runs after the request model is parsed and can only narrow provider model allowlists. Completed usage settles TPM and spend for both the key and owner. A monthly Payload task resets spend and alert state.

Rate windows are process-local. Spend writes are serialized within one process, but Payload has no atomic increment operation, so multiple processes can lose concurrent updates. Streaming and TPM admission can exceed a limit by in-flight requests. These are governance limits, not billing ledgers.

Webhook deliveries include the subject, current spend, configured budget, and newly crossed thresholds. Each threshold fires once per monthly period. Failed deliveries are not retried automatically.

## Security behavior

- Plaintext keys are returned only when created.
- The collection stores a SHA-256 hash and a short display prefix, not the plaintext key.
- Collection reads are scoped to the authenticated owner by default.
- Keys are revoked individually without affecting the owning user's other authentication methods.
