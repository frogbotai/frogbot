The FrogBot Local API gives you the ability to execute the same operations that are available through REST and GraphQL within Node, directly on your server. Here, you don't need to deal with server latency or network speed whatsoever and can interact directly with your database.

<Tip>
  The Local API is incredibly powerful when used in React Server Components and
  other similar server-side contexts. With FrogBot, you don't have to leave your
  server to gather the data you need. It can be incredibly fast and is definitely
  a game changer.
</Tip>

Here are some common examples of how you can use the Local API:

- Fetching FrogBot data within React Server Components
- Seeding data via Node seed scripts that you write and maintain
- Opening custom Next.js route handlers which feature additional functionality but still rely on FrogBot
- Within [Access Control](/access-control/overview) and [Hooks](/hooks/overview)

## Accessing FrogBot

You can gain access to the currently running `frogbot` object via two ways:

#### Accessing from args or `req`

In most places within FrogBot itself, you can access `frogbot` directly from the arguments of [Hooks](/hooks/overview), [Access Control](/access-control/overview), [validation functions](/fields/overview#validation), and similar. This is the simplest way to access FrogBot in most cases. Most config functions take the `req` (Request) object, which has FrogBot bound to it (`req.frogbot`).

Example:

```ts
const afterChangeHook: CollectionAfterChangeHook = async ({
  req: { frogbot },
}) => {
  const posts = await frogbot.find({
    collection: 'posts',
  })
}
```

#### Importing it

If you want to import FrogBot in places where you don't have the option to access it from function arguments or `req`, you can import it and initialize it.

```ts
import { getFrogBot } from 'frogbot'
import config from '@frogbot-config'

const frogbot = await getFrogBot({ config })
```

`getFrogBot` accepts:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `config` | `FrogBotSanitizedConfig \| Promise<FrogBotSanitizedConfig>` | Required | The result of `buildConfig`, usually imported from `@frogbot-config`. |
| `disableDBConnect` | `boolean` | `false` | Starts FrogBot without connecting to the database. |
| `disableOnInit` | `boolean` | `false` | Skips the config's `onInit` callbacks, the `onInit` option, trigger reconciliation, and the development-only type and import map generation. |
| `onInit` | `(frogbot: FrogBot) => void \| Promise<void>` | — | Runs once after startup, before the config's `onInit` callbacks. |
| `startChannelGateway` | `boolean` | `true` | Opens gateway connections for channels that need one, such as Discord. Set `false` when [`frogbot channels:run`](/pieces/discord) holds the connection in another process. |

`getFrogBot` caches the instance. Later calls with the same config return it and ignore these options.

If you're working in Next.js' development mode, FrogBot will work with Hot Module Replacement (HMR), and as you make changes to your FrogBot Config, your usage of FrogBot will always be in sync with your changes. In production, `getFrogBot` simply disables all HMR functionality so you don't need to write your code any differently. We handle optimization for you in production mode.

If you are accessing FrogBot via function arguments or `req.frogbot`, HMR is automatically supported if you are using it within Next.js.

For more information about using FrogBot outside of Next.js, [click here](/local-api/outside-nextjs).

## Local options available

You can specify more options within the Local API vs. REST or GraphQL due to the server-only context that they are executed in.

| Local Option | Type | Default | Description |
| --- | --- | --- | --- |
| `collection` | `string` | Required | The slug of the collection to operate against. |
| `context` | `Record<string, unknown>` | — | [Context](/hooks/context), which will then be passed to `context` and `req.context`, which can be read by hooks. Useful if you want to pass additional information to the hooks which shouldn't be necessarily part of the document, for example a `triggerBeforeChange` option which can be read by the BeforeChange hook to determine if it should run or not. |
| `depth` | `number` | `defaultDepth` (`2`) | [Control auto-population](/queries/depth) of nested relationship and upload fields. Capped at `maxDepth`. |
| `disableErrors` | `boolean` | `false` | When set to `true`, errors will not be thrown. Instead, the `findByID` operation will return `null`, and the `find` operation will return an empty documents array. |
| `fallbackLocale` | `string` | The locale's `fallbackLocale`, then `defaultLocale`, when `localization.fallback` is on | Specify a [fallback locale](/configuration/localization) to use for any returned documents. Pass `'none'` to turn fallback off. |
| `locale` | `string` | `defaultLocale` | Specify [locale](/configuration/localization) for any returned documents. Pass `'all'` to return every locale. |
| `overrideAccess` | `boolean` | `true` | Skip access control. Set `false` to check access as `user` or `req.user`. |
| `populate` | `Record<string, unknown>` | — | Specify [populate](/queries/select#populate) to control which fields to include to the result from populated documents. |
| `req` | `FrogBotRequest` | Created for the call | The current request. Pass it to run in the same [transaction](#transactions) and give hooks the same `req.user` and `req.context`. |
| `select` | `SelectType` | — | Specify [select](/queries/select) to control which fields to include to the result. |
| `showHiddenFields` | `boolean` | `false` | Opt-in to receiving hidden fields. By default, they are hidden from returned documents in accordance to your config. |
| `user` | `object` | `req.user` | The user to check access against when `overrideAccess` is `false`. |

Every operation below accepts these options, except that auth operations and `restoreVersion` don't accept `select`.

Each operation below lists the options it adds.

## Transactions

When your database uses transactions you need to thread req through to all local operations. Postgres uses transactions and MongoDB uses transactions when you are using replica sets. Passing req without transactions is still recommended.

```ts
const post = await frogbot.find({
  collection: 'posts',
  req, // passing req is recommended
})
```

<Warning>
  By default, all access control checks are disabled in the Local API, but you
  can re-enable them if you'd like, as well as pass a specific user to run the
  operation with.
</Warning>

## Collections

The following Collection operations are available through the Local API:

### Create#collection-create

```ts
// The created Post document is returned
const post = await frogbot.create({
  collection: 'posts', // required
  data: {
    // required
    title: 'sure',
    description: 'maybe',
  },
  locale: 'en',
  fallbackLocale: 'none',
  user: dummyUserDoc,
  overrideAccess: true,
  showHiddenFields: false,

  // If creating verification-enabled auth doc,
  // you can optionally disable the email that is auto-sent
  disableVerificationEmail: true,

  // If your collection supports uploads, you can upload
  // a file directly through the Local API by providing
  // its full, absolute file path.
  filePath: path.resolve(__dirname, './path-to-image.jpg'),

  // Alternatively, you can directly pass a File,
  // if file is provided, filePath will be omitted
  file: uploadedFile,

  // If you want to create a document that is a duplicate of another document
  duplicateFromID: 'document-id-to-duplicate',
})
```

Accepts the [common options](#local-options-available) plus:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `collection` | `string` | Required | The collection slug. |
| `data` | `object` | Required | The document data. Typed from your generated types. |
| `draft` | `boolean` | `false` | Save as a draft. Required fields aren't validated unless `versions.drafts.validate` is on. Needs [drafts](/versions/drafts). |
| `disableVerificationEmail` | `boolean` | `false` | Skips the verification email when creating a user in a collection with `auth.verify`. |
| `file` | `{ data: Buffer; mimetype: string; name: string; size: number; tempFilePath?: string }` | — | Upload collections only. The file to store. Takes precedence over `filePath`. |
| `filePath` | `string` | — | Upload collections only. Absolute path of a file on disk to store. |
| `overwriteExistingFiles` | `boolean` | `false` | Upload collections only. When a file with the same name is already stored, replace it instead of saving the upload under a numbered name such as `photo-1.jpg`. |
| `duplicateFromID` | `string \| number` | — | Copies the data of this document, and its file in an upload collection, into the new document. Fields in `data` override the copied values. |
| `disableTransaction` | `boolean` | `false` | Set to `true` to skip the [database transaction](/database/transactions) the operation would otherwise open, so its write isn't rolled back if a later step fails. |

### Find#collection-find

```ts
// Result will be a paginated set of Posts.
// See /queries/pagination for more.
const result = await frogbot.find({
  collection: 'posts', // required
  depth: 2,
  page: 1,
  limit: 10,
  pagination: false, // If you want to disable pagination count, etc.
  where: {}, // pass a `where` query here
  sort: '-title',
  locale: 'en',
  fallbackLocale: 'none',
  user: dummyUser,
  overrideAccess: false,
  showHiddenFields: true,
})
```

Accepts the [common options](#local-options-available) plus:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `collection` | `string` | Required | The collection slug. |
| `where` | `Where` | — | A [query](/queries/overview) that limits the documents. |
| `sort` | `string \| string[]` | Collection `defaultSort` | [Sort](/queries/sort) by one or more fields. Prefix a field with `-` for descending order. |
| `limit` | `number` | `10` | Documents per page. `0` returns every document. See [Pagination](/queries/pagination). |
| `page` | `number` | `1` | The page to return. |
| `pagination` | `boolean` | `true` | Set `false` to return all matching documents and skip counting them. |
| `draft` | `boolean` | `false` | Return the latest drafts instead of published documents. Needs [drafts](/versions/drafts). |

<Note>
  `pagination`, `page`, and `limit` are three related properties [documented
  here](/queries/pagination).
</Note>

## Auth Operations

If a collection has [`Authentication`](/authentication/overview) enabled, additional Local API operations will be
available:

### Auth

```ts
// If you're using Next.js, you'll have to import headers from next/headers, like so:
// import { headers as nextHeaders } from 'next/headers'

// you'll also have to await headers inside your function, or component, like so:
// const headers = await nextHeaders()

// If you're using FrogBot outside of Next.js, you'll have to provide headers accordingly.

// result will be formatted as follows:
// {
//    permissions: { ... }, // object containing current user's permissions
//    user: { ... }, // currently logged in user's document
//    responseHeaders: { ... } // returned headers from the response
// }

const result = await frogbot.auth({ headers, canSetHeaders: false })
```

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `headers` | `Headers` | Required | The incoming request headers, read for the auth cookie, `Authorization` header, or API key. |
| `canSetHeaders` | `boolean` | `false` | Lets [auth strategies](/authentication/custom-strategies) return `responseHeaders`, such as a refreshed cookie. They come back as `result.responseHeaders`. |
| `req` | `FrogBotRequest` | — | The current request, passed to custom strategies. |

`auth` doesn't accept the common options.

### Login

```ts
// result will be formatted as follows:
// {
//   token: 'o38jf0q34jfij43f3f...', // JWT used for auth
//   user: { ... } // the user document that just logged in
//   exp: 1609619861 // the UNIX timestamp when the JWT will expire
// }

const result = await frogbot.login({
  collection: 'users', // required
  data: {
    // required
    email: 'dev@frogbot.com',
    password: 'rip',
  },
  req: req, // optional, pass a Request object to be provided to all hooks
  depth: 2,
  locale: 'en',
  fallbackLocale: 'none',
  overrideAccess: false,
  showHiddenFields: true,
})
```

Accepts the [common options](#local-options-available), except `select`, plus:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `collection` | `string` | Required | The collection slug. |
| `data` | `{ email: string; password: string }` | Required | The user's credentials. |

```ts
// Result will be formatted as follows:
// {
//   token: 'o38jf0q34jfij43f3f...', // JWT used for auth
//   user: { ... } // the user document that just logged in
// }
const result = await frogbot.resetPassword({
  collection: 'users', // required
  data: {
    // required
    password: req.body.password, // the new password to set
    token: 'afh3o2jf2p3f...', // the token generated from the forgotPassword operation
  },
  req: req, // optional, pass a Request object to be provided to all hooks
})
```

Accepts the [common options](#local-options-available), except `select`, plus:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `collection` | `string` | Required | The collection slug. |
| `data` | `{ password: string; token: string }` | Required | The new password and the token from `forgotPassword`. |

### Unlock

```ts
// Returned result will be a boolean representing success or failure
const result = await frogbot.unlock({
  collection: 'users', // required
  data: {
    // required
    email: 'dev@frogbot.com',
  },
  req: req, // optional, pass a Request object to be provided to all hooks
  overrideAccess: true,
})
```

Accepts the [common options](#local-options-available), except `select`, plus:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `collection` | `string` | Required | The collection slug. |
| `data` | `{ email: string }` | Required | The email address of the user to unlock. |

### Verify

```ts
// Returned result will be a boolean representing success or failure
const result = await frogbot.verifyEmail({

```

Accepts the [common options](#local-options-available), except `select`, plus:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `collection` | `string` | Required | The collection slug. |
| `token` | `string` | Required | The user's verification token. |

## TypeScript

Local API calls will automatically infer your [generated types](/typescript/generating-types).

Here is an example of usage:

```ts
// Properly inferred as `Post` type
const post = await frogbot.create({
  collection: 'posts',

  // Data will now be typed as Post and give you type hints
  data: {
    title: 'my title',
    description: 'my description',
  },
})
```
