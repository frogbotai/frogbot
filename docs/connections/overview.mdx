Connections let each user supply credentials for a piece. Configure the allowed linking methods in the root `connections` array; users manage their accounts in **Settings → Linked accounts**.

## Configure linking

The piece factory accepts your developer credential as `auth` and your OAuth app as `oauth`. See [factory options](/pieces/overview#factory-options).

- Factory `auth` is used when the caller has no connection for the piece.
- Factory `oauth` is available as `instance.oauth` for reuse.

A connection entry controls what users can link:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `piece` | `PieceInstance` | Required | The piece instance users link accounts for. Each piece can appear in only one entry. |
| `secret` | `true` | — | Allow users to enter a credential matching the piece's static `auth` schema. Only pieces with an `auth` schema accept it. |
| `oauth` | `true` | — | Allow users to authorize through the piece's OAuth recipe and your app. Only instances created with factory `oauth` accept it, or pieces that [run their own sign-in](#pieces-that-run-their-own-sign-in). |

Set `secret`, `oauth`, or both.

```ts
import { createGmail } from '@frogbotai/piece-gmail'
import { createGoogle } from '@frogbotai/piece-google'
import { createGoogleCalendar } from '@frogbotai/piece-google-calendar'
import { createGoogleDrive } from '@frogbotai/piece-google-drive'
import { createGoogleSheets } from '@frogbotai/piece-google-sheets'
import { createLinear } from '@frogbotai/piece-linear'
import type { CollectionConfig, ConnectionEntry } from 'frogbot'

export const google = createGoogle({
  oauth: {
    clientId: process.env.GOOGLE_CLIENT_ID!,
    clientSecret: process.env.GOOGLE_CLIENT_SECRET!
  }
})

export const googleSheets = createGoogleSheets({ oauth: google.oauth })
export const googleDrive = createGoogleDrive({ oauth: google.oauth })
export const googleCalendar = createGoogleCalendar({ oauth: google.oauth })
export const gmail = createGmail({ oauth: google.oauth })
export const linear = createLinear({
  auth: { apiKey: process.env.LINEAR_API_KEY! }
})

export const connections: ConnectionEntry[] = [
  { piece: googleSheets, oauth: true },
  { piece: googleDrive, oauth: true },
  { piece: googleCalendar, oauth: true },
  { piece: gmail, oauth: true },
  { piece: linear, secret: true }
]

export const Users: CollectionConfig = {
  slug: 'users',
  auth: { signIn: [google] },
  fields: []
}
```

Pass `connections` and `collections: [Users]` to your root config. Reuse these instances wherever you call their actions or assign them as agent tools. `google` supplies login identity; each product instance supplies its own actions and connection. Sharing `google.oauth` shares app credentials, not tokens or product access.

Sheets, Drive, and Calendar are native packages: install their `@frogbotai/piece-*` packages without an Activepieces runtime or provider plugin. Each supports factory `auth: { accessToken, refreshToken? }` and optional user-entered tokens through `secret: true`. The example enables only OAuth for these products. Configure each entry's methods explicitly; there is no shared `google` connection group or source/secret policy.

Every entry needs at least one enabled method. OAuth requires both a piece recipe and factory app credentials. Static linking requires a user-enterable schema. Enable both methods only when the piece supports both. Duplicate entries for the same piece are rejected, including instances with different custom slugs.

### Credential combinations

These seven combinations apply to credential-requiring pieces. OAuth combinations require factory `oauth`; static combinations require a supported form schema.

| Factory `auth` | Entry `secret` | Entry `oauth` | Behavior |
| --- | --- | --- | --- |
| Yes | — | — | Developer credential; omit the connection entry. |
| No | `true` | — | User-entered credential required. |
| No | — | `true` | User OAuth connection required. |
| Yes | `true` | — | User-entered credential, otherwise developer credential. |
| Yes | — | `true` | User OAuth credential, otherwise developer credential. |
| No | `true` | `true` | User chooses static credentials or OAuth; a connection is required. |
| Yes | `true` | `true` | User chooses either method, otherwise developer credential. |

“Otherwise” means **no connection row exists**. An existing row must resolve successfully. Invalid credentials, revoked or error states, missing scopes, and expiry that cannot be refreshed throw `ConnectionError` and block fallback.

## Run AI on users' keys

A piece can link an AI provider, so each user's linked account becomes the credential for their AI calls to that provider. [OpenAI](/pieces/openai) is one:

```ts
import { createOpenAI } from '@frogbotai/piece-openai'
import { buildConfig } from 'frogbot'

export default buildConfig({
  // secret, db, and collections omitted
  connections: [{ piece: createOpenAI(), oauth: true, secret: true }],
})
```

Listing the piece chooses its provider. FrogBot adds the provider to `ai.providers` when it isn't there, and the app boots without an app key.

Each call picks its key in this order:

1. The asking user's linked account.
2. The app key: `ai.providers.<name>.apiKey`, then the provider's environment variable.

With neither, the call fails with a setup error before any request. An existing account that can't be used fails the call and never falls back to the app key.

Startup fails when two pieces link the same provider, or when the provider is not a built-in API-key provider.

Before a key is saved, FrogBot checks it with the piece's model listing, and the model picker offers only the models the user's key can use. See [Link a key](/pieces/openai#link-a-key). With `oauth: true`, OpenAI users can instead sign in with ChatGPT and run on their plan; see [Continue with ChatGPT](/pieces/openai#continue-with-chatgpt).

## Link an account in Settings

1. Sign in to the admin panel and open **Settings → Linked accounts**.
2. Select **New Connection**, then choose an integration.
3. Authorize with OAuth or enter the requested credential fields. When both methods are enabled, choose **OAuth** or **Static credentials**. A piece can name its OAuth method, as OpenAI's **ChatGPT** does.
4. View the linked account and its status in the list. Use the row menu's **Disconnect** action to remove it.

The page is available at `/admin/settings/connections` with the default admin route. FrogBot adds it automatically when `connections` is non-empty, and the same view is the default view of the `connections` collection at `/admin/collections/connections`. Linking another account or switching methods replaces the existing connection for that owner and piece.

Each integration shows the logo URL from its piece's `admin.icon`, or a link icon when the piece has none or the image fails to load.

## Connection endpoints

The paths below use the default `routes.api: '/api'`. If you configure another API prefix, use it in requests and provider redirect URIs. Callback origins use `serverURL` when configured, otherwise the request origin.

| Method | Path | Result |
| --- | --- | --- |
| `GET` | `/api/connections` | List the caller's connection metadata using the collection API. |
| `POST` | `/api/connections/:piece` | Create or replace a static credential. |
| `GET` | `/api/connections/:piece/authorize` | Start OAuth linking for the signed-in user. |
| `GET` | `/api/connections/:piece/callback` | Exchange the authorization code, store the connection, and redirect. `404` for pieces that run their own sign-in. |
| `DELETE` | `/api/connections/:id` | Delete the caller's connection; returns `204`, or `404` when not found. |

`:piece` is the piece's built-in slug, such as `gmail` or `linear`, not a custom instance slug. Owners belong to the auth collection selected by `admin.user`.

Static writes, deletion, and OAuth authorization require authentication from that collection. Anonymous requests receive `401`, and users from another auth collection receive `403`.

### Submit a static credential

Send the raw JSON input expected by the piece's `auth` schema. Linear accepts an object with `apiKey`:

```bash
curl --request POST http://localhost:3000/api/connections/linear \
  --header "Authorization: Bearer $TOKEN" \
  --header "Content-Type: application/json" \
  --data '{"apiKey":"lin_api_..."}'
```

FrogBot validates the body against the schema, encrypts the original input, and returns metadata without the credential. Schema transformations run when the credential is resolved. Invalid JSON or schema input returns `400`; a piece without static linking enabled returns `404`. The authenticated user determines ownership.

Static forms support primitive values, nested objects, and arrays with supported item schemas. The piece's input schema defines the body shape; credentials do not use a common envelope.

### Configure OAuth redirects

For the example above, enable the Google Sheets, Drive, Calendar, and Gmail APIs and register these redirect URIs in the shared Google OAuth app:

```text
https://app.example.com/api/users/sign-in/google/callback
https://app.example.com/api/connections/google-sheets/callback
https://app.example.com/api/connections/google-drive/callback
https://app.example.com/api/connections/google-calendar/callback
https://app.example.com/api/connections/gmail/callback
```

| To | Start at |
| --- | --- |
| Link a product | `/api/connections/:piece/authorize`, with `:piece` replaced by `google-sheets`, `google-drive`, `google-calendar`, or `gmail`. |
| Log in | `/api/users/sign-in/google` |

- **Login** creates a FrogBot session without storing provider tokens or creating a connection.
- **Linking** requires a signed-in user and stores only that product's credential. By default it returns to the configured admin route plus `/settings/connections`. An optional `returnTo` selects a same-origin destination.

OAuth state is encrypted, browser-bound, single-use, and expires after ten minutes. It binds the piece, OAuth app, collection, callback, and link intent to the original owner. PKCE is used when the piece recipe enables it. The callback validates that intent before storing credentials.

### Pieces that run their own sign-in

Some providers' sign-ins can't use this redirect flow. OpenAI's ChatGPT sign-in, for example, must return to `127.0.0.1` and registers a client per user.

A piece recipe can define `authorize` instead of `authorizationUrl` and `tokenUrl`. The app then needs no client ID or secret, and the factory takes no `oauth`:

| Recipe field | Description |
| --- | --- |
| `authorize({ req, returnTo, save })` | Required. Starts a sign-in and returns the URL to send the browser to. `returnTo` is the absolute same-origin destination. The piece handles the provider's answer and calls `save({ tokens, account })`, which stores the connection for the user who started, as the callback route does. |
| `refresh({ tokens, req })` | Required. Returns renewed tokens; omitted fields keep their stored values. |
| `scopes` | The scope catalog. Required scopes must be among each connection's granted scopes, or its calls fail with code `scopes`. |
| `toAuth`, `auth` | Turn tokens into the piece's auth value, and the schema that checks it when it differs from the pasted-key schema. Both also work on redirect-flow recipes. |
| `revoke({ tokens, req })` | Optional, on any recipe. Ends the session at the provider when the user disconnects. A failure or a 10-second timeout is logged, and the connection is deleted anyway. |
| `label` | Optional, on any recipe. Names the method in Linked accounts, in place of **OAuth**, and on the **Continue with …** button. |

### Choose OAuth scopes

Each piece requests its default scopes plus the scopes its account lookup and token refresh need. Change the list with the factory's `scopes` option, beside `oauth`. A function receives the defaults and adds to them; an array replaces them:

```ts
const gmail = createGmail({
  oauth: google.oauth,
  scopes: ({ defaultScopes }) => [...defaultScopes, 'gmail.labels'],
})

const readOnlyGmail = createGmail({ oauth: google.oauth, scopes: ['gmail.readonly'] })
```

Scopes are short names from the piece's catalog, such as `gmail.labels` for `https://www.googleapis.com/auth/gmail.labels`.

- Your editor autocompletes them, and an unknown name fails to compile.
- Each OAuth piece exports its catalog as `<piece>Scopes`, for example `gmailScopes`, and its page lists the names.
- The required scopes are always requested, and no form removes them. For the Google products, these are `openid`, `userinfo.email`, and `userinfo.profile`.

`scopes` belongs to one instance. Sharing an OAuth app between pieces reuses only the app credentials, so a scope added to Gmail never reaches Drive or Google sign-in. Each piece still has its own consent flow, callback, and connection. Selecting fewer agent actions does not narrow OAuth scopes.

The Google product recipes add these scopes to the identity scopes:

| Product | Default product scopes under `https://www.googleapis.com/auth/` |
| --- | --- |
| Gmail | `gmail.send`, `gmail.readonly`, `gmail.compose` |
| Sheets | `spreadsheets`, `drive.readonly`, `drive` |
| Drive | `drive` |
| Calendar | `calendar.events`, `calendar.readonly` |

When you add a scope, accounts linked earlier lack it:

- Every action for that piece throws `ConnectionError` with code `scopes`, and `missingScopes` lists the provider strings.
- Settings → Linked accounts shows those rows as **needs re-link**.
- `frogbot.connections.authorizations()` lists the piece with its `authorizeUrl`.

Linking again asks for the full list and replaces the row.

## Resolve credentials on the server

Piece actions and `piece.client({ req })` resolve credentials automatically. Pass `req` to use the caller's linked account. For direct resolution and account management:

```ts
const auth = await frogbot.connections.resolve({ piece: gmail, req })
const accounts = await frogbot.connections.list({ req })

const gmailAccount = accounts.find(({ piece }) => piece === 'gmail')
if (gmailAccount) {
  await frogbot.connections.delete({ req, id: gmailAccount.id })
}
```

`resolve` accepts optional `scopes` to require specific grants. It returns the piece's parsed auth value, converting stored OAuth tokens through the recipe's `toAuth` when provided. `list` returns IDs, owner, piece, method, account, scopes, expiry, status, and timestamps, without plaintext or encrypted credentials.

- **Refresh.** Expired OAuth connections refresh lazily during resolution, using the recipe's `refresh` function or a refresh-token grant at its `tokenUrl`. Concurrent refreshes are serialized per owner and piece.
- **Failed refresh.** A failed refresh marks the connection `error` and throws. It never silently switches to factory `auth`. Reconnect to replace the failing credential.
- **Disconnect.** Disconnecting removes the row, which allows factory fallback again if configured. It revokes access at the provider only when the recipe defines `revoke`.

`ConnectionError.code` is `missing`, `revoked`, `expired`, `error`, or `scopes`. Scope errors include `missingScopes`. `frogbot.connections.authorizations({ pieces, req })` returns linking requirements keyed by piece, including enabled methods and an OAuth `authorizeUrl` when available.

## Storage and access

FrogBot creates its reserved `connections` collection only when the root list is non-empty. A unique `(owner, piece)` constraint permits one row per user and piece. Rows contain `method`, encrypted `credential`, account metadata, scopes, expiry, and status.

Static input and OAuth token sets are encrypted as JSON with AES-256-GCM using a key derived from the root `secret`. Keep that secret stable: changing it makes existing credentials unreadable. Factory `auth` stays in your configuration and is never copied into connection storage.

Collection reads are owner-scoped. Ordinary collection creates, updates, and deletes are disabled; use the connection endpoints. The credential field is hidden and denies field-level reads. Deleting a user also deletes every connection that user owns.

Connections authorize outbound calls to providers. [OAuth sign-in](/authentication/sign-in) establishes a FrogBot session, while [API keys](/plugins/api-keys) authenticate inbound requests to FrogBot.
