Collection Hooks are [Hooks](/hooks/overview) that run on Documents within a specific [Collection](/configuration/collections). They allow you to execute your own logic during specific events of the Document lifecycle.

To add Hooks to a Collection, use the `hooks` property in your [Collection Config](/configuration/collections):

```ts
import type { CollectionConfig } from 'frogbot'

export const CollectionWithHooks: CollectionConfig = {
  // ...
  hooks: {
    // ...
  },
}
```

<Note>
  You can also set hooks on the field-level to isolate hook logic to specific
  fields. [More details](/hooks/fields).
</Note>

## Config Options

All Collection Hooks accept an array of [synchronous or asynchronous functions](/hooks/overview#awaited-vs-non-blocking-hooks). Each Collection Hook receives specific arguments based on its own type, and has the ability to modify specific outputs.

```ts
import type { CollectionConfig } from 'frogbot';

export const CollectionWithHooks: CollectionConfig = {
  // ...
  hooks: {
    beforeOperation: [(args) => {...}],
    beforeValidate: [(args) => {...}],
    beforeDelete: [(args) => {...}],
    beforeChange: [(args) => {...}],
    beforeRead: [(args) => {...}],
    afterChange: [(args) => {...}],
    afterRead: [(args) => {...}],
    afterDelete: [(args) => {...}],
    afterOperation: [(args) => {...}],
    afterError: [(args) => {....}],

    // Auth-enabled Hooks
    beforeLogin: [(args) => {...}],
    afterLogin: [(args) => {...}],
    afterLogout: [(args) => {...}],
    afterRefresh: [(args) => {...}],
    afterMe: [(args) => {...}],
    afterForgotPassword: [(args) => {...}],
    refresh: [(args) => {...}],
    me: [(args) => {...}],
  },
}
```

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `beforeOperation` | `CollectionBeforeOperationHook[]` | `[]` | Runs before any operation. Can replace the operation's arguments. [More details](#beforeoperation). |
| `beforeValidate` | `CollectionBeforeValidateHook[]` | `[]` | Runs on `create` and `update` before validation. Can change the data. [More details](#beforevalidate). |
| `beforeChange` | `CollectionBeforeChangeHook[]` | `[]` | Runs on `create` and `update` after validation. Can change the data. [More details](#beforechange). |
| `afterChange` | `CollectionAfterChangeHook[]` | `[]` | Runs after a document is created or updated. Can change the returned document. [More details](#afterchange). |
| `beforeRead` | `CollectionBeforeReadHook[]` | `[]` | Runs before a document is returned, before field hooks. [More details](#beforeread). |
| `afterRead` | `CollectionAfterReadHook[]` | `[]` | Runs before a document is returned, after field hooks. [More details](#afterread). |
| `beforeDelete` | `CollectionBeforeDeleteHook[]` | `[]` | Runs before a document is deleted. [More details](#beforedelete). |
| `afterDelete` | `CollectionAfterDeleteHook[]` | `[]` | Runs after a document is deleted. [More details](#afterdelete). |
| `afterOperation` | `CollectionAfterOperationHook[]` | `[]` | Runs after any operation. Can replace the result. [More details](#afteroperation). |
| `afterError` | `CollectionAfterErrorHook[]` | `[]` | Runs when a request on this collection fails. [More details](#aftererror). |
| `beforeLogin` | `CollectionBeforeLoginHook[]` | `[]` | Auth collections only. Runs before a login succeeds. [More details](#beforelogin). |
| `afterLogin` | `CollectionAfterLoginHook[]` | `[]` | Auth collections only. Runs after a login succeeds. [More details](#afterlogin). |
| `afterLogout` | `CollectionAfterLogoutHook[]` | `[]` | Auth collections only. Runs after a logout. [More details](#afterlogout). |
| `afterMe` | `CollectionAfterMeHook[]` | `[]` | Auth collections only. Runs after the `me` operation. [More details](#afterme). |
| `afterRefresh` | `CollectionAfterRefreshHook[]` | `[]` | Auth collections only. Runs after a token is refreshed. [More details](#afterrefresh). |
| `afterForgotPassword` | `CollectionAfterForgotPasswordHook[]` | `[]` | Auth collections only. Runs after a forgot password request succeeds. [More details](#afterforgotpassword). |
| `refresh` | `CollectionRefreshHook[]` | `[]` | Auth collections only. Can replace the `refresh` operation. [More details](#refresh). |
| `me` | `CollectionMeHook[]` | `[]` | Auth collections only. Can replace the `me` operation. [More details](#me). |

### beforeOperation

The `beforeOperation` hook can be used to modify the arguments that operations accept or execute side-effects that run before an operation begins.

```ts
import type { CollectionBeforeOperationHook } from 'frogbot'

const beforeOperationHook: CollectionBeforeOperationHook = async ({
  args,
  operation,
  req,
}) => {
  return args // return modified operation arguments as necessary
}
```

The following arguments are provided to the `beforeOperation` hook:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `collection` | `SanitizedCollectionConfig` | Always set | The [Collection](/configuration/collections) in which this Hook is running against. |
| `context` | `RequestContext` | Always set | Custom context passed between Hooks. [More details](/hooks/context). |
| `req` | `FrogBotRequest` | Always set | The request, with the signed-in `user` and `req.frogbot`. For [Local API](/local-api/overview) operations without a `req`, FrogBot creates one. |
| `operation` | `string` | Always set | The operation about to run, such as `'create'`, `'find'`, `'findByID'`, `'update'`, `'updateByID'`, `'delete'`, `'deleteByID'`, `'count'`, `'login'`, or `'forgotPassword'`. Some operations also report the older names `'read'` and `'readDistinct'`. |
| `args` | `object` | Always set | The arguments the operation was called with. Return a changed copy to replace them. |
| `overrideAccess` | `boolean` | — | Whether the operation skips access control. |

### beforeValidate

Runs during the `create` and `update` operations. This hook allows you to add or format data before the incoming data is validated server-side.

Please do note that this does not run before client-side validation. If you render a custom field component in your front-end and provide it with a `validate` function, the order that validations will run in is:

1. `validate` runs on the client
2. if successful, `beforeValidate` runs on the server
3. `validate` runs on the server

```ts
import type { CollectionBeforeValidateHook } from 'frogbot'
import type { Post } from '@/frogbot-types'

const beforeValidateHook: CollectionBeforeValidateHook<Post> = async ({
  data, // Typed as Partial<Post>
}) => {
  return data
}
```

The following arguments are provided to the `beforeValidate` hook:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `collection` | `SanitizedCollectionConfig` | Always set | The [Collection](/configuration/collections) in which this Hook is running against. |
| `context` | `RequestContext` | Always set | Custom context passed between Hooks. [More details](/hooks/context). |
| `data` | `object` | — | The incoming data passed through the operation. |
| `operation` | `'create' \| 'update'` | Always set | The name of the operation that this hook is running within. |
| `originalDoc` | `object` | — | The full document before changes are applied. Present on updates; undefined on creates. Use this to read the document id and any unchanged fields. |
| `req` | `FrogBotRequest` | Always set | The request, with the signed-in `user` and `req.frogbot`. For [Local API](/local-api/overview) operations without a `req`, FrogBot creates one. |

**Why isn't id in data?**

`data` only represents the delta you're saving. Read `originalDoc.id` during updates, and prefer `afterChange` if you need the `id` during creates

<Warning>
  On update operations, data contains only the fields being changed. It may omit
  id and any unchanged fields. Use originalDoc to read existing values. On
  create, data is the new submission and the document id is not yet available at
  this stage.
</Warning>

### beforeChange

Immediately before validation, beforeChange hooks will run during create and update operations. At this stage, the data should be treated as unvalidated user input. There is no guarantee that required fields exist or that fields are in the correct format. As such, using this data for side effects requires manual validation. You can optionally modify the shape of the data to be saved.

```ts
import type { CollectionBeforeChangeHook } from 'frogbot'

export const requireTitleOnUpdate: CollectionBeforeChangeHook = async ({
  data, // Partial<T> — changed fields only
  originalDoc, // Full doc before changes (defined on update)
  operation, // 'create' | 'update'
}) => {
  // Need the id? Don't expect it in `data`.
  const id = operation === 'update' ? originalDoc.id : undefined

  // Example: enforce that title cannot be cleared on update
  if (operation === 'update' && 'title' in (data ?? {}) && !data.title) {
    throw new Error(`Document ${id} must have a title`)
  }

  return data
}
```

The following arguments are provided to the `beforeChange` hook:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `collection` | `SanitizedCollectionConfig` | Always set | The [Collection](/configuration/collections) in which this Hook is running against. |
| `context` | `RequestContext` | Always set | Custom context passed between Hooks. [More details](/hooks/context). |
| `data` | `object` | Always set | The incoming data passed through the operation. |
| `operation` | `'create' \| 'update'` | Always set | The name of the operation that this hook is running within. |
| `originalDoc` | `object` | — | The full document before changes are applied. Present on updates; undefined on creates. Use this to read the document id and any unchanged fields. |
| `req` | `FrogBotRequest` | Always set | The request, with the signed-in `user` and `req.frogbot`. For [Local API](/local-api/overview) operations without a `req`, FrogBot creates one. |

**Why isn't id in data?**

`data` only represents the delta you're saving. Read `originalDoc.id` during updates, and prefer `afterChange` if you need the `id` during creates

<Warning>
  On update operations, data contains only the fields being changed. It may omit
  id and any unchanged fields. Use originalDoc to read existing values. On
  create, data is the new submission and the document id is not yet available at
  this stage.
</Warning>

### afterChange

After a document is created or updated, the `afterChange` hook runs. This hook is helpful for recalculating statistics, syncing user profile changes to a CRM, and more.

```ts
import type { CollectionAfterChangeHook } from 'frogbot'
import type { Post } from '@/frogbot-types'

const afterChangeHook: CollectionAfterChangeHook<Post> = async ({
  doc, // Typed as Post
  previousDoc, // Typed as Post
}) => {
  return doc
}
```

The following arguments are provided to the `afterChange` hook:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `collection` | `SanitizedCollectionConfig` | Always set | The [Collection](/configuration/collections) in which this Hook is running against. |
| `context` | `RequestContext` | Always set | Custom context passed between Hooks. [More details](/hooks/context). |
| `data` | `object` | Always set | The incoming data passed through the operation. |
| `doc` | `object` | Always set | The resulting Document after changes are applied. |
| `operation` | `'create' \| 'update'` | Always set | The name of the operation that this hook is running within. |
| `previousDoc` | `object` | Always set | The Document before changes were applied. |
| `overrideAccess` | `boolean` | — | Whether the operation skips access control. |
| `req` | `FrogBotRequest` | Always set | The request, with the signed-in `user` and `req.frogbot`. For [Local API](/local-api/overview) operations without a `req`, FrogBot creates one. |

### beforeRead

Runs before `find` and `findByID` operations are transformed for output by `afterRead`. This hook fires before hidden fields are removed and before localized fields are flattened into the requested locale. Using this Hook will provide you with all locales and all hidden fields via the `doc` argument.

```ts
import type { CollectionBeforeReadHook } from 'frogbot'
import type { Post } from '@/frogbot-types'

const beforeReadHook: CollectionBeforeReadHook<Post> = async ({
  doc, // Typed as Post
}) => {
  return doc
}
```

The following arguments are provided to the `beforeRead` hook:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `collection` | `SanitizedCollectionConfig` | Always set | The [Collection](/configuration/collections) in which this Hook is running against. |
| `context` | `RequestContext` | Always set | Custom context passed between Hooks. [More details](/hooks/context). |
| `doc` | `object` | Always set | The Document as read from the database, before field hooks and access control run. |
| `query` | `Record<string, any>` | Always set | The [Query](/queries/overview) of the request. |
| `overrideAccess` | `boolean` | — | Whether the operation skips access control. |
| `req` | `FrogBotRequest` | Always set | The request, with the signed-in `user` and `req.frogbot`. For [Local API](/local-api/overview) operations without a `req`, FrogBot creates one. |

### afterRead

| `doc` | `object` | Always set | The Document after field hooks and access control run. |

### afterOperation

The `afterOperation` hook can be used to modify the result of operations or execute side-effects that run after an operation has completed.

```ts
import type { CollectionAfterOperationHook } from 'frogbot'

const afterOperationHook: CollectionAfterOperationHook = async ({ result }) => {
  return result
}
```

The following arguments are provided to the `afterOperation` hook:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `args` | `object` | Always set | The arguments passed into the operation. |
| `collection` | `SanitizedCollectionConfig` | Always set | The [Collection](/configuration/collections) in which this Hook is running against. |
| `req` | `FrogBotRequest` | Always set | The request, with the signed-in `user` and `req.frogbot`. For [Local API](/local-api/overview) operations without a `req`, FrogBot creates one. |
| `operation` | `string` | Always set | The name of the operation that this hook is running within, with the same values as `beforeOperation`. |
| `result` | `unknown` | Always set | The result of the operation, before modifications. Return a value to replace it. |
| `overrideAccess` | `boolean` | — | Whether the operation skips access control. |

### afterError

The `afterError` Hook is triggered when an error occurs in the FrogBot application. This can be useful for logging errors to a third-party service, sending an email to the development team, logging the error to Sentry or DataDog, etc. The output can be used to transform the result object / status code.

```ts
import type { CollectionAfterErrorHook } from 'frogbot';

const afterErrorHook: CollectionAfterErrorHook = async ({
  error,
  req,
  collection,
}) => {...}
```

The following arguments are provided to the `afterError` Hook:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `error` | `Error` | Always set | The error that occurred. |
| `context` | `RequestContext` | Always set | Custom context passed between Hooks. [More details](/hooks/context). |
| `graphqlResult` | `GraphQLFormattedError` | — | The GraphQL result object, available if the hook is executed within a GraphQL context. |
| `req` | `FrogBotRequest` | Always set | The `FrogBotRequest` object that extends [Web Request](https://developer.mozilla.org/en-US/docs/Web/API/Request). Contains currently authenticated `user` and the Local API instance `frogbot`. |
| `collection` | `SanitizedCollectionConfig` | Always set | The [Collection](/configuration/collections) in which this Hook is running against. |
| `result` | `ErrorResult` | — | The formatted error result object, available if the hook is executed from a REST context. |

## TypeScript

FrogBot exports a type for each Collection hook which can be accessed as follows:

```ts
import type {
  CollectionBeforeOperationHook,
  CollectionBeforeValidateHook,
  CollectionBeforeChangeHook,
  CollectionAfterChangeHook,
  CollectionAfterReadHook,
  CollectionBeforeReadHook,
  CollectionBeforeDeleteHook,
  CollectionAfterDeleteHook,
  CollectionBeforeLoginHook,
  CollectionAfterLoginHook,
  CollectionAfterLogoutHook,
  CollectionAfterRefreshHook,
  CollectionAfterMeHook,
  CollectionAfterForgotPasswordHook,
  CollectionRefreshHook,
  CollectionMeHook,
} from 'frogbot'
```

You can also pass a generic type to each hook for strongly-typed `doc`, `previousDoc`, and `data` properties:

```ts
import type { CollectionAfterChangeHook } from 'frogbot'
import type { Post } from '@/frogbot-types'

const afterChangeHook: CollectionAfterChangeHook<Post> = async ({
  doc, // Typed as Post
  previousDoc, // Typed as Post
}) => {
  return doc
}
```
