A Collection is a group of records, called Documents, that all share a common schema. Each Document in a Collection is stored in the [Database](/database/overview) based on the [fields](/fields/overview) that you define, and automatically generates a [Local API](/local-api/overview), [REST API](/rest-api/overview), and [GraphQL API](/graphql/overview) used to manage your Documents. Collections can also enable [Authentication](/authentication/overview), [Uploads](/upload/overview), and more.

To define a Collection Config, use the `collections` property in your [FrogBot Config](/configuration/overview):

```ts
import { buildConfig } from 'frogbot'
import { Users } from './collections/Users'
import { Projects } from './collections/Projects'
import { Files } from './collections/Files'
import { Chats } from './collections/Chats'
import { Messages } from './collections/Messages'

export default buildConfig({
  collections: [Users, Projects, Files, Chats, Messages],
})
```

<Tip>
  FrogBot does not support Globals. Model singleton content as a Collection and enforce the single-document constraint in your application.
</Tip>

## Organize collection files

Give each collection its own TitleCase file with a named export, such as `export const Posts` in `src/collections/Posts.ts`, and import it into your config by its own path. Adding a collection means creating its file and adding it to `collections`; there is no `index.ts` to update.

When a collection gains hooks, access rules, or endpoints, turn its file into a folder with the same name:

```text
src/
├── collections/
│   ├── Posts.ts
│   └── Users/
│       ├── access/
│       │   └── isAdminOrSelf.ts
│       ├── endpoints/
│       │   └── exportUsers.ts
│       ├── hooks/
│       │   └── setLastLogin.ts
│       └── index.ts
└── frogbot.config.ts
```

Move `Users.ts` to `Users/index.ts`, then put its helpers in subfolders beside it. `import { Users } from './collections/Users'` resolves to either form, so the config doesn't change.

Move the file rather than copying it. If `Users.ts` and `Users/index.ts` both exist, `./collections/Users` resolves to `Users.ts` and the folder is ignored.

Match the casing of each import to its file name. `./collections/users` finds `Users.ts` on macOS but fails with "Cannot find module" on Linux, for example in Docker or a deployment.

## FrogBot collection model

Collections you configure remain ordinary FrogBot collections. Agents need chat and message stores, and pieces that create files need a files collection. You can adopt those roles into collections you own; FrogBot adds a files collection only when you mark one with `file: true`.

### Role markers

FrogBot identifies managed collections by role, not by a required slug. Mark a collection with `chat: true`, `message: true`, or `file: true`; FrogBot keeps its slug and merges in the required configuration.

```ts
import type { CollectionConfig } from 'frogbot'

export const Conversations: CollectionConfig = {
  slug: 'conversations',
  chat: true,
  fields: [{ name: 'channel', type: 'text' }]
}

export const Turns: CollectionConfig = {
  slug: 'turns',
  message: true,
  fields: []
}
```

Mark at most one collection per role. With no marker, agents cause FrogBot to inject defaults at `chats` and `messages`. An unmarked collection already using either default slug causes a configuration error rather than implicit adoption.

### Field contribution per role

Your compatible field, access, admin, and option values win during the merge. Missing base fields are appended and hooks are combined.

| Role marker | FrogBot contributes |
| --- | --- |
| `chat: true` | `title`, owner `user` relationship, agent slug, and `lastMessageAt` |
| `message: true` | Text `id`, chat relationship, role, `UIMessage.parts`, metadata, and usage |
| `file: true` | Uploads, folders, soft deletion, admin defaults, and authenticated access |

FrogBot rejects incompatible base field types. `chats.user` and `messages.id`, `messages.chat`, and `messages.parts` are reserved and cannot be redefined.

### Default collections

The default collections use soft deletion, appear under **Collections** in the admin panel, and scope access to the authenticated chat owner. The message ID is the AI SDK UI message ID, allowing an interrupted assistant message to be continued in place across database adapters.

The chat's `user` relationship resolves as follows:

- No auth collection: FrogBot's default `users` collection.
- One auth collection: that collection, regardless of slug.
- Multiple auth collections: the collection selected by `admin.user`.

See [Chat persistence](/chat/overview) for request behavior and durability guarantees.

## Collection config options

The following options are available on any `CollectionConfig`. FrogBot adds `chat`, `message`, and `file` to the built-in set; every other option below is part of the FrogBot configuration API. Configure [connections](/connections/overview) in the root config.

It's best practice to write Collections in separate files and import them into the root config.

Here is a minimal example:

```ts
import type { CollectionConfig } from 'frogbot'

export const Posts: CollectionConfig = {
  slug: 'posts',
  fields: [
    {
      name: 'title',
      type: 'text',
    },
  ],
}
```

<Tip>
  **Reminder:** For more complex examples, see the
  [Templates](https://github.com/frogbotcms/frogbot/tree/main/templates) and
  [Examples](https://github.com/frogbotcms/frogbot/tree/main/examples)
  directories in the FrogBot repository.
</Tip>

The following options are available:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `slug` | `string` | Required | Unique, URL-friendly identifier for the collection. `agents` is reserved. |
| `fields` | `Field[]` | Required | Fields that make up each document. [More details](/fields/overview). |
| `chat` | `boolean` | `false` | **FrogBot** — adopts this collection as the chat store. At most one collection may be marked. [More details](#role-markers). |
| `message` | `boolean` | `false` | **FrogBot** — adopts this collection as the message store. At most one collection may be marked. [More details](#role-markers). |
| `file` | `boolean` | `false` | **FrogBot** — adopts this collection as the files store. At most one collection may be marked. [More details](/upload/files). |
| `usageLog` | `boolean` | `false` | **FrogBot** — adopts this collection as the AI usage log when `ai` is configured. At most one collection may be marked. Without a marker, FrogBot adds a `usage-logs` collection. |
| `admin` | `CollectionAdminConfig` | — | Admin panel options. [More details](#admin-options). |
| `access` | `CollectionAccess` | Signed-in users only | Access control functions for each operation. [More details](/access-control/collections). |
| `auth` | `boolean \| AuthConfig` | `false` | Set to `true` for default authentication or pass an auth config object. Use `signIn` to add [OAuth login methods](/authentication/sign-in). [More details](/authentication/overview#config-options). |
| `custom` | `Record<string, any>` | `{}` | Extension point for your own data, such as plugin settings. Server only. |
| `dbName` | `string \| (({ tableName }) => string)` | Derived from `slug` | Table or collection name in the database. Changing it on existing data needs a migration. |
| `defaultPopulate` | `SelectType` | — | Fields selected when this collection is populated from another document. [More details](/queries/select#defaultpopulate-collection-config-property). |
| `defaultSort` | `Sort` | — | Sort used by `find` and bulk `update` when the request doesn't set `sort`. Prefix a field with `-` for descending order. |
| `disableBulkDelete` | `boolean` | `false` | Disables bulk delete in the admin panel and the REST API. |
| `disableBulkEdit` | `boolean` | `false` | Disables bulk edit in the admin panel and the REST API. |
| `disableDuplicate` | `boolean` | `false` | Hides the **Duplicate** button and makes `duplicate` fail in every API. |
| `enableQueryPresets` | `boolean` | `false` | Lets users save and share list filters, columns, and sorts for this collection. Configure access with the root [`queryPresets`](/configuration/overview#query-presets). |
| `endpoints` | `Endpoint[]` | — | Custom REST routes under this collection's path. [More details](/rest-api/overview#custom-endpoints). |
| `folders` | `boolean \| { browseByFolder?: boolean }` | `false` | Adds a folder field and folder navigation to this collection. `browseByFolder` (default `true`) includes it in the Browse by folder view. See [root folder options](/configuration/overview#folders). |
| `forceSelect` | `SelectType` | — | Fields always selected, whatever `select` a request passes. Use it for fields that hooks or access control read. [More details](/queries/select#always-selected-fields). |
| `graphQL` | `false \| CollectionGraphQL` | — | GraphQL names, or `false` to leave this collection out of the schema. [More details](#graphql). |
| `hooks` | `CollectionHooks` | — | Lifecycle hooks. [More details](/hooks/collections). |
| `indexes` | `CompoundIndex[]` | `[]` | Compound indexes on two or more fields, to speed up queries or enforce uniqueness. [More details](/database/indexes). |
| `labels` | `{ singular?: string \| LabelFunction; plural?: string \| LabelFunction }` | Derived from `slug` | Labels used for this collection throughout FrogBot. Each can be a string, a localized object, or a function. |
| `lockDocuments` | `false \| { duration: number }` | Enabled, `300` seconds | Locks a document while someone edits it. `duration` sets how long, in seconds, a lock lasts without activity. `false` turns locking off. |
| `orderable` | `boolean` | `false` | Lets documents be reordered by drag and drop. [More details](#orderable). |
| `search` | `Record<string, SearchIndexConfig>` | — | Named search indexes over this collection. [More details](/search/overview#configure-indexes). |
| `timestamps` | `boolean` | `true` | Adds `createdAt` and `updatedAt`. Set `false` to leave them out. |
| `trash` | `boolean` | `false` | Turns on soft deletes. [More details](/trash/overview). |
| `typescript` | `{ interface?: string }` | Derived from `slug` | Name of the generated TypeScript interface. |
| `upload` | `boolean \| UploadConfig` | `false` | Turns on file uploads. [More details](/upload/overview). |
| `versions` | `boolean \| VersionsConfig` | `false` | Turns on versions and drafts. [More details](/versions/overview#collection-config). |
| `_sanitized` | `boolean` | — | Internal. Set during sanitization; don't set it yourself. |

### Fields

[Fields](/fields/overview) define the schema of the Documents within a Collection.

### Access Control

[Collection Access Control](/access-control/collections) determines what a user can and cannot do with any given Document within a Collection. To learn more, go to the [Access Control](/access-control/overview) documentation.

### Hooks

[Collection Hooks](/hooks/collections) allow you to tie into the lifecycle of your Documents so you can execute your own logic during specific events. To learn more, go to the [Hooks](/hooks/overview) documentation.

### Orderable

When `orderable` is enabled, FrogBot uses [fractional indexing](https://observablehq.com/@dgreensp/implementing-fractional-indexing) to efficiently manage document order. When enabled on collections, this allows you to manually drag and drop documents in the Admin Panel to reorder them, as well as programmatically set the order of documents via the Local API, REST API, or GraphQL API.

Orderable can also be added to [join fields](/fields/join).

## Admin Options

The behavior of Collections within the Admin Panel can be customized to fit the needs of your application. This includes grouping or hiding their navigation links, adding custom components, selecting which fields to display in the List View, and more.

To configure Admin Options for Collections, use the `admin` property in your Collection Config:

```ts
import type { CollectionConfig } from 'frogbot'

export const MyCollection: CollectionConfig = {
  // ...
  admin: {
    // ...
  },
}
```

The following options are available:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `components` | `CollectionAdminComponents` | — | Swap in your own React components for this collection. [More details](#custom-components). |
| `custom` | `Record<string, any>` | `{}` | Your own data, sent to the admin panel's client config. |
| `description` | `string \| Record<string, string> \| (({ t }) => string)` | — | Text shown below the collection label in the List View. It's also used as the JSDoc comment on the generated type. Use `components.Description` to render a component instead. |
| `disableCopyToLocale` | `boolean` | `false` | Hides the **Copy to Locale** button in the Edit View. Only applies when localization is on. |
| `enableListViewSelectAPI` | `boolean` | `false` | Experimental. Makes the List View select only its active columns. [More details](#list-view-select-api). |
| `enableRichTextLink` | `boolean` | `true` | Lets Rich Text links point to documents in this collection. |
| `enableRichTextRelationship` | `boolean` | `true` | Lets Rich Text relationship blocks reference documents in this collection. |
| `formatDocURL` | `(args) => string \| null` | Default edit URL | Customizes document links in the List View. [More details](#format-document-urls). |
| `group` | `string \| Record<string, string> \| false \| null` | Collections group | Text or localized object used to group the navigation link. `null` makes it a top-level link; `false` hides the link but keeps its routes. |
| `groupBy` | `boolean` | See description | Beta. Lets the List View group documents by a field. FrogBot turns it on when `views` has a list view whose `groupBy` isn't `false`, or any board view. |
| `hidden` | `boolean \| (({ user }) => boolean)` | `false` | Leaves this collection out of navigation and admin routes. A function receives the current user. |
| `hideAPIURL` | `boolean` | `false` | Hides the API URL in the Edit View. |
| `icon` | `AdminIcon` | `'people'` for auth collections | Built-in kebab-case icon name or component path for the navigation link. See [Collection icons](/admin/admin-navigation#collection-icons-and-placement). |
| `livePreview` | `LivePreviewConfig` | — | Live Preview for this collection. See [Live Preview](/live-preview/overview). |
| `meta` | `MetaConfig` | — | Page metadata for this collection's admin pages. |
| `preview` | `(doc, { locale, req, token }) => string \| null \| Promise<string \| null>` | — | Builds a preview URL that points to your app. `req` is a `FrogBotRequest` with `req.frogbot`. |
| `useAsTitle` | `string` | `'id'` | Top-level field used as the document title throughout the admin panel. |
| `views` | `CollectionView[]` | One list view | Collection views, such as list, board, calendar, and custom layouts. [More details](#collection-views). |

<Warning>
  **Note:** If you set `useAsTitle` to a relationship or join field, it will use
  only the ID of the related document(s) as the title. To display a specific
  field (i.e. title) from the related document instead, create a virtual field
  that extracts the desired data, and set `useAsTitle` to that virtual field.
</Warning>

### Collection Views

`admin.views` accepts `CollectionView[]`. `CollectionView` is the exported union `ListView | BoardView | CalendarView | CustomView`.

The array order controls the switcher and first-view fallback. A collection can have at most one list view, and it must be first. Omit `views` to use one default list view without a switcher.

```ts
import type { CollectionConfig } from 'frogbot'

export const Projects: CollectionConfig = {
  slug: 'projects',
  admin: {
    views: [
      {
        type: 'list',
        slug: 'active',
        label: 'Active',
        defaultFields: ['title', 'status'],
        filter: { archived: { equals: false } },
        components: {
          beforeTable: ['/components/ProjectSummary#ProjectSummary'],
        },
      },
      {
        type: 'custom',
        slug: 'report',
        label: 'Report',
        component: '/components/ProjectReport#ProjectReport',
      },
    ],
  },
  fields: [],
}
```

#### Shared view properties

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `slug` | `string` | No; defaults to `type` | Unique route and saved-preference key after normalization to lowercase kebab case. Duplicate or empty normalized slugs produce a configuration error. The first view uses the collection's root route. |
| `label` | `string` | No; defaults to the capitalized `type` | Label displayed in the view switcher. |
| `defaultFields` | `string[]` | No | Ordered field dot paths initially displayed as list columns or board card fields. Users can change list columns through normal list controls. |
| `filter` | `Where \| ({ req }) => Where \| Promise<Where>` | No | Invisible base filter applied to the view. The function receives the current `FrogBotRequest`. |
| `defaultSort` | `Sort` (`string \| string[]`) | No | Initial field sort or ordered list of sorts. Prefix a field with `-` for descending order. |
| `searchableFields` | `string[]` | No | Adds field dot paths to the normal search behavior. The collection's `useAsTitle` field remains included; this option does not replace it. |
| `pagination` | `ViewPagination` | No | Configures query limits. Defaults depend on the view type. |
| `access` | `({ req }) => boolean \| Promise<boolean>` | No; defaults to collection access | Controls whether the current user can open the view. It does not replace collection operation access. |
| `components` | View-specific components | No | Supplies shared shell slots and slots for the selected view type. |

#### ViewPagination

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `defaultLimit` | `number` | No; list uses FrogBot list defaults, board defaults to `50` | List documents per page or board documents fetched per column. Board columns lazy-load additional pages and virtualize rendered cards. |
| `limits` | `number[]` | No; list uses FrogBot list defaults | Page-size choices shown by list controls. This property does not change board loading or display controls. |

#### ViewComponents

These shell slots are shared by list, board, calendar, and custom views. Each value uses a `FrogBotComponent` import path; array slots render in declaration order.

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `actions` | `FrogBotComponent[]` | No; `[]` | Adds actions to the view's action area. |
| `menuItems` | `FrogBotComponent[]` | No; `[]` | Adds entries to the view menu. |
| `beforeView` | `FrogBotComponent[]` | No; `[]` | Renders inside the collection shell before the view body. |
| `afterView` | `FrogBotComponent[]` | No; `[]` | Renders inside the collection shell after the view body. |

#### ListView

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `type` | `'list'` | Yes | Selects the table-based list view. |
| `groupBy` | `boolean` | No; `true` | Shows the **Group by** control in the list controls. Set `false` to hide it. |
| `components` | `ViewComponents & ListViewComponents` | No | Adds shared shell slots and list table slots. |

**ListView components**

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `beforeTable` | `FrogBotComponent[]` | No; `[]` | Renders after list controls and immediately before the table. |
| `afterTable` | `FrogBotComponent[]` | No; `[]` | Renders immediately after the table. |

#### BoardView

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `type` | `'board'` | Yes | Selects the column-based board view. |
| `groupBy` | `string` | No | Dot path to the select or single relationship field used for columns. Documents without a value appear in **Uncategorized**. |
| `cover` | `string` | No | Dot path to an upload field rendered as each card's cover image. |
| `components` | `ViewComponents & BoardComponents` | No | Adds shared shell slots and board-specific components. |

**Board components**

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `beforeColumns` | `FrogBotComponent[]` | No; `[]` | Renders before the board columns. |
| `afterColumns` | `FrogBotComponent[]` | No; `[]` | Renders after the board columns. |
| `ColumnHeader` | `FrogBotComponent` | No; built-in header | Replaces each column header. See [Column headers](/admin/collection-board#column-headers) for its props. |
| `Card` | `FrogBotComponent` | No; built-in card | Replaces each board card and receives the document as its `row` prop. |

#### CalendarView

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `type` | `'calendar'` | Yes | Selects the date-based calendar view. |
| `start` | `string` | Yes | Dot path to the date field used as each event's start. |
| `end` | `string` | No | Dot path to the date field used as each event's end. Without it, events use the start as their end. |
| `color` | `string` | No | Dot path to a select or radio field whose value colors each event. |
| `modes` | `CalendarMode[]` | No; `['month', 'week', 'day']` | Available modes in display order. The first mode is the default. |
| `snap` | `number` | No | Minute interval used when creating, moving, or resizing events. |
| `components` | `ViewComponents & CalendarComponents` | No | Adds shared shell slots and calendar-specific components. |

**Calendar components**

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `beforeCalendar` | `FrogBotComponent[]` | No; `[]` | Renders before the calendar. |
| `afterCalendar` | `FrogBotComponent[]` | No; `[]` | Renders after the calendar. |
| `Event` | `FrogBotComponent` | No; built-in event | Replaces each event body and receives the document as its `row` prop. |

See [Collection calendar](/admin/collection-calendar) for modes, date fields, loading, and editing behavior.

#### CustomView

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `type` | `'custom'` | Yes | Selects a developer-provided view. |
| `component` | `FrogBotComponent` | Yes | Component that renders the custom view body. |
| `shell` | `boolean` | No; `true` | When `true`, renders within the collection shell and supports `ViewComponents`. When `false`, replaces the complete collection page and must be the collection's only view. |
| `components` | `ViewComponents` | No | Configures shared shell slots when the shell is enabled. |

### Custom Components

Collections can set [Custom Components](/custom-components/overview) for their List and Edit Views.

To override Collection Components, use the `admin.components` property in your Collection Config:

```ts
import type { CollectionConfig } from 'frogbot'

export const MyCollection: CollectionConfig = {
  // ...
  admin: {
    components: {
      // ...
    },
  },
}
```

The following options are available:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `Description` | `FrogBotComponent` | Built-in description | Replaces the collection description. [More details](/custom-components/list-view#description). |
| `edit` | `object` | — | Edit View component slots. [More details](#edit-view-options). |

List slots belong to a `type: 'list'` entry in `admin.views`: use `components.beforeView`, `beforeTable`, `afterTable`, and `afterView`. To replace the collection list, use a `type: 'custom'` entry with `component`. See [List View](/custom-components/list-view).

#### Edit View Options

Configure these slots under `admin.components.edit`. See [Edit View](/custom-components/edit-view) for working component examples.

| Option | Type | Default | Description |
| --- | --- | --- | --- |

| `editMenuItems` | `FrogBotComponent[]` | `[]` | Inject custom components within the 3-dot menu dropdown located in the document controls bar. |
| `SaveButton` | `FrogBotComponent` | Built-in button | Replace the default Save Button within the Edit View. [Drafts](/versions/drafts) must be disabled. |
| `SaveDraftButton` | `FrogBotComponent` | Built-in button | Replace the default Save Draft Button within the Edit View. [Drafts](/versions/drafts) must be enabled and autosave disabled. |
| `Status` | `FrogBotComponent` | Built-in status | Replace the default Status component within the Edit View. [Drafts](/versions/drafts) must be enabled. |
| `PublishButton` | `FrogBotComponent` | Built-in button | Replace the default Publish Button within the Edit View. [Drafts](/versions/drafts) must be enabled. |
| `UnpublishButton` | `FrogBotComponent` | Built-in button | Replace the default Unpublish Button within the Edit View. [Drafts](/versions/drafts) must be enabled. |
| `PreviewButton` | `FrogBotComponent` | Built-in button | Replace the default Preview Button within the Edit View. Preview must be enabled. |
| `Upload` | `FrogBotComponent` | Built-in upload | Replace the default Upload component within the Edit View. [Upload](/upload/overview) must be enabled. |
| `views` | `object` | — | Override built-in document views, add custom routes or tabs, or replace the complete document area. [More details](#document-views). |

##### Document Views

Use `admin.components.edit.views` to replace a built-in document view or add a custom route or tab. See [Document Views](/custom-components/document-views) for configuration and examples.

| Key | Route | Behavior |
| --- | --- | --- |
| `default` | Document root | Main document editor. |
| `api` | `/api` | API view. |
| `livePreview` | None (rendered inside the edit view's preview window) | Live Preview view. |
| `versions` | `/versions` | Version history. |
| `version` | `/versions/:version` | A specific version. |
| Any custom key | The configured `path` | Adds a custom route, tab, or both. |
| `root` | All document routes | Replaces the entire document area, including its header, controls, tabs, and nested views. |

`root` is mutually exclusive with every built-in and custom nested document view. When `root` is configured, it must be the only key in `views`.

**Built-in and root view config**

| Property | Type | Default | Behavior |
| --- | --- | --- | --- |
| `Component` | `FrogBotComponent` | Built-in view | Replaces the view component. Optional, allowing other properties to modify the built-in view. |
| `actions` | `FrogBotComponent[]` | — | Adds components to the view's actions. |
| `meta` | `MetaConfig` | — | Overrides metadata for the view. |
| `tab` | `DocumentTabConfig` | Built-in tab | Modifies the view's document tab. |

**Custom view config**

| Property | Type | Default | Behavior |
| --- | --- | --- | --- |
| `Component` | `FrogBotComponent` | Required with `path` | Renders the custom view. Required when `path` is set; otherwise optional. |
| `path` | `` `/${string}` `` | Required with `Component` | Adds a route below the document URL. Requires `Component`. Omit both `path` and `Component` to add only a tab. |
| `actions` | `FrogBotComponent[]` | — | Adds components to the view's actions. |
| `meta` | `MetaConfig` | — | Overrides metadata for the view. |
| `tab` | `DocumentTabConfig` | — | Configures the custom document tab. |

Document view configs do not support `exact`; custom `path` values use document-view routing.

**Document tab config**

| Property | Type | Default | Behavior |
| --- | --- | --- | --- |
| `Component` | `FrogBotComponent` | Built-in tab | Replaces the complete tab component. It receives the resolved `path`. |
| `Pill` | `FrogBotComponent` | — | Adds a component beside the tab label. |
| `label` | `string \| ({ t }) => string` | — | Sets the tab label. |
| `href` | `string \| function` | — | Sets or computes the tab destination. |
| `condition` | `function` | — | Returns whether the tab should be shown for the current request and permissions. |
| `isActive` | `boolean \| ({ href }) => boolean` | — | Controls whether the tab is active. |
| `newTab` | `boolean` | `false` | Opens the destination in a new browser tab. |
| `order` | `number` | — | Sets the tab's render order. Increments of `100` are recommended. |

<Warning>
  **Important:** All edit view components must be configured under
  `admin.components.edit`, not directly under `admin.components`.

For example, use `admin.components.edit.Status`, not `admin.components.Status`.

</Warning>

### Pagination

All Collections receive their own List View which displays a paginated list of documents that can be sorted and filtered. The pagination behavior of the List View can be customized on a per-Collection basis, and uses the same [Pagination](/queries/pagination) API that FrogBot provides.

To configure pagination options, use `pagination` on a list entry in `admin.views`:

```ts
import type { CollectionConfig } from 'frogbot'

export const Posts: CollectionConfig = {
  // ...
  admin: {
    views: [
      {
        type: 'list',
        pagination: {
          defaultLimit: 10,
          limits: [10, 20, 50],
        },
      },
    ],
  },
}
```

The following options are available:

| Option         | Description                                                                                         |
| -------------- | --------------------------------------------------------------------------------------------------- |
| `defaultLimit` | Integer that specifies the initial per-page limit. When omitted, the List View uses FrogBot's list default. |
| `limits`       | Integers offered as List View page-size choices. This does not configure Board View loading.             |

### List Searchable Fields

In the List View, there is a "search" box that allows you to quickly find a document through a simple text search. Normal search behavior includes the ID and, when defined, `admin.useAsTitle`. `searchableFields` adds fields to that behavior rather than replacing the title field.

To define which fields should be searched, use `searchableFields` on a list entry in `admin.views`:

```ts
import type { CollectionConfig } from 'frogbot'

export const Posts: CollectionConfig = {
  // ...
  admin: {
    views: [
      {
        type: 'list',
        defaultFields: ['title', 'slug'],
        searchableFields: ['title', 'slug'],
      },
    ],
  },
}
```

<Warning>
  **Tip:** If you are adding searchable fields, make sure you index each of
  these fields so your admin queries can remain performant.
</Warning>

## List View Select API

Set `admin.enableListViewSelectAPI` to `true` to make the List View use the [Select API](/queries/select) to query only the _active_ columns as opposed to entire documents. This greatly improves performance, especially for collections with large documents or many fields.

This may cause unexpected behavior in some cases, such as when using hooks that rely on the full document data.

For example, if your component relies on a "title" field, this field will not be populated if the column is inactive:

```ts
import type { CollectionConfig } from 'frogbot'

export const Posts: CollectionConfig = {
  // ...
  fields: [
    // ...
    {
      name: 'myField',
      type: 'text',
      hooks: {
        afterRead: [
          ({ doc }) => doc.title, // The `title` field will not be populated by default, unless the column is active
        ],
      },
    },
  ],
}
```

To ensure title is always present, list it in [`forceSelect`](/queries/select#always-selected-fields) on your Collection Config:

```ts
export const Posts: CollectionConfig = {
  // ...
  forceSelect: { title: true },
}
```

### Format Document URLs

The `formatDocURL` function allows you to customize how document links are generated in the List View. This is useful for disabling links for certain documents, redirecting to custom destinations, or modifying URLs based on user context or document state.

To define a custom document URL formatter, use the `admin.formatDocURL` property in your Collection Config:

```ts
import type { CollectionConfig } from 'frogbot'

export const Posts: CollectionConfig = {
  // ...
  admin: {
    formatDocURL: ({ doc, defaultURL, req, collectionSlug, viewType }) => {
      // Disable linking for documents with specific status
      if (doc.status === 'private') {
        return null
      }

      // Custom destination for featured posts
      if (doc.featured) {
        return '/admin/featured-posts'
      }

      // Add query parameters based on user role
      if (req.user?.role === 'admin') {
        return defaultURL + '?admin=true'
      }

      // Use default URL for all other cases
      return defaultURL
    },
  },
}
```

The `formatDocURL` function receives the following arguments:

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `doc` | `Record<string, unknown>` | Always set | The document data for the current row. |
| `defaultURL` | `string` | Always set | The URL FrogBot would normally use for this document. Return it as-is, change it, or replace it. |
| `req` | `FrogBotRequest` | Always set | The current request, with the signed-in user, request data, and `req.frogbot`. |
| `collectionSlug` | `string` | Always set | The slug of the current collection. |
| `viewType` | `ViewTypes` | — | The view the link is rendered in, such as `'list'` or `'trash'`. |

The function should return:

- `null` to disable the link entirely (no link will be rendered)
- A `string` containing the custom URL to use for the link
- The `defaultURL` parameter to use FrogBot's default linking behavior

<Tip>
  **Tip:** The `defaultURL` parameter saves you from having to reconstruct URLs
  manually. You can modify it by appending query parameters or use it as a
  fallback for your custom logic.
</Tip>

#### Examples

**Disable linking for certain users:**

```ts
formatDocURL: ({ defaultURL, req }) => {
  if (req.user?.role === 'editor') {
    return null // No link rendered
  }
  return defaultURL
}
```

## GraphQL

You can completely disable GraphQL for this collection by passing `graphQL: false` to your collection config. This will completely disable all queries, mutations, and types from appearing in your GraphQL schema.

You can also pass an object to the collection's `graphQL` property, which allows you to define the following properties:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `singularName` | `string` | Derived from `slug` | Singular name used for this collection's GraphQL types and queries. |
| `pluralName` | `string` | Derived from `slug` | Plural name used for this collection's GraphQL types and queries. |
| `disableQueries` | `true` | — | Leaves this collection's queries out of the schema. |
| `disableMutations` | `true` | — | Leaves this collection's mutations out of the schema. |

## TypeScript

You can import types from FrogBot to help make writing your Collection configs easier and type-safe. There are two main types that represent the Collection Config, `CollectionConfig` and `SanitizedCollectionConfig`.

The `CollectionConfig` type represents a raw Collection Config in its full form, where only the bare minimum properties are marked as required. The `SanitizedCollectionConfig` type represents a Collection Config after it has been fully sanitized. Generally, this is only used internally by FrogBot.

```ts
import type { CollectionConfig, SanitizedCollectionConfig } from 'frogbot'
```
