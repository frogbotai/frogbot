A Collection is a group of records, called Documents, that all share a common schema. Each Document in a Collection is stored in the [Database](/database/overview) based on the [Fields](/fields/overview) that you define, and automatically generates a [Local API](/local-api/overview), [REST API](/rest-api/overview), and [GraphQL API](/graphql/overview) used to manage your Documents. Collections can also enable [Authentication](/authentication/overview), [Uploads](/upload/overview), and more.

To define a Collection Config, use the `collections` property in your [FrogBot Config](/configuration/overview):

```ts
import { buildConfig } from 'frogbot'
import { Users, Projects, Files, Chats, Messages } from './collections'

export default buildConfig({
  collections: [Users, Projects, Files, Chats, Messages],
})
```

<Tip>
  If your Collection is only ever meant to contain a single Document, consider using a [Global](/configuration/globals) instead.
</Tip>

## FrogBot collection model

Collections you configure remain ordinary FrogBot collections. FrogBot injects a files collection, and agents also need chat and message stores. You can adopt those roles into collections you own.

### Role markers

FrogBot identifies managed collections by role, not by a required slug. Mark a collection with `chat: true`, `message: true`, or `file: true`; FrogBot keeps its slug and merges in the required configuration.

```ts
import type { CollectionConfig } from 'frogbot'

export const Conversations: CollectionConfig = {
  slug: 'conversations',
  chat: true,
  fields: [{ name: 'channel', type: 'text' }]
}

export const Turns: CollectionConfig = {
  slug: 'turns',
  message: true,
  fields: []
}
```

Mark at most one collection per role. With no marker, agents cause FrogBot to inject defaults at `chats` and `messages`. An unmarked collection already using either default slug causes a configuration error rather than implicit adoption.

### Field contribution per role

Your compatible field, access, admin, and option values win during the merge. Missing base fields are appended and hooks are combined.

| Role marker | FrogBot contributes |
| --- | --- |
| `chat: true` | `title`, owner `user` relationship, agent slug, and `lastMessageAt` |
| `message: true` | Text `id`, chat relationship, role, `UIMessage.parts`, metadata, and usage |
| `file: true` | Uploads, folders, soft deletion, admin defaults, and authenticated access |

FrogBot rejects incompatible base field types. `chats.user` and `messages.id`, `messages.chat`, and `messages.parts` are reserved and cannot be redefined.

### Default collections

The default collections use soft deletion, appear under **Chat** in the admin panel, and scope access to the authenticated chat owner. The message ID is the AI SDK UI message ID, allowing an interrupted assistant message to be continued in place across database adapters.

The chat's `user` relationship resolves as follows:

- No auth collection: FrogBot's default `users` collection.
- One auth collection: that collection, regardless of slug.
- Multiple auth collections: the collection selected by `admin.user`.

See [Chat persistence](/chat/overview) for request behavior and durability guarantees.

## Collection config options

The following options are available on any `CollectionConfig`. FrogBot adds `chat`, `message`, `connections`, and `file` to the built-in set; every other option below is part of the FrogBot configuration API.

It's best practice to write Collections in separate files and import them into the root config.

Here is a minimal example:

```ts
import type { CollectionConfig } from 'frogbot'

export const Posts: CollectionConfig = {
  slug: 'posts',
  fields: [
    {
      name: 'title',
      type: 'text',
    },
  ],
}
```

<Tip>
  **Reminder:** For more complex examples, see the
  [Templates](https://github.com/frogbotcms/frogbot/tree/main/templates) and
  [Examples](https://github.com/frogbotcms/frogbot/tree/main/examples)
  directories in the FrogBot repository.
</Tip>

The following options are available:

| Option               | Description                                                                                                                                                                                                                                                |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `chat`             | **FrogBot** — adopts this collection as the chat store. At most one collection may be marked. [More details](#role-markers).                                                                                                                           |
| `message`            | **FrogBot** — adopts this collection as the message store. At most one collection may be marked. [More details](#role-markers).                                                                                                                         |
| `file`               | **FrogBot** — adopts this collection as the files store. At most one collection may be marked. [More details](/configuration/files).                                                                                                                    |
| `admin`              | The configuration options for the Admin Panel. [More details](#admin-options).                                                                                                                                                                             |
| `access`             | Provide Access Control functions to define exactly who should be able to do what with Documents in this Collection. [More details](/access-control/collections).                                                                                         |
| `auth`               | Specify options if you would like this Collection to feature authentication. Set to `true` for defaults or pass an auth config object. FrogBot extends auth with `providers`, `allowedDomains`, and `allowSignup`. [More details](/authentication/overview).                                                                                         |
| `custom`             | Extension point for adding custom data (e.g. for plugins)                                                                                                                                                                                                  |
| `disableDuplicate`   | When true, do not show the "Duplicate" button while editing documents within this Collection and prevent `duplicate` from all APIs.                                                                                                                        |
| `dbName`             | Custom table or Collection name depending on the Database Adapter. Auto-generated from slug if not defined.                                                                                                                                                |
| `endpoints`          | Add custom routes to the REST API. Set to `false` to disable routes. [More details](/rest-api/overview#custom-endpoints).                                                                                                                                |
| `fields` \*          | Array of field types that will determine the structure and functionality of the data stored within this Collection. [More details](/fields/overview).                                                                                                    |
| `graphQL`            | Manage GraphQL-related properties for this collection. [More](#graphql)                                                                                                                                                                                    |
| `hooks`              | Entry point for Hooks. [More details](/hooks/overview#collection-hooks).                                                                                                                                                                                 |
| `hierarchy`          | Enable hierarchical tree structure with automatic parent-child relationships and path generation. [More details](/hierarchy/overview).                                                                                                                   |
| `orderable`          | If true, enables custom ordering for the collection, and documents can be reordered via drag and drop. Uses [orderable](#orderable) for efficient reordering.                                                                                              |
| `labels`             | Singular and plural labels for use in identifying this Collection throughout FrogBot. Auto-generated from slug if not defined.                                                                                                                             |
| `enableQueryPresets` | Enable query presets for this Collection. [More details](/query-presets/overview).                                                                                                                                                                       |
| `lockDocuments`      | Enables or disables document locking. By default, document locking is enabled. Set to an object to configure, or set to `false` to disable locking. [More details](/admin/locked-documents).                                                             |
| `slug` \*            | Unique, URL-friendly string that will act as an identifier for this Collection.                                                                                                                                                                            |
| `timestamps`         | Set to false to disable documents' automatically generated `createdAt` and `updatedAt` timestamps.                                                                                                                                                         |
| `trash`              | A boolean to enable soft deletes for this collection. Defaults to `false`. [More details](/trash/overview).                                                                                                                                              |
| `typescript`         | An object with property `interface` as the text used in schema generation. Auto-generated from slug if not defined.                                                                                                                                        |
| `upload`             | Specify options if you would like this Collection to support file uploads. For more, consult the [Uploads](/upload/overview) documentation.                                                                                                              |
| `versions`           | Set to true to enable default options, or configure with object properties. [More details](/versions/overview#collection-config).                                                                                                                        |
| `defaultPopulate`    | Specify which fields to select when this Collection is populated from another document. [More Details](/queries/select#defaultpopulate-collection-config-property).                                                                                      |
| `indexes`            | Define compound indexes for this collection. This can be used to either speed up querying/sorting by 2 or more fields at the same time or to ensure uniqueness between several fields.                                                                     |
| `select`             | Function that receives the current `operation`, `req`, and caller's `select`, and returns the final `select` to apply. Useful for forcing fields to be populated for hooks / access control. [More details](/queries/select#entity-level-select-config). |
| `disableBulkDelete`  | Disable the bulk delete operation for the collection in the admin panel and the REST API                                                                                                                                                                   |
| `disableBulkEdit`    | Disable the bulk edit operation for the collection in the admin panel and the REST API                                                                                                                                                                     |

_\* An asterisk denotes that a property is required._

### Fields

Fields define the schema of the Documents within a Collection. To learn more, go to the [Fields](/fields/overview) documentation.

### Access Control

[Collection Access Control](/access-control/collections) determines what a user can and cannot do with any given Document within a Collection. To learn more, go to the [Access Control](/access-control/overview) documentation.

### Hooks

[Collection Hooks](/hooks/collections) allow you to tie into the lifecycle of your Documents so you can execute your own logic during specific events. To learn more, go to the [Hooks](/hooks/overview) documentation.

### Orderable

When `orderable` is enabled, FrogBot uses [fractional indexing](https://observablehq.com/@dgreensp/implementing-fractional-indexing) to efficiently manage document order. When enabled on collections, this allows you to manually drag and drop documents in the Admin Panel to reorder them, as well as programmatically set the order of documents via the Local API, REST API, or GraphQL API.

Orderable can also be added to [joins fields](/fields/join).

#### Fractional indexing

If you need to generate order keys programmatically (e.g., when creating documents via the Local API with a specific order), you can import the utilities directly:

```ts
import { generateKeyBetween, generateNKeysBetween } from 'frogbot/shared'

// Generate a key between two existing keys (or null for start/end)
const newKey = generateKeyBetween('a0', 'a1')

// Generate a key at the start (before 'a0')
const startKey = generateKeyBetween(null, 'a0')

// Generate a key at the end (after 'a1')
const endKey = generateKeyBetween('a1', null)

// Generate multiple keys between two existing keys
const keys = generateNKeysBetween('a0', 'a1', 5)
```

These utilities are useful when you need fine-grained control over document ordering, such as inserting documents at specific positions or batch-creating documents with predetermined order.

## Admin Options

The behavior of Collections within the [Admin Panel](/admin/overview) can be fully customized to fit the needs of your application. This includes grouping or hiding their navigation links, adding [Custom Components](/custom-components/overview), selecting which fields to display in the List View, and more.

To configure Admin Options for Collections, use the `admin` property in your Collection Config:

```ts
import type { CollectionConfig } from 'frogbot'

export const MyCollection: CollectionConfig = {
  // ...
  admin: {
    // ...
  },
}
```

The following options are available:

| Option                       | Description                                                                                                                                                                                                                  |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `group`                      | Text or localization object used to group collection links. Set to `null` for a top-level link or `false` to hide the link while keeping its routes accessible.                                                              |
| `icon`                       | Built-in kebab-case icon name or component import path used for the collection's navigation link.                                                                                                                           |
| `hidden`                     | Set to true or a function, called with the current user, returning true to exclude this Collection from navigation and admin routing.                                                                                        |
| `useAsTitle`                 | Specify a top-level field to use for a document title throughout the Admin Panel. If no field is defined, the ID of the document is used as the title.                                                                       |
| `description`                | Text to display below the Collection label in the List View to give editors more information. Alternatively, you can use the `admin.components.Description` to render a React component. [More details](#custom-components). |
| `views`                      | Ordered list of collection views, including list, board, calendar, and custom layouts. [More details](#collection-views).                                                                                                  |
| `disableCopyToLocale`        | Disables the "Copy to Locale" button while editing documents within this Collection. Only applicable when localization is enabled.                                                                                           |
| `enableRichTextLink`         | The [Rich Text](/fields/rich-text) field features a `Link` element which allows for users to automatically reference related documents within their rich text. Set to `true` by default.                                   |
| `enableRichTextRelationship` | The [Rich Text](/fields/rich-text) field features a `Relationship` element which allows for users to automatically reference related documents within their rich text. Set to `true` by default.                           |
| `folders`                    | A boolean to enable folders for a given collection. Defaults to `false`. [More details](/folders/overview).                                                                                                                |
| `formatDocURL`               | Function to customize document links in the List View. Return `null` to disable linking, or a string for custom URLs. [More details](#format-document-urls).                                                                 |
| `meta`                       | Page metadata overrides to apply to this Collection within the Admin Panel. [More details](/admin/metadata).                                                                                                               |
| `preview`                    | Function to generate preview URLs within the Admin Panel that can point to your app. [More details](/admin/preview).                                                                                                       |
| `livePreview`                | Enable real-time editing for instant visual feedback of your front-end application. [More details](/live-preview/overview).                                                                                                |
| `components`                 | Swap in your own React components to be used within this Collection. [More details](#custom-components).                                                                                                                     |
| `pagination`                 | Set pagination-specific options for this Collection in the List View. [More details](#pagination).                                                                                                                           |

<Warning>
  **Note:** If you set `useAsTitle` to a relationship or join field, it will use
  only the ID of the related document(s) as the title. To display a specific
  field (i.e. title) from the related document instead, create a virtual field
  that extracts the desired data, and set `useAsTitle` to that virtual field.
</Warning>

### Collection Views

`admin.views` accepts `CollectionView[]`. `CollectionView` is the exported union `ListView | BoardView | CalendarView | CustomView`.

The array order controls the switcher and first-view fallback. A collection can have at most one list view, and it must be first. Omit `views` to use one default list view without a switcher.

```ts
import type { CollectionConfig } from 'frogbot'

export const Projects: CollectionConfig = {
  slug: 'projects',
  admin: {
    views: [
      {
        type: 'list',
        slug: 'active',
        label: 'Active',
        defaultFields: ['title', 'status'],
        filter: { archived: { equals: false } },
        components: {
          beforeTable: ['/components/ProjectSummary#ProjectSummary'],
        },
      },
      {
        type: 'custom',
        slug: 'report',
        label: 'Report',
        component: '/components/ProjectReport#ProjectReport',
      },
    ],
  },
  fields: [],
}
```

#### Shared view properties

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `slug` | `string` | No; defaults to `type` | Unique route and saved-preference key after normalization to lowercase kebab case. Duplicate or empty normalized slugs produce a configuration error. The first view uses the collection's root route. |
| `label` | `string` | No; defaults to the capitalized `type` | Label displayed in the view switcher. |
| `defaultFields` | `string[]` | No | Ordered field dot paths initially displayed as list columns or board card fields. Users can change list columns through normal list controls. |
| `filter` | `Where \| ({ req }) => Where \| Promise<Where>` | No | Invisible base filter applied to the view. The function receives the current `FrogbotRequest`. |
| `defaultSort` | `Sort` (`string \| string[]`) | No | Initial field sort or ordered list of sorts. Prefix a field with `-` for descending order. |
| `searchableFields` | `string[]` | No | Adds field dot paths to the normal search behavior. The collection's `useAsTitle` field remains included; this option does not replace it. |
| `pagination` | `ViewPagination` | No | Configures query limits. Defaults depend on the view type. |
| `access` | `({ req }) => boolean \| Promise<boolean>` | No; defaults to collection access | Controls whether the current user can open the view. It does not replace collection operation access. |
| `components` | View-specific components | No | Supplies shared shell slots and slots for the selected view type. |

#### ViewPagination

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `defaultLimit` | `number` | No; list uses FrogBot list defaults, board defaults to `50` | List documents per page or board documents fetched per column. Board columns lazy-load additional pages and virtualize rendered cards. |
| `limits` | `number[]` | No; list uses FrogBot list defaults | Page-size choices shown by list controls. This property does not change board loading or display controls. |

#### ViewComponents

These shell slots are shared by list, board, calendar, and custom views. Each value uses a `FrogbotComponent` import path; array slots render in declaration order.

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `actions` | `FrogbotComponent[]` | No; `[]` | Adds actions to the view's action area. |
| `menuItems` | `FrogbotComponent[]` | No; `[]` | Adds entries to the view menu. |
| `beforeView` | `FrogbotComponent[]` | No; `[]` | Renders inside the collection shell before the view body. |
| `afterView` | `FrogbotComponent[]` | No; `[]` | Renders inside the collection shell after the view body. |

#### ListView

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `type` | `'list'` | Yes | Selects the table-based list view. |
| `components` | `ViewComponents & ListViewComponents` | No | Adds shared shell slots and list table slots. |

**ListView components**

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `beforeTable` | `FrogbotComponent[]` | No; `[]` | Renders after list controls and immediately before the table. |
| `afterTable` | `FrogbotComponent[]` | No; `[]` | Renders immediately after the table. |

#### BoardView

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `type` | `'board'` | Yes | Selects the column-based board view. |
| `groupBy` | `string` | No | Dot path to the select or single relationship field used for columns. Documents without a value appear in **Uncategorized**. |
| `cover` | `string` | No | Dot path to an upload field rendered as each card's cover image. |
| `components` | `ViewComponents & BoardComponents` | No | Adds shared shell slots and board-specific components. |

**Board components**

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `beforeColumns` | `FrogbotComponent[]` | No; `[]` | Renders before the board columns. |
| `afterColumns` | `FrogbotComponent[]` | No; `[]` | Renders after the board columns. |
| `ColumnHeader` | `FrogbotComponent` | No; built-in header | Replaces each column header. |
| `Card` | `FrogbotComponent` | No; built-in card | Replaces each board card and receives the document as its `row` prop. |

See [Collection board](/configuration/collection-board) for grouping, loading, and drag behavior.

#### CalendarView

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `type` | `'calendar'` | Yes | Selects the date-based calendar view. |
| `start` | `string` | Yes | Dot path to the date field used as each event's start. |
| `end` | `string` | No | Dot path to the date field used as each event's end. Without it, events use the start as their end. |
| `color` | `string` | No | Dot path to a select or radio field whose value colors each event. |
| `modes` | `CalendarMode[]` | No; `['month', 'week', 'day']` | Available modes in display order. The first mode is the default. |
| `snap` | `number` | No | Minute interval used when creating, moving, or resizing events. |
| `components` | `ViewComponents & CalendarComponents` | No | Adds shared shell slots and calendar-specific components. |

**Calendar components**

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `beforeCalendar` | `FrogbotComponent[]` | No; `[]` | Renders before the calendar. |
| `afterCalendar` | `FrogbotComponent[]` | No; `[]` | Renders after the calendar. |
| `Event` | `FrogbotComponent` | No; built-in event | Replaces each event body and receives the document as its `row` prop. |

See [Collection calendar](/configuration/collection-calendar) for modes, date fields, loading, and editing behavior.

#### CustomView

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `type` | `'custom'` | Yes | Selects a developer-provided view. |
| `component` | `FrogbotComponent` | Yes | Component that renders the custom view body. |
| `shell` | `boolean` | No; `true` | When `true`, renders within the collection shell and supports `ViewComponents`. When `false`, replaces the complete collection page and must be the collection's only view. |
| `components` | `ViewComponents` | No | Configures shared shell slots when the shell is enabled. |

### Custom Components

Collections can set their own [Custom Components](/custom-components/overview) which only apply to Collection-specific UI within the [Admin Panel](/admin/overview). This includes elements such as the Save Button, or entire layouts such as the Edit View.

To override Collection Components, use the `admin.components` property in your Collection Config:

```ts
import type { CollectionConfig } from 'frogbot'

export const MyCollection: CollectionConfig = {
  // ...
  admin: {
    components: {
      // ...
    },
  },
}
```

The following options are available:

| Option            | Description                                                                                                                                                                        |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Description`     | A component to render below the Collection label in the List View. An alternative to the `admin.description` property. [More details](/custom-components/list-view#description). |
| `edit`            | Override specific components within the Edit View. [More details](#edit-view-options).                                                                                             |

#### Edit View Options

Custom components within the Edit View are configured under `admin.components.edit`:

```ts
import type { CollectionConfig } from 'frogbot'

export const MyCollection: CollectionConfig = {
  // ...
  admin: {
    components: {
      edit: {
        Status: '/path/to/CustomStatus',
        SaveButton: '/path/to/CustomSaveButton',
        PublishButton: '/path/to/CustomPublishButton',
        views: {
          root: {
            Component: '/path/to/CustomEditView',
          },
        },
      },
    },
  },
}
```

The following components can be customized within `admin.components.edit`:

| Option                   | Description                                                                                                                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `beforeDocumentControls` | Inject custom components before the Save / Publish buttons. [More details](/custom-components/edit-view#beforedocumentcontrols).                                                                      |
| `editMenuItems`          | Inject custom components within the 3-dot menu dropdown located in the document controls bar. [More details](/custom-components/edit-view#editmenuitems).                                             |
| `SaveButton`             | Replace the default Save Button within the Edit View. [Drafts](/versions/drafts) must be disabled. [More details](/custom-components/edit-view#savebutton).                                         |
| `SaveDraftButton`        | Replace the default Save Draft Button within the Edit View. [Drafts](/versions/drafts) must be enabled and autosave must be disabled. [More details](/custom-components/edit-view#savedraftbutton). |
| `Status`                 | Replace the default Status component within the Edit View. [Drafts](/versions/drafts) must be enabled. [More details](/custom-components/edit-view#status).                                         |
| `PublishButton`          | Replace the default Publish Button within the Edit View. [Drafts](/versions/drafts) must be enabled. [More details](/custom-components/edit-view#publishbutton).                                    |
| `UnpublishButton`        | Replace the default Unpublish Button within the Edit View. [Drafts](/versions/drafts) must be enabled. [More details](/custom-components/edit-view#unpublishbutton).                                |
| `PreviewButton`          | Replace the default Preview Button within the Edit View. [Preview](/admin/preview) must be enabled. [More details](/custom-components/edit-view#previewbutton).                                     |
| `Upload`                 | Replace the default Upload component within the Edit View. [Upload](/upload/overview) must be enabled. [More details](/custom-components/edit-view#upload).                                         |
| `views`                  | Override built-in document views, add custom routes or tabs, or replace the complete document area. [More details](#document-views).                                                         |

##### Document Views

Use `admin.components.edit.views` to replace a built-in document view or add a custom view. The built-in keys are `default`, `api`, `livePreview`, `version`, and `versions`. Any other key defines a custom view and can add a route, a tab, or both.

```ts
import type { CollectionConfig } from 'frogbot'

export const Posts: CollectionConfig = {
  slug: 'posts',
  admin: {
    components: {
      edit: {
        views: {
          default: {
            actions: ['/components/EditActions#EditActions'],
          },
          audit: {
            Component: '/components/AuditView#AuditView',
            path: '/audit',
            tab: {
              label: 'Audit log',
              Pill: '/components/AuditCount#AuditCount',
            },
          },
        },
      },
    },
  },
  fields: [],
}
```

| Key | Route | Behavior |
| --- | --- | --- |
| `default` | Document root | Main document editor. |
| `api` | `/api` | API view. |
| `livePreview` | `/preview` | Live Preview view. |
| `versions` | `/versions` | Version history. |
| `version` | `/versions/:version` | A specific version. |
| Any custom key | The configured `path` | Adds a custom route, tab, or both. |
| `root` | All document routes | Replaces the entire document area, including its header, controls, tabs, and nested views. |

`root` is mutually exclusive with every built-in and custom nested document view. When `root` is configured, it must be the only key in `views`.

**Built-in and root view config**

| Property | Type | Behavior |
| --- | --- | --- |
| `Component` | `FrogbotComponent` | Replaces the view component. Optional, allowing other properties to modify the built-in view. |
| `actions` | `FrogbotComponent[]` | Adds components to the view's actions. |
| `meta` | `MetaConfig` | Overrides metadata for the view. |
| `tab` | `DocumentTabConfig` | Modifies the view's document tab. |

**Custom view config**

| Property | Type | Behavior |
| --- | --- | --- |
| `Component` | `FrogbotComponent` | Renders the custom view. Required when `path` is set; otherwise optional. |
| `path` | `` `/${string}` `` | Adds a route below the document URL. Requires `Component`. Omit both `path` and `Component` to add only a tab. |
| `actions` | `FrogbotComponent[]` | Adds components to the view's actions. |
| `meta` | `MetaConfig` | Overrides metadata for the view. |
| `tab` | `DocumentTabConfig` | Configures the custom document tab. |

Document view configs do not support `exact`; custom `path` values use document-view routing.

**Document tab config**

| Property | Type | Behavior |
| --- | --- | --- |
| `Component` | `FrogbotComponent` | Replaces the complete tab component. It receives the resolved `path`. |
| `Pill` | `FrogbotComponent` | Adds a component beside the tab label. |
| `label` | `string \| ({ t }) => string` | Sets the tab label. |
| `href` | `string \| function` | Sets or computes the tab destination. |
| `condition` | `function` | Returns whether the tab should be shown for the current request and permissions. |
| `isActive` | `boolean \| ({ href }) => boolean` | Controls whether the tab is active. |
| `newTab` | `boolean` | Opens the destination in a new browser tab. |
| `order` | `number` | Sets the tab's render order. Increments of `100` are recommended. |

<Warning>
  **Important:** All edit view components must be configured under
  `admin.components.edit`, not directly under `admin.components`.

For example, use `admin.components.edit.Status`, not `admin.components.Status`.

</Warning>

<Tip>
  **Note:** For details on how to build Custom Components, see [Building Custom
  Components](/custom-components/overview#building-custom-components).
</Tip>

### Pagination

All Collections receive their own List View which displays a paginated list of documents that can be sorted and filtered. The pagination behavior of the List View can be customized on a per-Collection basis, and uses the same [Pagination](/queries/pagination) API that FrogBot provides.

To configure pagination options, use `pagination` on a list entry in `admin.views`:

```ts
import type { CollectionConfig } from 'frogbot'

export const Posts: CollectionConfig = {
  // ...
  admin: {
    views: [
      {
        type: 'list',
        pagination: {
          defaultLimit: 10,
          limits: [10, 20, 50],
        },
      },
    ],
  },
}
```

The following options are available:

| Option         | Description                                                                                         |
| -------------- | --------------------------------------------------------------------------------------------------- |
| `defaultLimit` | Integer that specifies the initial per-page limit. When omitted, the List View uses FrogBot's list default. |
| `limits`       | Integers offered as List View page-size choices. This does not configure Board View loading.             |

### List Searchable Fields

In the List View, there is a "search" box that allows you to quickly find a document through a simple text search. Normal search behavior includes the ID and, when defined, `admin.useAsTitle`. `searchableFields` adds fields to that behavior rather than replacing the title field.

To define which fields should be searched, use `searchableFields` on a list entry in `admin.views`:

```ts
import type { CollectionConfig } from 'frogbot'

export const Posts: CollectionConfig = {
  // ...
  admin: {
    views: [
      {
        type: 'list',
        defaultFields: ['title', 'slug'],
        searchableFields: ['title', 'slug'],
      },
    ],
  },
}
```

<Warning>
  **Tip:** If you are adding searchable fields, make sure you index each of
  these fields so your admin queries can remain performant.
</Warning>

## List View Select API

The List View uses the [Select API](/queries/select) to query only the _active_ columns as opposed to entire documents. This greatly improves performance, especially for collections with large documents or many fields.

This may cause unexpected behavior in some cases, such as when using hooks that rely on the full document data.

For example, if your component relies on a "title" field, this field will not be populated if the column is inactive:

```ts
import type { CollectionConfig } from 'frogbot'

export const Posts: CollectionConfig = {
  // ...
  fields: [
    // ...
    {
      name: 'myField',
      type: 'text',
      hooks: {
        afterRead: [
          ({ doc }) => doc.title, // The `title` field will not be populated by default, unless the column is active
        ],
      },
    },
  ],
}
```

To ensure title is always present, define a top-level [`select`](/queries/select#entity-level-select-config) function on your Collection Config that merges the caller's `select` with the fields you require:

```ts
export const Posts: CollectionConfig = {
  // ...
  select: ({ select }) => ({ ...select, title: true }),
}
```

### Format Document URLs

The `formatDocURL` function allows you to customize how document links are generated in the List View. This is useful for disabling links for certain documents, redirecting to custom destinations, or modifying URLs based on user context or document state.

To define a custom document URL formatter, use the `admin.formatDocURL` property in your Collection Config:

```ts
import type { CollectionConfig } from 'frogbot'

export const Posts: CollectionConfig = {
  // ...
  admin: {
    formatDocURL: ({ doc, defaultURL, req, collectionSlug, viewType }) => {
      // Disable linking for documents with specific status
      if (doc.status === 'private') {
        return null
      }

      // Custom destination for featured posts
      if (doc.featured) {
        return '/admin/featured-posts'
      }

      // Add query parameters based on user role
      if (req.user?.role === 'admin') {
        return defaultURL + '?admin=true'
      }

      // Use default URL for all other cases
      return defaultURL
    },
  },
}
```

The `formatDocURL` function receives the following arguments:

| Argument         | Description                                                                                                                            |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `doc`            | The document data for the current row                                                                                                  |
| `defaultURL`     | The default URL that FrogBot would normally generate for this document. You can return this as-is, modify it, or replace it entirely.  |
| `req`            | The full [PayloadRequest](/types/frogbot-request) object, providing access to user context, frogbot instance, and other request data |
| `collectionSlug` | The slug of the current collection                                                                                                     |
| `viewType`       | The current view context (`'list'`, `'trash'`, etc.) where the link is being generated                                                 |

The function should return:

- `null` to disable the link entirely (no link will be rendered)
- A `string` containing the custom URL to use for the link
- The `defaultURL` parameter to use FrogBot's default linking behavior

<Tip>
  **Tip:** The `defaultURL` parameter saves you from having to reconstruct URLs
  manually. You can modify it by appending query parameters or use it as a
  fallback for your custom logic.
</Tip>

#### Examples

**Disable linking for certain users:**

```ts
formatDocURL: ({ defaultURL, req }) => {
  if (req.user?.role === 'editor') {
    return null // No link rendered
  }
  return defaultURL
}
```

## GraphQL

You can completely disable GraphQL for this collection by passing `graphQL: false` to your collection config. This will completely disable all queries, mutations, and types from appearing in your GraphQL schema.

You can also pass an object to the collection's `graphQL` property, which allows you to define the following properties:

| Option             | Description                                                                         |
| ------------------ | ----------------------------------------------------------------------------------- |
| `singularName`     | Override the "singular" name that will be used in GraphQL schema generation.        |
| `pluralName`       | Override the "plural" name that will be used in GraphQL schema generation.          |
| `disableQueries`   | Disable all GraphQL queries that correspond to this collection by passing `true`.   |
| `disableMutations` | Disable all GraphQL mutations that correspond to this collection by passing `true`. |

## TypeScript

You can import types from FrogBot to help make writing your Collection configs easier and type-safe. There are two main types that represent the Collection Config, `CollectionConfig` and `SanitizedCollectionConfig`.

The `CollectionConfig` type represents a raw Collection Config in its full form, where only the bare minimum properties are marked as required. The `SanitizedCollectionConfig` type represents a Collection Config after it has been fully sanitized. Generally, this is only used internally by FrogBot.

```ts
import type { CollectionConfig, SanitizedCollectionConfig } from 'frogbot'
```
