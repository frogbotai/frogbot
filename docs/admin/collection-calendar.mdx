---
title: Collection calendar
description: Configure a date-based calendar for a collection.
---

Add a calendar entry to `admin.views` to show documents in month, week, or day layouts. Include a list entry when users should be able to switch between table and calendar layouts.

See the complete [Collection views reference](/configuration/collections#collection-views).

## Calendar properties

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `type` | `'calendar'` | Yes | Selects the calendar layout. |
| `slug` | `string` | No; defaults to `'calendar'` | Unique normalized route and preference key. The first view uses the collection's root route. |
| `label` | `string` | No; defaults to `'Calendar'` | Label on the view's tab. |
| `icon` | `AdminIcon` | No; `'calendar'` | Icon on the view's tab. |
| `start` | `string` | Yes | Dot path to the date field used as each event's start. |
| `end` | `string` | No | Dot path to the date field used as each event's end. Without it, events use the start as their end and can't be resized. |
| `color` | `string` | No | Dot path to a select or radio field. When the field has [option colors](/fields/select#option-colors), each event takes its option's color, and options without one are gray. |
| `modes` | `CalendarMode[]` | No; `['month', 'week', 'day']` | Available modes in display order. The first mode is the default. |
| `snap` | `number` | No | Minute interval used when creating, moving, or resizing events. |
| `defaultFields` | `string[]` | No | Dot paths to fields rendered on each event, in display order. |
| `filter` | `Where` | No | Invisible base filter applied to every calendar query, as plain data. |
| `defaultSort` | `Sort` (`string \| string[]`) | No | Initial query sort. Prefix a field with `-` for descending order. |
| `searchableFields` | `string[]` | No | Not read by the calendar. Its search uses the list view's `searchableFields`, plus `useAsTitle`. |
| `pagination` | `ViewPagination` | No | Accepted for consistency with other views, but calendar views ignore it. Each visible range loads at most 1000 events. |
| `access` | `({ req }) => boolean \| Promise<boolean>` | No; collection access | Controls whether the current user can open the calendar without replacing collection operation access. |
| `components` | `ViewComponents & CalendarComponents` | No | Configures shared view slots and calendar components. |

## Calendar components

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `actions` | `FrogBotComponent[]` | No; `[]` | Renders in the page header, top right. |
| `toolbar` | `FrogBotComponent[]` | No; `[]` | Renders in the calendar's view controls, before Filters. Below the small breakpoint it moves into a right-aligned row under the toolbar. |
| `menuItems` | `FrogBotComponent[]` | No; `[]` | Adds entries to the calendar menu. |
| `beforeView` | `FrogBotComponent[]` | No; `[]` | Renders inside the view frame before the header. |
| `afterView` | `FrogBotComponent[]` | No; `[]` | Renders inside the view frame after the calendar body. |
| `beforeCalendar` | `FrogBotComponent[]` | No; `[]` | Renders before the calendar. |
| `afterCalendar` | `FrogBotComponent[]` | No; `[]` | Renders after the calendar. |
| `Event` | `FrogBotComponent` | No; built-in event | Replaces each event body and receives the document as its `row` prop. |
| `NoResults` | `FrogBotComponent` | No; built-in empty state | Shown above the grid when the calendar's filters match no records. The grid stays. |

```ts
export const Pipelines: CollectionConfig = {
  slug: 'pipelines',
  admin: {
    views: [
      {
        type: 'list',
        defaultFields: ['title', 'stage', 'owner', 'dueDate'],
      },
      {
        type: 'calendar',
        slug: 'schedule',
        start: 'dueDate',
        defaultFields: ['title', 'stage', 'owner'],
        modes: ['month', 'week', 'day'],
      },
    ],
  },
  fields: [
    { name: 'title', type: 'text', required: true },
    { name: 'stage', type: 'select', options: ['Backlog', 'Review', 'Done'] },
    { name: 'owner', type: 'relationship', relationTo: 'users' },
    { name: 'dueDate', type: 'date', admin: { date: { pickerAppearance: 'dayOnly' } } },
  ],
}
```

The `start` and `end` paths must resolve to date fields. Nested date fields use dot paths such as `schedule.startsAt`.

## Time zones and all-day dates

The calendar shows events in the viewer's browser time zone: a meeting saved at `2026-09-06T02:00:00Z` shows at 7pm on September 5 for someone in Los Angeles. An event that crosses midnight shows in every day it touches. Dragging an event to another day in month view, or in the all-day row, keeps its time of day, even across a daylight-saving change.

A `start` field with `pickerAppearance` `'dayOnly'` or `'monthOnly'` is a date, not a moment. Its events show in the all-day row on their saved date, the same day for every viewer, and moving or creating one saves noon UTC on the day. Every other date field is a moment shown at its time of day, including a plain `type: 'date'` field, because it can hold any instant, such as `createdAt` or a timestamp a hook writes. The `end` field is read the same way on its own, so a date-only `start` with a timed `end` keeps the end's time when an event moves.

Calendar queries are limited to the visible range and include the collection view's filter and current search. A range displays at most 1000 events.

Dragging or resizing an event performs a normal collection update, including access checks, validation, and hooks. When a day has more events than fit in month view, **+N more** opens a list of all of them. Creating a range opens the document drawer with the configured date fields prefilled. Users without update access can view events but cannot move or resize them.

The selected mode, date, event fields, filters and sort are saved per user and view. URL values take precedence over saved preferences, which take precedence over the configured defaults. **Reset to default** in the view menu clears the saved filters, sort and fields.

With the collection's [`admin.useAsDone`](/configuration/collections#done-records) set, done events show a green check and a muted title. The event open in the document drawer shows the shared selected style.
