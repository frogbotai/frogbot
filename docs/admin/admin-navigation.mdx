FrogBot's default admin sidebar starts with New Chat, followed by configurable sections and a bottom rail. It supports desktop collapse, mobile navigation, active links, and saved section state without additional configuration.

## Configure sections

`admin.components.navSections` is an ordered array of component import paths. By default, FrogBot renders `CollectionsSection` followed by `RecentsSection`:

```ts
admin: {
  components: {
    navSections: [
      '@frogbotai/next#CollectionsSection',
      '@frogbotai/next#RecentsSection'
    ]
  }
}
```

Setting `navSections` replaces that default array, so include every section you want rendered. Sections appear after New Chat and configured `admin.components.navItems`, in array order. Plugin navigation items follow configured items. The bottom rail renders after all sections.

Remove Recents by omitting `@frogbotai/next#RecentsSection`. To move it, place that path at the desired position in `navSections`.

`NavSection` gives each section a title, collapsible body, and scrolling content. Its collapsed state is saved for the current user under `frogbot-nav-section:{id}` and restored on reload. Give every section a stable, unique `id`.

## Recents behavior

Recents is enabled by default. FrogBot server-renders up to 30 chats available to the signed-in user, ordered by latest message, then refreshes the list after chat mutations, when the window regains focus, and every 30 seconds.

Chats are grouped under Today, Yesterday, Previous 7 days, Previous 30 days, and Older. Empty groups are hidden. The current chat remains active for its nested admin routes, and View all opens the configured chats collection list.

## Collection icons and placement

Set `admin.icon` on a collection to a built-in kebab-case icon name or a component import path. `IconName` provides autocomplete for every built-in name, including `robot`, `bubble-chat`, `file`, `link-square`, `ai-search`, and `people`.

```ts
import type { CollectionConfig } from 'frogbot'

export const Projects: CollectionConfig = {
  slug: 'projects',
  admin: {
    icon: 'robot',
    group: null,
  },
  fields: [],
}
```

Use `group: null` for a top-level collection. Leave `group` undefined for the default Collections group, provide a string or localized value for a named group, or use `false` to hide only the navigation link.

Component icons receive `size` and `className` props and are added to the generated import map:

```ts
admin: {
  icon: './src/components/ProjectsIcon#ProjectsIcon'
}
```

Within `CollectionsSection`, top-level collections retain collection configuration order. Named groups follow in first-seen order, with their collections in configuration order.

When the sidebar is collapsed, section headings and labels are hidden and each item displays its label in a tooltip. Section state and named-group state persist for the current user.

## Add a navigation item

`admin.components.navItems` holds the links above your collections. By default it is a single New Chat link pointing at the create route of the resolved chats collection. Each item requires a `label` and a full `path`. Set `icon` to a built-in kebab-case icon name or a component import path.

```ts
admin: {
  components: {
    navItems: [
      {
        label: 'Operations',
        path: '/admin/operations',
        icon: './src/components/OperationsIcon#OperationsIcon'
      }
    ]
  }
}
```

Setting `navItems` replaces the default array, so the configuration above removes New Chat. Include it yourself to keep it, in whatever position you want:

```ts
admin: {
  components: {
    navItems: [
      { label: 'New Chat', path: '/admin/collections/chats/create', icon: 'pencil-edit' },
      { label: 'Operations', path: '/admin/operations' }
    ]
  }
}
```

Use your own admin route and chats collection slug in that path when either is customized. Set `navItems: []` to render no links above your collections.

Component icons receive `size` and `className` props and are added to the generated import map.

Configured items are application-authored links and are not filtered by collection permissions or visibility. Apply any required access behavior in the component or destination.

## Copy and customize a section

The default sections and their prop types are exported from `@frogbotai/next`. Copy `RecentsSection` into your application when you need to change its query, heading, or server-rendered content. Keep its server component contract and import the reusable client renderer from the public client entry point:

```tsx
import { NavSection, type RecentsSectionProps } from '@frogbotai/next'
import {
  RecentsSectionClient,
  type RecentsSectionClientProps
} from '@frogbotai/next/client'
import { getCachedFrogbot } from 'frogbot'
import { formatAdminURL } from 'payload/shared'

export async function WorkspaceRecents({ payload, req }: RecentsSectionProps) {
  const chat = getCachedFrogbot()?.config.chat
  const chatsSlug = chat?.enabled ? chat.chatsSlug : ''
  let recents: RecentsSectionClientProps['recents'] = []
  let collectionPath = ''

  if (chat?.enabled && req?.user) {
    const result = await payload.find({
      collection: chat.chatsSlug,
      depth: 0,
      limit: 30,
      overrideAccess: false,
      req,
      sort: '-lastMessageAt'
    })
    collectionPath = formatAdminURL({
      adminRoute: payload.config.routes.admin,
      path: `/collections/${chat.chatsSlug}`
    })
    recents = result.docs.map(doc => ({
      id: doc.id,
      title: typeof doc.title === 'string' && doc.title ? doc.title : 'Untitled Chat',
      agent: typeof doc.agent === 'string' ? doc.agent : '',
      lastMessageAt: typeof doc.lastMessageAt === 'string' ? doc.lastMessageAt : null
    }))
  }

  return (
    <NavSection id="workspace-recents" title="Recents">
      <RecentsSectionClient
        chatsSlug={chatsSlug}
        collectionPath={collectionPath}
        recents={recents}
      />
    </NavSection>
  )
}
```

`RecentsSectionClient` preserves live refresh, date buckets, active rows, and View all. Its public `RecentsSectionClientProps` contract requires `chatsSlug`, `collectionPath`, and normalized `recents`. `bucketRecents` is also exported from `@frogbotai/next/client` when only the default grouping is needed.

```ts
admin: {
  components: {
    navSections: [
      '@frogbotai/next#CollectionsSection',
      './src/components/WorkspaceRecents#WorkspaceRecents'
    ]
  }
}
```

Component paths in `navSections`, navigation icons, and admin component slots use `FrogbotComponent`. This type accepts either an import-map path string or a component definition and is exported from `frogbot` for reusable configuration types.

Chat-wide component slots are grouped under `admin.components.chat`. Use `Chat` to replace the canonical conversation surface, or `UserMessageActions` and `AssistantMessageActions` to customize only role-specific controls. See [Chat persistence](/chat/overview#customize-admin-chat-components).

## Register a settings page

Add pages to the Settings card grid with the root `settings` array. Each entry requires a `label`, a relative `path`, and a `Component`. Paths may be nested, such as `security/audit`, but every normalized path must be unique. Do not include `/settings` or a leading slash.

```ts
import type { SettingsEntry } from 'frogbot'

const usageSettings: SettingsEntry = {
  label: 'Usage',
  path: 'usage',
  Component: './src/settings/Usage#Usage',
  icon: './src/settings/UsageIcon#UsageIcon',
  access: ({ req }) => Boolean(req.user)
}

export default buildConfig({
  settings: [usageSettings]
})
```

`icon` and `access` are optional. Without `access`, FrogBot allows any authenticated user. The access function runs before FrogBot shows the card or renders the page. Component and icon references are added to the generated import map.

Plugins append entries after existing settings so they compose in plugin order:

```ts
return {
  ...config,
  settings: [
    ...(config.settings ?? []),
    {
      label: 'Usage',
      path: 'usage',
      Component: '@workspace/plugin/client#UsageSettings'
    }
  ]
}
```

The usage reports, OAuth, and API keys plugins follow this convention. Their cards appear only when the corresponding plugin is installed. OAuth links to the existing Connections collection, while API Keys links to its existing collection list and key-creation modal; the settings registry does not duplicate those interfaces. Both links follow custom admin routes and custom collection slugs.

Registry entries add pages within FrogBot's default Settings shell; they do not override its core routes. To replace the entire Settings surface, configure a custom root view:

```ts
admin: {
  components: {
    views: {
      settings: {
        Component: './src/components/Settings#Settings',
        exact: false,
        path: '/settings'
      }
    }
  }
}
```

## Customize the bottom rail

Account and Settings appear in the default bottom rail. Add components around them with `admin.components.beforeBottomRail` and `admin.components.afterBottomRail`. Use `beforeSidebarClose` for controls immediately left of the expanded sidebar close button.

```ts
admin: {
  components: {
    beforeBottomRail: ['./src/components/WorkspaceSwitcher#WorkspaceSwitcher'],
    afterBottomRail: ['./src/components/SupportLink#SupportLink'],
    beforeSidebarClose: ['./src/components/SidebarAction#SidebarAction']
  }
}
```

## Replace the sidebar

Set `admin.components.Nav` to replace the default sidebar. Your component receives the standard admin server props, including the current user, permissions, and visible collections.

```ts
admin: {
  components: {
    Nav: './src/components/WorkspaceNav#WorkspaceNav'
  }
}
```

A custom `Nav` fully owns navigation rendering. It does not receive FrogBot's default sidebar styles, default New Chat link, configured items or sections, bottom rail, or shell slots automatically.
