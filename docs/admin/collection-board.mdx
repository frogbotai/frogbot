---
title: Collection board
description: Configure a draggable board for a collection.
---

Add a board entry to `admin.views` to show documents as cards grouped into columns. Include a list entry when users should be able to switch between table and board layouts.

`admin.views` uses the exported `CollectionView` union. See the complete [Collection views reference](/configuration/collections#collection-views) or configure a [Collection calendar](/admin/collection-calendar).

## Board properties

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `type` | `'board'` | Yes | Selects the board layout. |
| `slug` | `string` | No; defaults to `'board'` | Unique normalized route and preference key. The first view uses the collection's root route. |
| `label` | `string` | No; defaults to `'Board'` | Label on the view's tab. |
| `icon` | `AdminIcon` | No; `'kanban'` | Icon on the view's tab. |
| `groupBy` | `string` | No | Dot path to the select or single relationship field that determines each card's column. |
| `defaultFields` | `string[]` | No | Dot paths to the fields rendered on each card, in display order. |
| `cover` | `string` | No | Dot path to an upload field rendered as the card's cover image. |
| `filter` | `Where` | No | Invisible base filter applied to every board query, as plain data. |
| `defaultSort` | `Sort` (`string \| string[]`) | No | Initial card order within columns. Prefix a field with `-` for descending order. |
| `searchableFields` | `string[]` | No | Not read by the board. Its search uses the list view's `searchableFields`, plus `useAsTitle`. |
| `pagination` | `ViewPagination` | No; `defaultLimit: 50` | Sets the documents fetched per column. Each column lazy-loads additional pages and virtualizes rendered cards. `limits` only drives list page-size choices. |
| `access` | `({ req }) => boolean \| Promise<boolean>` | No; collection access | Controls whether the current user can open the board without replacing collection operation access. |
| `components` | `ViewComponents & BoardComponents` | No | Configures shared view slots and board components. |

## Board components

| Property | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `actions` | `FrogBotComponent[]` | No; `[]` | Renders in the page header, top right. |
| `toolbar` | `FrogBotComponent[]` | No; `[]` | Renders in the board's view controls, before Filters. Below the small breakpoint it moves into a right-aligned row under the toolbar. |
| `menuItems` | `FrogBotComponent[]` | No; `[]` | Adds entries to the board menu. |
| `beforeView` | `FrogBotComponent[]` | No; `[]` | Renders inside the view frame before the header. |
| `afterView` | `FrogBotComponent[]` | No; `[]` | Renders inside the view frame after the board body. |
| `beforeColumns` | `FrogBotComponent[]` | No; `[]` | Renders before the columns. |
| `afterColumns` | `FrogBotComponent[]` | No; `[]` | Renders after the columns. |
| `ColumnHeader` | `FrogBotComponent` | No; built-in header | Replaces each column header. See [Column headers](#column-headers). |
| `Card` | `FrogBotComponent` | No; built-in card | Replaces each card and receives the document as its `row` prop. |
| `NoResults` | `FrogBotComponent` | No; built-in empty state | Replaces the columns when the board's filters or search match no records. An unfiltered empty board shows its columns instead. |

```ts
export const Tasks: CollectionConfig = {
  slug: 'tasks',
  admin: {
    views: [
      {
        type: 'list',
        defaultFields: ['title', 'stage', 'assignee', 'dueDate'],
      },
      {
        type: 'board',
        slug: 'workflow',
        label: 'Workflow',
        groupBy: 'stage',
        defaultFields: ['title', 'assignee', 'dueDate'],
      },
    ],
  },
  fields: [
    { name: 'title', type: 'text' },
    {
      name: 'stage',
      type: 'select',
      options: ['Backlog', 'Review', 'Done'],
    },
    { name: 'assignee', type: 'relationship', relationTo: 'users' },
    { name: 'dueDate', type: 'date' },
  ],
}
```

The group field must be a single select or relationship field. Select option order controls column order. Documents without a value appear in **Uncategorized**.

Dragging a card performs a normal collection update, including access checks, validation, and hooks. A rejected update restores the card to its original column and displays the error.

When the board is sorted by its manual order, dragging a card within a column saves its new position. The order is the collection's hidden `_order` field, so every board on one collection shares a single manual order, and new documents go to the bottom.

Nested fields use dot paths such as `workflow.stage` and `details.dueDate`.

Board views use `pagination.defaultLimit` for each column, defaulting to 50. Columns lazy-load subsequent pages and virtualize their cards. `pagination.limits` applies only to list page-size controls. Omitting `admin.views` creates one default list view without a tab row, using FrogBot's normal list pagination defaults.

The board's group, sort, filters and card fields are saved per user, as are collapsed and hidden columns. **Reset to default** in the view menu returns to the config.

With the collection's [`admin.useAsDone`](/configuration/collections#done-records) set, each built-in card starts with a check circle that toggles the record's done field, and done cards show a muted title. The check is read-only without update access to the field. The card open in the document drawer shows the shared selected style.

## Adding cards

Users who can create documents in the collection see **+ Add** at the foot of each column. It opens an empty card with a title input, and the new document gets that column's group value:

- **Enter** saves the card and opens the next one, so several cards can be added in a row. Cards are saved one at a time, in the order they were typed.
- **Escape** discards the card. Leaving the input saves its text, or removes the card when it is empty.
- A save that fails keeps the card and its text, shows the error, and offers **Open form**.

**+ Add** opens the create form, prefilled with the column's value, instead of an inline card when a title alone can't create a document:

- `useAsTitle` is unset, `id`, or not a top-level Text or Textarea field, or the user can't set it.
- The collection is an upload collection, or an auth collection using the local strategy.
- Another field is required and has no `defaultValue` and no field-level `beforeValidate` hook. Fields inside arrays and blocks don't count.

When the group field itself is required, **Uncategorized** always opens the form.

## Collapsing and hiding columns

Each column's menu collapses it to a narrow strip showing its label and total, or hides it. A collapsed column still accepts dropped cards, and clicking the strip expands it. Hidden columns are listed under **Hidden** after the last column, where each can be shown again. Both are remembered per user in the board's preferences.

A column with no cards shows **No cards** and still accepts dropped cards.

## Column headers

Each column header shows the column's label and the total number of matching documents in it, including those not loaded yet. When the group field is a select or radio field with [option colors](/fields/select#option-colors), each option's header shows its label as a coloured pill, and options without a colour show as `gray`. **Uncategorized** always keeps a plain label.

A `ColumnHeader` component replaces the whole header and receives these props:

| Prop | Type | Behavior |
| --- | --- | --- |
| `column.key` | `string` | Stable key for the column. |
| `column.label` | `string` | Label shown in the header, such as the option label or the related document's title. **Uncategorized** for documents without a value. |
| `column.value` | `unknown` | Stored group value for the column. `undefined` for **Uncategorized**. |
| `column.color` | `OptionColor \| undefined` | The option's colour. Set only when the group field has option colors, and never for **Uncategorized**. |
| `count` | `number` | Total matching documents in the column, including those not loaded yet. |

Use `OptionPill` from `@frogbotai/ui` to draw the same pill as the built-in header. It accepts these props:

| Prop | Type | Required / default | Behavior |
| --- | --- | --- | --- |
| `color` | `OptionColor` | Yes | One of the seven option colours. |
| `children` | `ReactNode` | No | Pill content. |
| `className` | `string` | No | Added after the pill's own classes. |
| Other `span` props | `ComponentProps<'span'>` | No | Passed to the rendered `span`. |

```tsx
'use client'

import { OptionPill } from '@frogbotai/ui'
import type { OptionColor } from 'frogbot'

type StageHeaderProps = {
  column: { color?: OptionColor; key: string; label: string; value: unknown }
  count: number
}

export function StageHeader({ column, count }: StageHeaderProps) {
  return (
    <>
      {column.color ? <OptionPill color={column.color}>{column.label}</OptionPill> : <strong>{column.label}</strong>}
      <span>{count === 1 ? '1 task' : `${count} tasks`}</span>
    </>
  )
}
```

```ts
{
  type: 'board',
  groupBy: 'stage',
  components: { ColumnHeader: '/components/StageHeader#StageHeader' },
}
```
