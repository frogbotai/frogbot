## User model and budget policy

When AI is configured, FrogBot adds policy fields to the auth collection. `modelAccess` defaults to `all`, which includes models and routers configured later. `selected` requires at least one exact target in `models`. Granting a router permits that router slug, not direct calls to the model behind it.

Agent chat applies the same list. A user sees only the agent models they may use, and a request without a model runs the agent's default if allowed, otherwise the first allowed model. Agents with no allowed model are hidden from that user and reject their requests. Turns with no user, such as scheduled tasks and anonymous channel messages, have no per-user limit.

`monthlyBudget` is an optional USD limit. Completed billable usage increments `spendThisPeriodUSD`, including configured custom-provider prices. Requests stop when spend reaches the limit, and FrogBot resets spend at midnight UTC on the first day of each month. Counter updates are serialized within one process; deployments with multiple writers should use database-level serialization if exact concurrent accounting is required.

### Customizing the fields

Policy fields have no default access restrictions. Define a same-name field on your auth collection to override labels, admin settings, defaults, or access while FrogBot supplies omitted policy behavior.

Leave the fields out for fully open field access.

Block updates with your own check:

```ts
{ name: 'monthlyBudget', type: 'number', access: {
  update: ({ req }) => req.user?.isAdmin === true,
} }
```

Compose access from the roles plugin:

```ts
{ name: 'monthlyBudget', type: 'number', access: {
  update: allow('admin'),
} }
```

`spendThisPeriodUSD` is update-locked and read-only by default because FrogBot maintains it. A same-name override can replace that access or admin setting when needed.

The `ai` block creates an embedded `@frogbotai/gateway` instance when FrogBot starts. Local operations use AI SDK v7 against that in-process gateway, so no separate proxy service is required.

## Configure providers

Add at least one provider. Set a provider to `true` to use its SDK's standard environment credentials.

```ts
import { buildConfig } from 'frogbot'

export default buildConfig({
  // secret, db, and collections omitted
  ai: {
    providers: {
      openai: true,
      anthropic: true,
      bedrock: true
    }
  }
})
```

Built-in keys are `openai`, `anthropic`, `google`, `bedrock`, `groq`, `mistral`, `cohere`, `togetherai`, `fireworks`, `deepinfra`, `xai`, `perplexity`, `cerebras`, `voyage`, `replicate`, `typesafe-ai`, and `vercel`. See [TypeSafe AI setup](/gateway/providers#typesafe-ai-evaluation) for its server-side credential and evaluation-only models.

Model IDs use `<provider>/<model>`, where `<provider>` is the exact key you used under `ai.providers`, such as `bedrock/...` or `togetherai/...`. Replicate's `apiKey` maps to its `apiToken` option. Bedrock uses bearer tokens first, then explicit SigV4 keys, then the AWS default credential chain.

Use `{ apiKey: process.env.CUSTOM_KEY }` only for an alternate credential. Explicit keys must be non-empty. Bedrock accepts `true`, `{ region }`, paired `{ accessKeyId, secretAccessKey, sessionToken? }` overrides, or a custom `credentialProvider`. In Node.js, the default chain supports AWS profiles and IAM Identity Center, web identity, ECS task roles, and EC2 instance profiles. Install the optional `@aws-sdk/credential-providers` peer dependency to use this fallback. Edge runtimes must provide an edge-compatible `credentialProvider` instead.

Add an OpenAI-compatible endpoint with any non-built-in key. Its `models` list is required for validation, and calls use the custom key as the provider prefix.

```ts
ai: {
  providers: {
    internal: {
      type: 'openai-compatible',
      baseUrl: 'https://models.internal.example/v1',
      apiKey: process.env.INTERNAL_AI_KEY,
      headers: { 'x-deployment': 'production' },
      models: [
        {
          id: 'legal-summary-v2',
          mode: 'chat',
          name: 'Legal Summary',
          limit: { context: 128_000, output: 8_000 },
          cost: { input: 0.5, output: 1.5 },
          modalities: { input: ['text'], output: ['text'] },
          tool_call: true,
          structured_output: true,
          reasoningOptions: [{ type: 'effort', values: ['low', 'high'] }]
        }
      ]
    }
  }
}
```

Invoke that model as `internal/legal-summary-v2`. The chat model picker labels it `Legal Summary`, and its reasoning selector offers `Default`, `Low`, and `High`; built-in models take their names and reasoning levels from the model catalog. Built-in provider entries accept an optional `models` allowlist to restrict their catalog IDs; this is different from a custom provider's required model definitions.

A provider's `models` list decides what the app can use, while an [agent's `model.options`](/agents/overview#define-one) decides what users can pick for that agent.

### AI options

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `providers` | `Record<string, true \| BuiltInProviderEntry \| BedrockProviderEntry \| CustomProviderEntry>` | Required | Providers keyed by name. At least one entry must be set. A built-in key takes `true` or [built-in provider options](#built-in-provider-options), `bedrock` takes `true` or [Bedrock provider options](#bedrock-provider-options), and any other key needs [custom provider options](#custom-provider-options). |
| `routers` | `Record<string, RouterConfig>` | `{}` | Aliases from a slug to one model ID. See [Router options](#router-options). |
| `defaultRouter` | `string` | — | Must name a key in `routers`, or startup fails. FrogBot validates it but does not use it to pick a model: every operation still requires `model`. |
| `defaultModel` | `ModelId` | — | Model or router slug for agents that set no `model` and no `model.default`. Must resolve to a configured provider. |
| `smallModel` | `ModelId` | A recent low-cost model from the active model's provider | Model or router slug for internal utility calls such as naming chats. Must resolve to a configured provider. See [Choose a utility model](#choose-a-utility-model). |
| `hooks` | `AIHooks` | No hooks | Lifecycle hooks for every operation. See [Observe calls](#observe-calls). |
| `access` | `AIAccessConfig` | Every category allows signed-in users | Access rules per operation category. See [Control access](#control-access). |
| `deploymentId` | `string` | `FROGBOT_DEPLOYMENT_ID`, then `'local'` | Added to every AI span as the `frogbot.deployment` attribute. |
| `telemetry` | `AITelemetryConfig` | Enabled | Span registration settings. See [Trace calls](#trace-calls). |

### Built-in provider options

Pass `true` to use the provider's standard environment credentials, or an object:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `apiKey` | `string \| undefined` | Required | Credential for the provider. Must be a non-empty string; the key is required even though its type admits `undefined`, so `process.env` values type-check. Replicate receives it as its `apiToken`. |
| `models` | `string[]` | Every catalog model for the provider | Allowlist of the provider's catalog model names, without the provider prefix. Unknown names fail startup, and calls to other models of this provider are rejected. Also limits what an agent's `model.options: '*'` includes. |

### Bedrock provider options

Pass `true` to use bearer tokens or the AWS default credential chain, or an object with `region`, explicit keys, or a `credentialProvider`:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `region` | `string` | `AWS_REGION` | AWS region. Required when the entry sets neither explicit keys nor `credentialProvider`. |
| `accessKeyId` | `string` | — | AWS access key ID. Requires `secretAccessKey`; can't be combined with `credentialProvider`. |
| `secretAccessKey` | `string` | — | AWS secret access key. Requires `accessKeyId`. |
| `sessionToken` | `string` | — | Temporary session token for the explicit keys. |
| `credentialProvider` | `() => Promise<{ accessKeyId: string; secretAccessKey: string; sessionToken?: string }>` | — | Returns AWS credentials for each request. Use it for edge runtimes or custom credential sources; can't be combined with explicit keys. |
| `models` | `string[]` | Every Bedrock catalog model | Allowlist of Bedrock catalog model names, as for [built-in providers](#built-in-provider-options). |

### Custom provider options

| Option | Type | Required / default | Description |
| --- | --- | --- | --- |
| `type` | `'openai-compatible'` | Yes | Marks the entry as a custom endpoint. Its key under `ai.providers` becomes the model ID prefix and must not be a built-in provider key. |
| `baseUrl` | `string` | Yes | Base URL of the OpenAI-compatible API, usually ending in `/v1`. Must be non-empty. |
| `apiKey` | `string` | No | Sent as `Authorization: Bearer <apiKey>`. Omit it for endpoints without authentication. |
| `headers` | `Record<string, string>` | No | Extra headers sent with every request to the endpoint. |
| `models` | `ModelConfig[]` | Yes; at least one entry | The models the app can call through this endpoint. Each entry is described in [Custom model options](#custom-model-options). |

### Custom model options

| Option | Type | Required / default | Description |
| --- | --- | --- | --- |
| `id` | `string` | Yes | Model ID sent to the endpoint. Call it as `<provider key>/<id>`, such as `internal/legal-summary-v2`. Must be non-empty. |
| `mode` | `'chat' \| 'embedding' \| 'image_generation' \| 'audio_speech' \| 'audio_transcription' \| 'rerank' \| 'evaluate' \| 'video_generation'` | Yes | The kind of model. Only `chat` models can serve an agent, and only they are included by an agent's `model.options: '*'`. |
| `name` | `string` | No; the picker shows `id` | Display label in the chat model picker and in the agent manifest's `names`. |
| `cost` | `{ input?: number; output?: number; cache_read?: number }` | No; usage costs `0` | Prices in USD per million tokens. FrogBot uses them for `costUSD` in usage logs and for `monthlyBudget` spend. A missing `input` or `output` price counts as `0`. `cache_read` prices cached input tokens and defaults to the `input` price; cache-write tokens are priced as input. |
| `reasoningOptions` | `ModelReasoningOption[]` | No; no reasoning levels | Reasoning levels the endpoint accepts. Custom providers support `{ type: 'effort', values?: string[] }`: each value becomes a level in the chat selector, `values` defaults to `['low', 'medium', 'high']`, and a selected level is sent as `reasoning_effort`. The selector's `Default` level sends nothing. `{ type: 'budget_tokens', min?, max? }` and `{ type: 'toggle' }` are accepted by the type but add no levels for custom providers. |
| `limit` | `{ context?: number; input?: number; output?: number }` | No | Token limits for the model's context window, input, and output. Descriptive only: FrogBot does not enforce them or send them to the endpoint. |
| `modalities` | `{ input: ModelModality[]; output: ModelModality[] }` | No | Content types the model accepts and produces, each one of `'text'`, `'image'`, `'audio'`, `'video'`, or `'file'`. Descriptive only: FrogBot does not filter content by them. |
| `reasoning` | `boolean` | No | Whether the model reasons. Descriptive only: reasoning levels come from `reasoningOptions`. |
| `tool_call` | `boolean` | No | Whether the model supports tool calls. Descriptive only: FrogBot sends tools regardless. |
| `structured_output` | `boolean` | No | Whether the model supports structured output. Descriptive only: FrogBot does not check it before sending an `output` request. |
| `temperature` | `boolean` | No | Whether the model accepts a `temperature` setting. Descriptive only: FrogBot passes `temperature` through regardless. |
| `status` | `'alpha' \| 'beta' \| 'deprecated'` | No | Release status of the model. Descriptive only: FrogBot does not hide or reject models by status. |

## Add aliases

Routers are pure aliases from a stable slug to one model ID.

```ts
ai: {
  providers: {
    openai: true
  },
  routers: {
    fast: { model: 'openai/gpt-4o-mini' },
    careful: { model: 'openai/o3' }
  },
  defaultRouter: 'fast'
}
```

An alias has no fallback chain or access rule. `hidden` exists on `RouterConfig` but is reserved for future admin integration.

### Router options

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `model` | `string` | Required | Provider-prefixed model ID the alias resolves to. Must be non-empty. |
| `hidden` | `boolean` | — | Reserved; FrogBot does not read it yet. |

`defaultRouter` must name a configured alias, but v0 operations still require `model`. Local operations and agents resolve aliases; the mounted gateway HTTP routes expect provider-prefixed model IDs.

## Choose a utility model

FrogBot uses a small chat model for internal work such as naming new chats. By default, it chooses a recent low-cost model from the same provider as the active agent model. If no catalog candidate is available, it uses the active model.

Set `smallModel` to pin these calls to a configured model or alias:

```ts
ai: {
  providers: {
    openai: true
  },
  routers: {
    utility: { model: 'openai/gpt-5-nano' }
  },
  smallModel: 'utility' // or 'openai/gpt-5-nano'
}
```

The model or alias must resolve to a configured provider. Utility calls use the normal operation lifecycle and appear in usage reporting.

## Call operations

Call methods on a `FrogBot` instance or `req.frogbot`. Text generation accepts either `prompt` or `messages`, never both.

```ts
const { text, usage, finishReason } = await req.frogbot.generateText({
  model: 'fast',
  prompt: 'Summarize the latest support request',
  req
})
```

These are the public v0 operation signatures.

```ts
generateText(opts: GenerateTextOpts)
streamText(opts: StreamTextOpts)
embed(opts: EmbedOpts)
embedMany(opts: EmbedManyOpts)
generateImage(opts: GenerateImageOpts)
generateSpeech(opts: GenerateSpeechOpts)
transcribe(opts: TranscribeOpts)
generateVideo(opts: GenerateVideoOpts)
rerank(opts: RerankOpts)
evaluate(opts: EvaluateOpts)
```

Every options type includes these shared options.

### Shared options

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `model` | `ModelId` | Required | Provider-prefixed model ID or router slug. A router slug resolves to its target model. |
| `req` | `Partial<FrogBotRequest>` | — | Request whose user is checked against [access](#control-access) and the [user model and budget policy](#user-model-and-budget-policy). Hooks receive it as `req`. |
| `overrideAccess` | `boolean` | `false` when `req` is passed, otherwise `true` | Set `true` to skip access and policy checks for a call with `req`. Checks need a request, so a call without `req` always skips them. |

### Text generation options

`generateText` and `streamText` accept these options. Text generation uses the AI SDK v7 option names.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `prompt` | `string` | Required unless `messages` is set | A single user prompt. Can't be combined with `messages`. |
| `messages` | `ModelMessage[]` | Required unless `prompt` is set | The conversation to continue. Can't be combined with `prompt`. |
| `instructions` | `string` | — | System instructions sent before the prompt or messages. |
| `tools` | `Tool[]` | — | FrogBot [tools](/agents/overview#tool-options) the model may call. Each runs with a [`ToolCtx`](/agents/overview#tool-context) whose `agent.slug` is `'direct'` and whose `runId` is new for the call. |
| `toolChoice` | `ToolChoice<ToolSet>` | `'auto'` | Whether and which tool the model must call: `'auto'`, `'none'`, `'required'`, or `{ type: 'tool', toolName }`. |
| `output` | `AIOutput` | Text | An `Output` specification for structured results. Read the parsed value from `result.output`. See [Request output](#request-output). |
| `stopWhen` | `StopCondition<ToolSet> \| StopCondition<ToolSet>[]` | `isStepCount(1)` | When to stop the tool loop. With the default, tool results do not trigger another model call. |
| `maxOutputTokens` | `number` | Provider default | Maximum tokens to generate. |
| `temperature` | `number` | Provider default | Sampling temperature. |
| `topP` | `number` | Provider default | Nucleus sampling threshold. |
| `topK` | `number` | Provider default | Samples only from the top K tokens. |
| `presencePenalty` | `number` | Provider default | Penalty for repeating content already present in the prompt. |
| `frequencyPenalty` | `number` | Provider default | Penalty for repeating the same words or phrases. |
| `seed` | `number` | — | Seed for deterministic sampling, when the provider supports it. |
| `maxRetries` | `number` | `2` | Retries for failed model calls. Set `0` to disable retries. |
| `timeout` | `number` | — | Total time limit for the call, in milliseconds. |
| `stopSequences` | `string[]` | — | Sequences that stop generation when produced. |
| `providerOptions` | `Record<string, unknown>` | — | Provider-specific options keyed by provider name, passed to the provider unchanged. |
| `abortSignal` | `AbortSignal` | — | Cancels the call. |
| `headers` | `Record<string, string>` | — | Extra HTTP headers sent to the provider. |
| `onStepEnd` | `(event: unknown) => void \| Promise<void>` | — | Called after each step with that step's result. |

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `onEnd` | `(event: unknown) => void \| Promise<void>` | — | Called once when the stream finishes, after FrogBot records usage and runs `afterOperation`. |
| `onFinish` | `(event: unknown) => void \| Promise<void>` | — | Alias of `onEnd`. Ignored when `onEnd` is set. |
| `onError` | `(event: { error: unknown }) => void \| Promise<void>` | — | Called when the stream fails, after `afterOperation` runs with the error. |
| `onAbort` | `(event: unknown) => void \| Promise<void>` | — | Called when `abortSignal` aborts the stream, after `afterOperation` runs with the abort reason. |

## Evaluate state

Use `frogbot.evaluate()` to ask named boolean, choice, and score questions about shared state. Configure `ai.providers['typesafe-ai']` with a server-side key first; [TypeSafe AI setup](/gateway/providers#typesafe-ai-evaluation) covers the options. State, instructions, and criteria can contain structured JSON.

```ts
const result = await req.frogbot.evaluate({
  model: 'typesafe-ai/jev',
  state: { ticket: 'Customer was charged twice and requested a refund' },
  questions: {
    refunded: {
      type: 'boolean',
      instructions: 'Was a refund issued?'
    },
    team: {
      type: 'choice',
      instructions: 'Which team should handle the ticket?',
      criteria: { billing: 'Billing team', support: 'Support team' }
    },
    severity: {
      type: 'score',
      instructions: 'How urgent is this ticket?',
      criteria: ['Low', 'Medium', 'High']
    }
  },
  req
})

const refundProbability = result.answers.refunded.probability
const assignedTeam = result.answers.team.choice
const severityScore = result.answers.severity.score
```

The result retains inferred answer types for each question, along with SDK usage, warnings, rounding, response, and provider metadata. A boolean probability is an estimate, not an automatic decision. TypeSafe rounds probabilities and scores to two decimal places; `result.rounding` records that precision. When provided, confidence for choice and score questions is separate from their answer probabilities at `result.providerMetadata?.typesafe?.confidence`. Evaluation uses the AI SDK's experimental API, which may change in patch releases.

`typesafe-ai/jev` is FrogBot's shorthand for upstream `jev-latest`; `typesafe-ai/jev-latest` also works. Local router slugs can target either model, while HTTP requests use provider-prefixed IDs.

### Evaluate options

`evaluate` accepts the [shared options](#shared-options) plus:

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `state` | `string \| JSONObject \| JSONValue[]` | Required | The shared state every question is asked about. An array is one state, not a batch. |
| `questions` | `Record<string, EvaluationQuestion>` | Required | Named questions. Each key becomes a key of `result.answers`. See [Question options](#question-options). |
| `maxRetries` | `number` | `2` | Retries for transient provider failures. |
| `abortSignal` | `AbortSignal` | — | Cancels the call. |
| `headers` | `Record<string, string>` | — | Extra HTTP headers sent to the provider. |
| `providerOptions` | `Record<string, unknown>` | — | Provider-specific options keyed by provider name. |
| `telemetry` | `TelemetryOptions` | — | AI SDK telemetry settings for this call. |
| `runtimeContext` | `Record<string, unknown>` | — | Values passed through to telemetry callbacks. Treat it as read-only. |
| `onStart` | `(event) => void \| Promise<void>` | — | Called when the evaluation starts. |
| `onEnd` | `(event) => void \| Promise<void>` | — | Called when the evaluation completes. |

### Question options

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `type` | `'boolean' \| 'choice' \| 'score'` | Required | `boolean` answers with a `probability`, `choice` with one of the `criteria` keys, and `score` with an index into the `criteria` levels. |
| `instructions` | `string \| JSONObject \| JSONValue[]` | Required | The question to answer about the state. |
| `criteria` | `Record<string, string \| JSONObject \| JSONValue[] \| null>` for `choice`; `(string \| JSONObject \| JSONValue[] \| null)[]` for `score`; `{ true?, false? }` for `boolean` | Required for `choice` and `score` | `choice`: a non-empty map of option names to descriptions. `score`: at least two ordered levels, indexed from `0`. `boolean`: optional descriptions of what `true` and `false` mean. `null` means no description. |

## Request output

AI SDK v7 handles structured data through `generateText` and an `Output` specification. Read the validated value from `result.output`; there is no `generateObject` method.

```ts
import { Output } from 'frogbot'
import { z } from 'zod'

const result = await req.frogbot.generateText({
  model: 'fast',
  prompt: 'Extract the ticket number and priority',
  output: Output.object({
    schema: z.object({
      ticket: z.string(),
      priority: z.enum(['low', 'medium', 'high'])
    })
  }),
  req
})

const ticket = result.output
```

FrogBot also re-exports `Output.text`, `Output.array`, `Output.choice`, and `Output.json` through the same `Output` object.

## Control access

Configure access by operation category. Every category defaults to `Boolean(req.user)`.

```ts
ai: {
  providers: {
    openai: true
  },
  access: {
    generate: ({ req }) => Boolean(req.user),
    embed: ({ req }) => Boolean(req.user),
    transcribe: ({ req }) => Boolean(req.user),
    rerank: ({ req }) => Boolean(req.user),
    evaluate: ({ req }) => Boolean(req.user)
  }
}
```

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `generate` | `({ req }) => boolean \| Promise<boolean>` | `Boolean(req.user)` | Checked for `generateText`, `streamText`, `generateImage`, `generateSpeech`, and `generateVideo`. |
| `embed` | `({ req }) => boolean \| Promise<boolean>` | `Boolean(req.user)` | Checked for `embed` and `embedMany`. |
| `transcribe` | `({ req }) => boolean \| Promise<boolean>` | `Boolean(req.user)` | Checked for `transcribe`. |
| `rerank` | `({ req }) => boolean \| Promise<boolean>` | `Boolean(req.user)` | Checked for `rerank`. |
| `evaluate` | `({ req }) => boolean \| Promise<boolean>` | `Boolean(req.user)` | Checked for `evaluate`. |

A rule that returns `false` rejects the call with `AIAccessError` (status `403`).

An in-process call with `req` enforces access unless `overrideAccess: true` is set. A server-side call without `req` bypasses access by default, following the Local API convention.

## Observe calls

Register arrays of hooks for the five-phase lifecycle. FrogBot creates one lifecycle for each direct operation, local agent run, agent HTTP call, and mounted `/api/v1/*` request.

```ts
ai: {
  providers: {
    openai: true
  },
  hooks: {
    beforeOperation: [({ context, user }) => {
      context.authenticated = Boolean(user)
    }],
    beforeUpstream: [({ headers }) => {
      headers.set('x-application', 'support')
    }],
    afterOperation: [({ durationMs, error }) => {
      console.info({ durationMs, failed: Boolean(error) })
    }]
  }
}
```

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `beforeOperation` | `AIBeforeOperationHook[]` | `[]` | Runs once after alias resolution and access checks, before the AI SDK call. |
| `beforeUpstream` | `AIBeforeUpstreamHook[]` | `[]` | Runs before each model's `doGenerate`, `doStream`, or equivalent call. |
| `afterUpstream` | `AIAfterUpstreamHook[]` | `[]` | Runs after each successful model call. |
| `afterError` | `AIAfterErrorHook[]` | `[]` | Runs after a failed model call, with `failedPhase` and `error`. |
| `afterOperation` | `AIAfterOperationHook[]` | `[]` | Runs once when the full operation succeeds, fails, ends, or is aborted. |

All phases share `requestId`, `operation`, `startedAt`, mutable `context`, and mutable `otel`. The per-phase arguments match the [gateway hook phases](/gateway/hooks#phases). FrogBot adds these fields to every hook argument:

| Argument | Type | Description |
| --- | --- | --- |
| `req` | `FrogBotRequest \| undefined` | The request passed to the operation or received by the HTTP route. |
| `user` | `FrogBotRequest['user'] \| undefined` | `req.user`, when a request is present. |
| `agent` | `{ slug: string; runId: string; chatId?: number \| string } \| undefined` | Set for agent runs. `chatId` is set when the run belongs to a persisted chat. |

FrogBot executes `beforeOperation` and `afterOperation` and does not pass them into the embedded gateway. It passes only `beforeUpstream`, `afterUpstream`, and `afterError` to `createGateway`.

Gateway HTTP handlers continue to execute upstream hooks inline. In-process model resolvers execute them around the returned model's `doGenerate`, `doStream`, or equivalent calls.

Mutate `messages`, `params`, `headers`, and `providerOptions` in place during `beforeUpstream`; `system` and `tools` are read-only. `afterUpstream`, `afterError`, and `afterOperation` isolate hook failures so later hooks still run.

Access failures happen before the lifecycle and run no hooks. A thrown `beforeOperation` stops the call before an operation lifecycle is returned, so `afterOperation` does not run for that failure.

## Trace calls

Telemetry is enabled by default and registers `@ai-sdk/otel` when that optional peer dependency is installed. Set a deployment ID or add span attributes without replacing FrogBot's defaults.

```ts
ai: {
  providers: {
    openai: true
  },
  deploymentId: 'support-production',
  telemetry: {
    enabled: true,
    enrichSpan: ({ operationId }) => ({
      'app.operation_id': operationId
    })
  }
}
```

`deploymentId` defaults to `FROGBOT_DEPLOYMENT_ID`, then `local`. When `@ai-sdk/otel` is absent, registration quietly does nothing.

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `enabled` | `boolean` | `true` | Set `false` to skip registering `@ai-sdk/otel`. |
| `enrichSpan` | `(args: AIEnrichSpanArgs) => Record<string, unknown> \| undefined` | — | Returns extra attributes for every AI SDK span. They are merged over FrogBot's `frogbot.deployment` attribute and stringified before they are attached. |

`enrichSpan` receives:

| Argument | Type | Description |
| --- | --- | --- |
| `spanType` | `'operation' \| 'step' \| 'languageModel' \| 'tool' \| 'embedding' \| 'reranking' \| 'experimental_evaluation'` | The kind of span being created. |
| `operationId` | `string` | AI SDK operation name, such as `ai.generateText`. |
| `callId` | `string` | ID of the AI SDK call the span belongs to. |
| `runtimeContext` | `Record<string, unknown> \| undefined` | The call's runtime context. Agent runs set `{ agent: { slug, runId, chatId? } }`. |

## Call over HTTP

The standalone server mounts the embedded gateway at `/api/v1`. Canonical `/api/v1/*` requests are authenticated through `frogbot.auth`, and requests without a resolved user receive `401` before reaching the gateway.

Use `@frogbotai/sdk` in browser and application clients. AI methods use the SDK's configured base URL, headers, and `fetch`, so cookie and bearer authentication wrappers apply without separate AI credentials.

```ts
import { createFrogBotSDK } from '@frogbotai/sdk'

const sdk = createFrogBotSDK({
  baseURL: '/api',
  fetch: (input, init) => fetch(input, { ...init, credentials: 'include' })
})

const result = await sdk.ai.transcribe({
  model: 'groq/whisper-large-v3',
  file: recording
})

const response = await sdk.ai.chat({
  model: 'openai/gpt-4o-mini',
  messages: [{ role: 'user', content: 'Hello' }]
})
```

`transcribe` returns parsed transcription JSON. `chat` returns the raw `Response` so the caller can consume either JSON or an SSE stream.

Each accepted request gets one FrogBot lifecycle around the gateway handler. FrogBot runs the operation hooks, while the gateway handler runs the configured upstream hooks inline.

| Method | Path |
| --- | --- |
| `GET` | `/api/v1/models` |
| `GET` | `/api/v1/health` |
| `POST` | `/api/v1/chat/completions` |
| `POST` | `/api/v1/messages` |
| `POST` | `/api/v1/responses` |
| `POST` | `/api/v1/embeddings` |
| `POST` | `/api/v1/images/generations` |
| `POST` | `/api/v1/audio/speech` |
| `POST` | `/api/v1/audio/transcriptions` |
| `POST` | `/api/v1/videos/generations` |
| `POST` | `/api/v1/rerank` |
| `POST` | `/api/v1/evaluate` |

Pass credentials accepted by your configured auth collection. HTTP bodies use provider-prefixed model IDs because router aliases are resolved by FrogBot's local operation layer, not by the gateway handler. After authentication, mounted operation routes enforce the matching `ai.access` category and user model policy. A denied request receives `403`; discovery routes such as `/models` do not run an operation access callback. Keep the TypeSafe upstream key on the server; clients authenticate to FrogBot instead. See the [evaluation JSON contract](/gateway/overview#evaluate-over-http) for a request and response shape.

```bash
curl http://localhost:3000/api/v1/chat/completions \
  --request POST \
  --header "Authorization: Bearer $FROGBOT_TOKEN" \
  --header "Content-Type: application/json" \
  --data '{
    "model": "openai/gpt-4o-mini",
    "messages": [{ "role": "user", "content": "Hello" }]
  }'
```
