## User model and budget policy

When AI is configured, FrogBot adds policy fields to the auth collection. `modelAccess` defaults to `all`, which includes models and routers configured later. `selected` requires at least one exact target in `models`. Granting a router permits that router slug, not direct calls to the model behind it.

`monthlyBudget` is an optional USD limit. Completed billable usage increments `spendThisPeriodUSD`, including configured custom-provider prices. Requests stop when spend reaches the limit, and FrogBot resets spend at midnight UTC on the first day of each month. Counter updates are serialized within one process; deployments with multiple writers should use database-level serialization if exact concurrent accounting is required.

### Customizing the fields

Policy fields have no default access restrictions. Define a same-name field on your auth collection to override labels, admin settings, defaults, or access while FrogBot supplies omitted policy behavior.

Leave the fields out for fully open field access.

Block updates with your own check:

```ts
{ name: 'monthlyBudget', type: 'number', access: {
  update: ({ req }) => req.user?.isAdmin === true,
} }
```

Compose access from the roles plugin:

```ts
{ name: 'monthlyBudget', type: 'number', access: {
  update: allow('admin'),
} }
```

`spendThisPeriodUSD` is update-locked and read-only by default because FrogBot maintains it. A same-name override can replace that access or admin setting when needed.

The `ai` block creates an embedded `@frogbotai/gateway` instance when FrogBot starts. Local operations use AI SDK v7 against that in-process gateway, so no separate proxy service is required.

## Configure providers

Add at least one provider. Set a provider to `true` to use its SDK's standard environment credentials.

```ts
import { buildConfig } from 'frogbot'

export default buildConfig({
  // secret, db, and collections omitted
  ai: {
    providers: {
      openai: true,
      anthropic: true,
      bedrock: true
    }
  }
})
```

Built-in keys are `openai`, `anthropic`, `google`, `bedrock`, `groq`, `mistral`, `cohere`, `togetherai`, `fireworks`, `deepinfra`, `xai`, `perplexity`, `cerebras`, `voyage`, `replicate`, and `typesafe-ai`. See [TypeSafe AI setup](/gateway/providers#typesafe-ai-evaluation) for its server-side credential and evaluation-only models.

Model IDs use `<provider>/<model>`, where `<provider>` is the exact key you used under `ai.providers`, such as `bedrock/...` or `togetherai/...`. Replicate's `apiKey` maps to its `apiToken` option. Bedrock uses bearer tokens first, then explicit SigV4 keys, then the AWS default credential chain.

Use `{ apiKey: process.env.CUSTOM_KEY }` only for an alternate credential. Explicit keys must be non-empty. Bedrock accepts `true`, `{ region }`, paired `{ accessKeyId, secretAccessKey, sessionToken? }` overrides, or a custom `credentialProvider`. In Node.js, the default chain supports AWS profiles and IAM Identity Center, web identity, ECS task roles, and EC2 instance profiles. Install the optional `@aws-sdk/credential-providers` peer dependency to use this fallback. Edge runtimes must provide an edge-compatible `credentialProvider` instead.

Add an OpenAI-compatible endpoint with any non-built-in key. Its `models` list is required for validation, and calls use the custom key as the provider prefix.

```ts
ai: {
  providers: {
    internal: {
      type: 'openai-compatible',
      baseUrl: 'https://models.internal.example/v1',
      apiKey: process.env.INTERNAL_AI_KEY,
      headers: { 'x-deployment': 'production' },
      models: [
        {
          id: 'legal-summary-v2',
          mode: 'chat',
          limit: { context: 128_000, output: 8_000 },
          modalities: { input: ['text'], output: ['text'] },
          tool_call: true,
          structured_output: true
        }
      ]
    }
  }
}
```

Invoke that model as `internal/legal-summary-v2`. Built-in provider entries accept an optional `models` allowlist to restrict their catalog IDs; this is different from a custom provider's required model definitions.

## Add aliases

Routers are pure aliases from a stable slug to one model ID.

```ts
ai: {
  providers: {
    openai: true
  },
  routers: {
    fast: { model: 'openai/gpt-4o-mini' },
    careful: { model: 'openai/o3' }
  },
  defaultRouter: 'fast'
}
```

An alias has no fallback chain or access rule. `hidden` exists on `RouterConfig` but is reserved for future admin integration.

`defaultRouter` must name a configured alias, but v0 operations still require `model`. Local operations and agents resolve aliases; the mounted gateway HTTP routes expect provider-prefixed model IDs.

## Choose a utility model

FrogBot uses a small chat model for internal work such as naming new chats. By default, it chooses a recent low-cost model from the same provider as the active agent model. If no catalog candidate is available, it uses the active model.

Set `smallModel` to pin these calls to a configured model or alias:

```ts
ai: {
  providers: {
    openai: true
  },
  routers: {
    utility: { model: 'openai/gpt-5-nano' }
  },
  smallModel: 'utility' // or 'openai/gpt-5-nano'
}
```

The model or alias must resolve to a configured provider. Utility calls use the normal operation lifecycle and appear in usage reporting.

## Call operations

Call methods on a `FrogBot` instance or `req.frogbot`. Text generation accepts either `prompt` or `messages`, never both.

```ts
const { text, usage, finishReason } = await req.frogbot.generateText({
  model: 'fast',
  prompt: 'Summarize the latest support request',
  req
})
```

These are the public v0 operation signatures.

```ts
generateText(opts: GenerateTextOpts)
streamText(opts: StreamTextOpts)
embed(opts: EmbedOpts)
embedMany(opts: EmbedManyOpts)
generateImage(opts: GenerateImageOpts)
generateSpeech(opts: GenerateSpeechOpts)
transcribe(opts: TranscribeOpts)
generateVideo(opts: GenerateVideoOpts)
rerank(opts: RerankOpts)
evaluate(opts: EvaluateOpts)
```

Every options type includes this base.

```ts
type BaseAIOpts = {
  model: ModelId
  req?: FrogBotRequest
  overrideAccess?: boolean
}
```

Generation uses the AI SDK v7 option names exposed below.

```ts
type GenerateTextOpts = BaseAIOpts & (
  | { prompt: string; messages?: never }
  | { prompt?: never; messages: ModelMessage[] }
) & {
  instructions?: string
  tools?: Tool[]
  toolChoice?: ToolChoice<ToolSet>
  output?: AIOutput
  stopWhen?: StopCondition<ToolSet> | StopCondition<ToolSet>[]
  maxOutputTokens?: number
  temperature?: number
  topP?: number
  topK?: number
  presencePenalty?: number
  frequencyPenalty?: number
  seed?: number
  maxRetries?: number
  timeout?: number
  stopSequences?: string[]
  providerOptions?: Record<string, unknown>
  abortSignal?: AbortSignal
  headers?: Record<string, string>
  onStepEnd?: (event: unknown) => void | Promise<void>
}

type StreamTextOpts = GenerateTextOpts & {
  onFinish?: (event: unknown) => void | Promise<void>
  onEnd?: (event: unknown) => void | Promise<void>
}
```

The remaining operations expose only the fields implemented by their corresponding AI SDK functions.

```ts
type EmbedOpts = BaseAIOpts & {
  value: string
  abortSignal?: AbortSignal
  headers?: Record<string, string>
}

type EmbedManyOpts = BaseAIOpts & {
  values: string[]
  maxParallelCalls?: number
  abortSignal?: AbortSignal
  headers?: Record<string, string>
}

type GenerateImageOpts = BaseAIOpts & {
  prompt: string
  n?: number
  size?: string
  providerOptions?: Record<string, unknown>
  abortSignal?: AbortSignal
  headers?: Record<string, string>
}

type GenerateSpeechOpts = BaseAIOpts & {
  text: string
  voice?: string
  speed?: number
  providerOptions?: Record<string, unknown>
  abortSignal?: AbortSignal
}

type TranscribeOpts = BaseAIOpts & {
  audio: Blob | ArrayBuffer | ReadableStream
  language?: string
  providerOptions?: Record<string, unknown>
  abortSignal?: AbortSignal
}

type GenerateVideoOpts = BaseAIOpts & {
  prompt: string
  providerOptions?: Record<string, unknown>
  abortSignal?: AbortSignal
}

type RerankOpts = BaseAIOpts & {
  query: string
  documents: string[]
  topN?: number
  abortSignal?: AbortSignal
}
```

Each method returns the result from its AI SDK v7 counterpart. `streamText` performs asynchronous access and hook setup, so await it before consuming `textStream` or another result stream.

## Evaluate state

Use `frogbot.evaluate()` to ask named boolean, choice, and score questions about shared state. Configure `ai.providers['typesafe-ai']` with a server-side key first; [TypeSafe AI setup](/gateway/providers#typesafe-ai-evaluation) covers the options. State, instructions, and criteria can contain structured JSON.

```ts
const result = await req.frogbot.evaluate({
  model: 'typesafe-ai/jev',
  state: { ticket: 'Customer was charged twice and requested a refund' },
  questions: {
    refunded: {
      type: 'boolean',
      instructions: 'Was a refund issued?'
    },
    team: {
      type: 'choice',
      instructions: 'Which team should handle the ticket?',
      criteria: { billing: 'Billing team', support: 'Support team' }
    },
    severity: {
      type: 'score',
      instructions: 'How urgent is this ticket?',
      criteria: ['Low', 'Medium', 'High']
    }
  },
  req
})

const refundProbability = result.answers.refunded.probability
const assignedTeam = result.answers.team.choice
const severityScore = result.answers.severity.score
```

The result retains inferred answer types for each question, along with SDK usage, warnings, rounding, response, and provider metadata. A boolean probability is an estimate, not an automatic decision. TypeSafe rounds probabilities and scores to two decimal places; `result.rounding` records that precision. When provided, confidence for choice and score questions is separate from their answer probabilities at `result.providerMetadata?.typesafe?.confidence`. Evaluation uses the AI SDK's experimental API, which may change in patch releases.

`typesafe-ai/jev` is FrogBot's shorthand for upstream `jev-latest`; `typesafe-ai/jev-latest` also works. Local router slugs can target either model, while HTTP requests use provider-prefixed IDs.

## Request output

AI SDK v7 handles structured data through `generateText` and an `Output` specification. Read the validated value from `result.output`; there is no `generateObject` method.

```ts
import { Output } from 'frogbot'
import { z } from 'zod'

const result = await req.frogbot.generateText({
  model: 'fast',
  prompt: 'Extract the ticket number and priority',
  output: Output.object({
    schema: z.object({
      ticket: z.string(),
      priority: z.enum(['low', 'medium', 'high'])
    })
  }),
  req
})

const ticket = result.output
```

FrogBot also re-exports `Output.text`, `Output.array`, `Output.choice`, and `Output.json` through the same `Output` object.

## Control access

Configure access by operation category. Every category defaults to `Boolean(req.user)`.

```ts
ai: {
  providers: {
    openai: true
  },
  access: {
    generate: ({ req }) => Boolean(req.user),
    embed: ({ req }) => Boolean(req.user),
    transcribe: ({ req }) => Boolean(req.user),
    rerank: ({ req }) => Boolean(req.user),
    evaluate: ({ req }) => Boolean(req.user)
  }
}
```

| Category | Operations |
| --- | --- |
| `generate` | `generateText`, `streamText`, `generateImage`, `generateSpeech`, `generateVideo` |
| `embed` | `embed`, `embedMany` |
| `transcribe` | `transcribe` |
| `rerank` | `rerank` |
| `evaluate` | `evaluate` |

An in-process call with `req` enforces access unless `overrideAccess: true` is set. A server-side call without `req` bypasses access by default, following the Local API convention.

## Observe calls

Register arrays of hooks for the five-phase lifecycle. FrogBot creates one lifecycle for each direct operation, local agent run, agent HTTP call, and mounted `/api/v1/*` request.

```ts
ai: {
  providers: {
    openai: true
  },
  hooks: {
    beforeOperation: [({ context, user }) => {
      context.authenticated = Boolean(user)
    }],
    beforeUpstream: [({ headers }) => {
      headers.set('x-application', 'support')
    }],
    afterOperation: [({ durationMs, error }) => {
      console.info({ durationMs, failed: Boolean(error) })
    }]
  }
}
```

| Phase | Runs |
| --- | --- |
| `beforeOperation` | Once after alias resolution and access checks, before the AI SDK call |
| `beforeUpstream` | Before each model's `doGenerate`, `doStream`, or equivalent call |
| `afterUpstream` | After each successful model call |
| `afterError` | After a failed model call, with `failedPhase` and `error` |
| `afterOperation` | Once when the full operation succeeds, fails, ends, or is aborted |

All phases share `requestId`, `operation`, `startedAt`, mutable `context`, and mutable `otel`. FrogBot intersects every hook argument with this context.

```ts
type AIHookContext = {
  req?: FrogBotRequest
  user?: FrogBotRequest['user']
  agent?: {
    slug: string
    runId: string
  }
}
```

FrogBot executes `beforeOperation` and `afterOperation` and does not pass them into the embedded gateway. It passes only `beforeUpstream`, `afterUpstream`, and `afterError` to `createGateway`.

Gateway HTTP handlers continue to execute upstream hooks inline. In-process model resolvers execute them around the returned model's `doGenerate`, `doStream`, or equivalent calls.

Mutate `messages`, `params`, `headers`, and `providerOptions` in place during `beforeUpstream`; `system` and `tools` are read-only. `afterUpstream`, `afterError`, and `afterOperation` isolate hook failures so later hooks still run.

Access failures happen before the lifecycle and run no hooks. A thrown `beforeOperation` stops the call before an operation lifecycle is returned, so `afterOperation` does not run for that failure.

## Trace calls

Telemetry is enabled by default and registers `@ai-sdk/otel` when that optional peer dependency is installed. Set a deployment ID or add span attributes without replacing FrogBot's defaults.

```ts
ai: {
  providers: {
    openai: true
  },
  deploymentId: 'support-production',
  telemetry: {
    enabled: true,
    enrichSpan: ({ operationId }) => ({
      'app.operation_id': operationId
    })
  }
}
```

`deploymentId` defaults to `FROGBOT_DEPLOYMENT_ID`, then `local`. When `@ai-sdk/otel` is absent, registration quietly does nothing.

## Call over HTTP

The standalone server mounts the embedded gateway at `/api/v1`. Canonical `/api/v1/*` requests are authenticated through `frogbot.auth`, and requests without a resolved user receive `401` before reaching the gateway.

Use `@frogbotai/sdk` in browser and application clients. AI methods use the SDK's configured base URL, headers, and `fetch`, so cookie and bearer authentication wrappers apply without separate AI credentials.

```ts
import { createFrogBotSDK } from '@frogbotai/sdk'

const sdk = createFrogBotSDK({
  baseURL: '/api',
  fetch: (input, init) => fetch(input, { ...init, credentials: 'include' })
})

const result = await sdk.ai.transcribe({
  model: 'groq/whisper-large-v3',
  file: recording
})

const response = await sdk.ai.chat({
  model: 'openai/gpt-4o-mini',
  messages: [{ role: 'user', content: 'Hello' }]
})
```

`transcribe` returns parsed transcription JSON. `chat` returns the raw `Response` so the caller can consume either JSON or an SSE stream.

Each accepted request gets one FrogBot lifecycle around the gateway handler. FrogBot runs the operation hooks, while the gateway handler runs the configured upstream hooks inline.

| Method | Path |
| --- | --- |
| `GET` | `/api/v1/models` |
| `GET` | `/api/v1/health` |
| `POST` | `/api/v1/chat/completions` |
| `POST` | `/api/v1/messages` |
| `POST` | `/api/v1/responses` |
| `POST` | `/api/v1/embeddings` |
| `POST` | `/api/v1/images/generations` |
| `POST` | `/api/v1/audio/speech` |
| `POST` | `/api/v1/audio/transcriptions` |
| `POST` | `/api/v1/videos/generations` |
| `POST` | `/api/v1/rerank` |
| `POST` | `/api/v1/evaluate` |

Pass credentials accepted by your configured auth collection. HTTP bodies use provider-prefixed model IDs because router aliases are resolved by FrogBot's local operation layer, not by the gateway handler. After authentication, mounted operation routes enforce the matching `ai.access` category and user model policy. A denied request receives `403`; discovery routes such as `/models` do not run an operation access callback. Keep the TypeSafe upstream key on the server; clients authenticate to FrogBot instead. See the [evaluation JSON contract](/gateway/overview#evaluate-over-http) for a request and response shape.

```bash
curl http://localhost:3000/api/v1/chat/completions \
  --request POST \
  --header "Authorization: Bearer $FROGBOT_TOKEN" \
  --header "Content-Type: application/json" \
  --data '{
    "model": "openai/gpt-4o-mini",
    "messages": [{ "role": "user", "content": "Hello" }]
  }'
```
